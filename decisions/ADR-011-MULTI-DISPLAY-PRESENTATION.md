# ADR-011 — Nearpane 多显示器呈现与独立配置

**状态：ACCEPTED — 产品方向；2026-11-09 补充精细尺寸设置；工程实施与真实验收未完成**  
**日期：2026-11-09**  
**覆盖范围：** 多显示器角色、驻留/按需出现策略、每屏与内部元素的精细尺寸设置、Native Spaces / Virtual Workspaces 协同。  
**权威关系：** 补充 PRODUCT_DEFINITION、NEARPANE-VISUAL-AUTHORITY、ADR-010；[ADR-012](ADR-012-DESKTOP-WORK-AREA-AND-FULLSCREEN.md) 定义原生全屏与桌面管理，[ADR-013](ADR-013-STABLE-WORKRECT-AND-EIGHT-WINDOW-TILING.md) 为最新的 **主/副屏固定式预留、浮窗不预留、扩容/退出/布局恢复** 权威。保留 Saytile/Riftlet 领域语义。  
**边界：** 本文件仅为设计和工程契约，不授权生产运行时代码、真实窗口写操作或系统设置修改。

## 1. 核心决定：一个主驻留屏 + 零到多个空间调度副屏

- Nearpane 的**主驻留屏（Primary Residence Display）**由用户选择，且任一时刻只有一块；不必等于 macOS 的系统主显示器。
- **Saytile 语音板、Riftlet 截图板和其他全局第一方输入能力只驻留在该主屏的一份主表面中**，全局只有一套领域状态机/截图队列，不因副屏数量增加而复制实例。
- 主屏空间调度按实际需要呈现：存在多个可切换空间或当前多个受管理普通窗口时应显示；单空间单窗且无其他调度目标时可以不显示，语音、截图仍然可用。UI 显隐不改变持久 WorkRect。
- 每块其他显示器至多拥有**一个独立 Space-only 空间调度面板**，不显示 Saytile、Riftlet、AI 或其它主屏模块。**副屏默认 Docked（驻留式，持续预留可配置的工作区域），可在设置里改为 Floating（浮窗式，不预留空间）**。
- 副屏面板不是第二个 Nearpane Host，也不是多开另一份应用；同一 Host 提供多 display-specific surfaces，读同一个经验证的桌面状态源，各副屏有自己的窗口、尺寸、位置、触发与可见性策略。
- 单屏时只存在主驻留表面，不需要副屏空壳。

## 2. 出现条件：将“有多个可切换目标”和“何时实际弹出”分开

副屏有两组互不混淆的设置：**空间占用形态 Docked / Floating（默认 Docked）**，以及**出现时机 On-demand / Contextual Auto / Pinned（默认 On-demand）**。On-demand 时临时隐藏不会释放 Docked 的保留区；自动和持续显示仅用户明确选择后启用：

1. **On-demand / 按需（默认）：** 平时隐藏。用户在该屏执行明确的唤出交互（可配置屏幕边缘、快捷键、显式入口等）才出现；完成切换或外部点击后可收起。仅在具备可确认且有意义的切换目标时出现；不占用无必要的桌面空间。
2. **Contextual Auto / 多目标自动：** 在该显示器存在至少两个**有意义的可切换窗口目标**，或者至少两个当前模式下可确认的工作空间时，允许自动出现空间面板；窗口和空间减少后延迟收起。过滤系统临时窗口、Nearpane 自身面板、不可操作元素和重复影子记录，不把原始 CGWindow 数量直接当成目标数量。具体阈值、去抖/收起延时由后续交互与实机测试确定，避免频繁闪烁。
3. **Pinned / 固定：** 用户可以选择让这块副屏的空间面板持续显示。副屏依然**只有空间调度**，不会因此复制语音或截图模块。

“多窗口才显示”作为**可选择的自动策略**，而非无条件默认。即使只有一个可见窗口，若还有多个真实可切换 Space/Workspace，按需策略仍允许显示；没有可切换目标时不伪造空间或窗口。

处于原生全屏、演示、游戏或系统安全界面时**默认不显示空间调度**，包括主屏与副屏；用户可在设置中对已经技术验证的情境选择例外，但不得默认自动弹出完整 Nearpane。即使明确启用自动出现，亦需尊重焦点、Mission Control、去抖和安全状态。默认不劫持系统 Mission Control 快捷键或热角，只有用户显式启用兼容入口时才绑定，冲突时保留系统行为。

### 2.1 副屏默认预留；浮窗始终不预留（最新正式规则）

- **Docked / 驻留式（副屏默认）**：为该显示器的空间调度预留独立配置的边缘工作区。面板可按需出现、暂时消失、无内容或手动隐藏，但无论其 UI 是否可见，受管理普通应用窗口**都不能占用预留区**。其他窗口不能只在空间调度出现时被挤开。
- **Floating / 浮窗式（副屏可选）**：在用户指定的位置显示可移动的 Space-only 浮窗，窗口可以位于它的下方；**无论浮窗显示或隐藏，都不为浮窗扣除 WorkRect**。只改变出现时机不能改变这一占用规则。
- **Pinned ≠ Docked**：Pinned 只表示常显示，Docked 表示持续预留；Docked + On-demand 和 Floating + Pinned 都是合法配置。
- **仅显隐变化：** 不修改本屏任何普通应用窗口 frame。**用户明确在设置里切换 Docked/Floating**、改变预留区尺寸、或真实桌面/显示器几何改变时，才按当前屏的独立设置和受控写能力改变 WorkRect；不能误动其他显示器的窗口。
- 主驻留屏保持唯一 Saytile/Riftlet，默认 Docked；副屏各自独立保存形态、宽高、位置和出现策略。真正原生全屏时该显示器的 WorkRect 例外；退出全屏恢复原先的占位模式。**明确退出 Nearpane 后停止接管，并恢复接管前的系统窗口布局。**

## 3. 每块显示器独立可配置

| 范畴 | 主驻留屏 | 副屏 Space-only |
|---|---|---|
| 面板角色 | 唯一全功能主表面 | 独立空间调度表面 |
| Saytile / Riftlet | 唯一常驻实例 | 不显示，不创建副本 |
| 空间调度 | 可按屏独立启停 | 唯一功能，可按屏启停 |
| 宽度与高度 | 独立，默认宽约本屏 1/8 | 独立，按空间行及屏幕形态设置 |
| 左/右侧、纵向位置 | 独立设置 | 独立设置 |
| 空间行高度、密度、缩放 | 独立 | 独立 |
| 占用形态 | Docked（主屏默认） | **Docked（副屏默认，始终预留）/ Floating（浮窗，不预留）** |
| 出现时机 | 按实际模块需求显示 | On-demand / Contextual Auto / Pinned（与占用形态分离） |
| 可选模块 | 遵循主表面模块契约 | 不装载可选模块 |
| 透明度与动效 | 独立 | 独立 |
| 显示器旋转、缩放、可用区域 | 依实际几何重新计算 | 单独重新计算，不继承主屏尺寸 |

宽高等参数针对**各自显示器的可用区域**存储，不直接复用另一屏的点数或像素数。用户可以精细调整任意主/副屏面板及其内容区域尺寸，而不是被迫使用固定的 1/8 或 3/8+5/8 比例。所用滚动/行高策略不得拉伸单个窗口。空间缩略图按该空间统一、保比例的坐标变换缩放；受管理普通主窗口依 ADR-012 默认实际平铺、互不重叠，预览如实呈现平铺后的宽高/位置；例外系统窗口不得伪装成已平铺。

**原 3/8（Saytile+Riftlet）/5/8（Spaces）只适用于主屏完整形态的出厂默认，不是固定比例**。只有没有多空间/多普通窗口调度需求时，主屏才可省略空间区并缩短界面；此时主屏 Docked 保留区不变。副屏不适用 3/8/5/8：每屏空间面板独立可调；**Docked 副屏即使 UI 暂时不在也持续预留，Floating 副屏不论 UI 是否显示都不预留**。占用模式或持久预留尺寸由用户在设置里改变后才计算新的 WorkRect；真正原生全屏是该屏例外。

主屏约 1/8 宽度是已确认的默认形态；副屏不要求机械复制 1/8 宽度，尤其竖屏与旋转屏须按自身窗口预览可读性单独设置。两者仍遵循 macOS 毛玻璃、无标题、克制边框和统一视觉语言。

### 3.1 全部可见尺寸精细可调，默认使用已确认方案（本轮新增裁决）

**基本规则：出厂即好用，调整权归用户。** 所有 UI **可视布局尺寸**均提供设置项，保留当前视觉权威确定的默认值/相对比例；用户不进入设置时不必调整任何数值。进入设置后，可以逐项精确修改，主界面本身不出现拖拽缩放把手、尺寸滑块、调节浮层或额外 Header。

| 可调整分组 | 设置中应提供的尺寸项 | 默认规则 |
|---|---|---|
| 主屏面板与副屏面板 | 总宽、总高、上下/侧边留距、纵向偏移、位置锚点 | 主屏完整形态默认约屏宽 1/8；副屏采用经视觉确认的适配布局 |
| 主屏核心分区 | Saytile 高度、Riftlet 高度、Spaces 高度及三者之间间隔 | 原 3/8 + 5/8 为默认，不作为锁定比例；三者高度可分别调整 |
| Saytile 内部排版 | 文字区高度/内边距、字体大小、行距、状态/复制按钮尺寸、按钮间距、声波条大小 | 首次使用继承已确定的 Saytile 设计 token 和三态语义 |
| Riftlet 托盘 | 托盘高度、缩略图显示位尺寸、列/行间距、内边距、展开预览尺寸、按钮尺寸 | 首次使用继承 Riftlet 已确认的托盘和缩略图比例；图片本身按 Fit 不变形 |
| 每个屏幕的空间调度 | 空间区高度、各行高度/密度、行间距、缩略桌面容器大小、内部留白、分页/滚动可视区 | 主屏沿用原完整布局，副屏独立根据其屏幕比例适配 |
| 公共视觉度量 | 容器内/外边距、圆角、分隔线粗细、图标尺寸、可读文本字号、必要交互目标尺寸 | 保持原精致视觉默认值，但可单独调整 |
| 可选模块（仅主屏） | 紧凑入口、展开面板、文本、边距、可滚动区等尺寸 | 依据模块原设计 token，跟随该屏独立配置 |

**精细控制方式：** 设置提供滑杆作快速调节，同时提供**可直接输入的精确数值**、微调步进、预览与恢复默认；布局度量以 macOS 逻辑 point（pt）为主要单位，屏幕相对比例也应可选（例如宽度可在 pt 与“该显示器可用宽度百分比”之间选择），在设置界面注明每项单位和当前生效值。建议微调支持 1 pt 与 0.5 pt 等适当精度，具体控件实现以视觉与像素对齐测试为准；不能仅允许“紧凑/标准/宽敞”三档，也不能只有粗粒度滑杆。

**独立性与保存：** 每块显示器的面板及其内部尺寸配置互不覆盖；若用户只修改 Riftlet 高度，**不能未经确认就重置 Saytile/Spaces 的自定义值**。配置按稳定显示器身份记录，支持逐项、逐模块和逐显示器“恢复默认”；显示器暂时断开时保留其自定义尺寸。若 UI 中提供“全部恢复默认”，必须明确影响范围。

**布局约束而非固定尺寸：** 尺寸调整不得破坏实际桌面/窗口宽高比、坐标与点击映射。空间预览容器任意改变宽高时，内部桌面内容统一等比缩放并按需留白/裁切，不准对每个窗口独立拉伸。用户增大某一模块后，其他已设置的模块不应被静默强制缩小：应优先使用明确的滚动、分页或提示解决溢出。超出实际屏幕、安全区域或可点击/可读极限的数值需有清晰边界和原因，不能产生不可访问控件。不同显示器分辨率、缩放或旋转时重新计算有效显示尺寸，并尽可能保留用户输入的尺寸偏好。

**出厂默认值不等于永久锁定值。** 既有视觉权威文档里的 1/8、3/8、5/8 和微图、按钮、行高、内边距等规格，今后解释为相应位置的**默认设计 token / 出厂 preset**；只有“单主驻留屏、其他屏 Space-only、无标题、真实窗口几何、Saytile/Riftlet 领域语义、必要交互可用性”等属于不可通过尺寸设置破坏的产品边界。

## 4. 多屏空间数据归属：不要发明“每屏独立 Spaces”

- **Native 模式**：副屏只展示系统当前真正与该显示器相关、身份和归属已确认的 Spaces/窗口；空间缩略图整行切换 Space，不独立点击内部普通窗口。尤其在 `screensHaveSeparateSpaces=false` 时，不得将 SkyLight 的 3+1 scope 记录机械解释为“两屏分别有三个和一个可独立切换的 Space”。若系统使用共享 Spaces，UI 必须表达实际跨屏联动；证据不足时不展示虚构的副屏独立列表。
- **Virtual 模式**：显示该屏的 Nearpane 逻辑 Workspace 与实际/可恢复的窗口布局；空间缩略图整行切换 Workspace，不按内部窗口命中。全系统仍只有一个 Virtual 调度引擎；每屏仅是对应的展示和操作入口，不能形成互相争夺窗口的多个管理器。
- 当前空间模式（Native/Virtual）是**全局工作区引擎选择**；每屏的面板角色、位置、尺寸与出现策略是独立的 presentation configuration。二者不得混成同一个设置，也不因角色调整自动切换工作区模式。
- 任何屏幕上的窗口点击和切换，都需要 mode-scoped 的目标身份、display identity、快照版本、能力权限检查，不能用一个屏的窗口 ID/Space ID 猜测另一个屏的目标。

## 5. 生命周期、显示器变更与安全

- 保存 per-display 配置时使用可验证的稳定显示器标识；无法唯一识别时不将旧偏好盲目施加到另一台显示器。
- 主驻留屏拔除时，主表面安全迁移到当前仍可用的显示器，仅迁移**呈现角色**，不复制或重启 Saytile/Riftlet 领域服务；原显示器重连后在无冲突情况下恢复用户指定角色和尺寸。
- 副屏拔除时关闭对应 Space-only presentation window，保留其独立配置；不遗留不可见的交互窗口。
- 显示器旋转、分辨率/缩放、镜像关系和主屏变更时重新校验坐标和 Space/Workspace 归属，不能把镜像输出当成额外独立工作区目标。
- 副屏按需显示不得改变当前前台 App 的焦点；空间整行切换必须由用户点击经确认的空间目标触发，自动模式仅控制呈现，不自动执行空间或窗口激活。
- 原生全屏默认不出现任何 Spaces 调度面板；用户若启用小状态条，只能点击后展开经过验证可见的可移动录音等精简浮层。对全屏 App、Stage Manager、不同 macOS `NSWindow.CollectionBehavior` 组合进行实机测试；未经验证不得承诺覆盖任意第三方全屏界面。
- ScreenCaptureKit 或同类窗口预览刷新由统一资源调度控制：副屏隐藏时无持续的高帧率后台预览；Riftlet 用户主动截图优先于普通预览刷新，不能因多个显示器而倍增无谓采集。
- 子面板故障或显示器切换不影响语音、截图、其他模块及已启用的 Native/Virtual 工作区引擎。

## 6. 工程契约和分阶段工作

建议引入 **MultiDisplayPresentationCoordinator**，独立于 ADR-010 的 WorkspaceModeCoordinator：

- 一份唯一的 Primary Surface，零到多个 display-scoped Space-only Surfaces。
- 全局 WorkspaceModeCoordinator 选择 Native/Virtual 引擎；Display Presentation Coordinator 决定某个显示器显示哪种 UI、何时显示，以及独立的尺寸/位置。
- 每屏配置必须分别保存 `displayIdentity`, `role`, **`spacePanelPlacement: docked | floating`**, `panelVisiblePolicy: onDemand | contextualAuto | pinned`, `reservedRegion`（仅 Docked 生效）, `enabledSurfaces`, `size`, `edge`, `verticalAnchor`, `workspaceRowDensity`, `material` 和版本化 `layoutMetrics`。**WorkRect 只由占用形态和持久预留配置决定，不读 UI 显隐状态**；本轮不实施生产 schema。
- 各 Surface 订阅经一致性验证的 snapshot；基于该屏过滤的窗口/空间集合得到视图数据，不自行构造另一套真相。
- Host 控制焦点、层级、无障碍和召回逻辑；副屏 UI 不拥有独立的录音、截图或工作区控制器。

实施阶段：
1. **P2 mock-based**：先验证两显示器“一全功能 + 一 Space-only”、三显示器、旋转屏、各屏独立设置、主屏拔插迁移、焦点不抢占；不触发真实 Space/窗口写操作。
2. **P1 Native / Virtual**：独立验证不同模式下每屏真正可切换的目标集合及切换后焦点/显示器归属。
3. **P4**：依两个引擎各自通过的 gate 接入真实 Space/Workspace 切换、窗口激活；检查多屏回归。
4. **P6**：按需策略的性能、耗电、系统快捷键/全屏兼容性和用户可恢复体验验收。

## 7. 产品验收条件

- [ ] 只有用户指定的一块显示器显示 Saytile 和 Riftlet；副屏没有重复的语音板和截图板。
- [ ] 主屏与每块副屏的尺寸、位置、占用形态和出现时机互不影响。**副屏默认 Docked，隐藏仍预留；改 Floating 后出现/隐藏均不预留**，切换设置仅影响本屏。
- [ ] 面板、内部模块、按钮、文字、截图缩略图、空间行、间距/内边距等所有可视尺寸在**设置中**可精确输入/微调；不修改时沿用既定出厂值。
- [ ] 修改某项尺寸不重置其他项；支持预览、逐项/模块/显示器恢复默认并保持跨重启与显示器重连。
- [ ] 极端尺寸组合不得导致失真、错误点击热区、无法访问的控制或未经提示的布局压缩。
- [ ] 主屏在无空间调度需求时可不展示 Spaces，仍继续显示有使用需求的语音/截图；有多空间/多窗口需求时空间区保持可见，无论 UI 如何变更都维持 WorkRect。
- [ ] 副屏默认隐藏，能在其所在屏幕被用户明确唤出；多目标自动与固定模式为可配置选项。
- [ ] 自动出现按真实有效的切换目标计算，不对临时窗口、重复 CGWindow 记录或失效目标做错误判断。
- [ ] 副屏唤出不会抢走前台 App 焦点或遮挡关键系统交互；全屏默认不显示 Spaces，也不自动展开录音浮层。
- [ ] Native 的共享/独立 Spaces 语义得到正确表达；Virtual 的每屏工作区集合与窗口恢复机制不因副屏而改变。
- [ ] 90° 旋转、多显示器相对位置、缩放和窗口跨屏状态下预览几何、点击目标与真实对应。
- [ ] 拔除/重连任一显示器后主驻留角色与 per-display 偏好可靠恢复。
- [ ] 多屏空间预览不会拖慢 Riftlet 用户主动截图或持续占用高帧率截图资源。
- [ ] 仅文档和 mock 验证不能宣称 Native / Virtual / 副屏实际生产实现已通过。

**最终裁决：Nearpane 是一个单一工作系统，只有一块主驻留屏拥有完整工具界面；其他显示器可以拥有独立、按需出现、独立配置的轻量空间调度面板。空间引擎是全局选择，显示器呈现策略是局部选择。**
