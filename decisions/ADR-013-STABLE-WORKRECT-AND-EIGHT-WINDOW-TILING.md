# ADR-013 — 稳定工作区域、渐进平铺与按策略扩容（8 窗阈值，非硬上限）

**状态：ACCEPTED（产品裁决；2026-11-09 增补双扩容策略、独立多屏保留策略和退出恢复；工程尚未验证）**  
**日期：2026-11-09**  
**优先级：** 本文件为当前窗口容量、空间平铺及持久 WorkRect 的最新产品权威；覆盖 ADR-012 的随 UI 隐藏释放保留区、ADR-013 早期的“超过 8 窗一律拒绝/8 是硬上限”、自动暂存、拖放不创建工作区等旧规则。与 ADR-011 的多屏显示模式配套。  
**继承：** ADR-010 双模式，ADR-011 主/副屏独立呈现，ADR-012 原生全屏、整行点击、单一产品、跨屏焦点规则。  
**授权边界：** 本轮为产品/设计/工程契约修订，不授权真实用户工作窗口写操作、系统 Space 变更或生产代码合并。

## 1. 永久普通桌面 WorkRect：保留区不随 UI 隐藏释放

- **非原生全屏**时，每块显示器按独立设置的呈现形态计算稳定 WorkRect：主驻留屏默认驻留式，预留约 **1/8** 可用宽度；**副显示器的空间调度默认也采用驻留式并预留独立的可配置区域**。只要该屏面板形态为驻留式（Docked），即使其 UI 暂时隐藏、收起或暂不显示，普通窗口也不得占用已预留的边界。若用户在设置中将副屏空间调度改为**浮窗（Floating）**，则始终**不为浮窗预留**，无论浮窗显示或隐藏，底下普通窗口都可以使用原区域。
- 每屏的 **Docked / Floating** 是独立、持久的**空间占用模式**，与 On-demand/Auto/Pinned 等**显示时机**分离。只有用户主动切换占用模式、改变预留宽度、显示器有效几何变化或真实窗口成员/布局改变时，才可按需要调整实际窗口 frame；面板的显示/隐藏不能触发 WorkRect 改变。Docked→Floating 可以在明确设置后安全释放该屏保留区；反向切换则创建预留区并重新平铺一次。
- 语音等精简工具浮层仅覆盖显示，不改变各屏驻留/浮窗占用策略。驻留式面板 UI 暂时隐藏后，其区域依旧保留；浮窗式空间调度显示和隐藏时则始终不产生预留。
- **真正的 macOS 原生全屏**是唯一默认例外：全屏 App 得到完整显示器（不再限制 7/8），不显示空间调度；退出后恢复当前配置的 7/8 WorkRect 与空间平铺。
- macOS 的 `NSScreen.visibleFrame` 并不会因为 Nearpane 自行出现就改变；WorkRect 的实际窗口限制必须由经过授权与实机验证的 Window Tiler 维持，不能把只是视觉上留白当作成功。

**核心原则：窗口决定 Nearpane 的展示状态；Nearpane 的展示状态不反向改变普通窗口的工作区域。**

## 2. 按内容与实际空间状态组合 Nearpane，不强制一个固定大面板

非全屏的主驻留屏根据真实工作状态显示相应部分，而不是始终占满一条顶天立地的可见侧栏：

- **存在需要调度的 Space / 窗口集合**：空间调度区必须可见，不能因为鼠标移开、模块关闭或自动收起策略把正在使用的空间预览藏起来；可用判据包括至少两个实际可切换的 Space/Workspace，或者当前空间存在至少两个受管理普通主窗口。空间数据不确定时先降级，不凭 CGWindow 原始计数伪造。
- **只有一个桌面空间、一个普通窗口、没有其他需要调度的空间目标**：Space 调度区可以收起/不呈现；若语音或截图模块仍在使用，继续显示对应模块（不强制呈现 Spaces 空容器）。
- **语音、截图、空间调度均无需要呈现的内容/状态**：主界面可完全隐藏；只影响表面可见性，工作区的 1/8 预留仍存在。这里“没有使用”指模块真正无须显示的状态，不得以隐藏等同暂停录音、丢失转写/截图。
- 用户在设置中可以分别调整各模块显示策略、尺寸和位置；全屏覆盖行为独立配置，**不自动唤出**录音正文或完整空间面板。副屏保留 ADR-011 的独立 Space-only 出现策略，不能由主屏可见性推导其窗口归属。
- 完整/半模块/隐藏是 **Presentation State**，不是 Window Layout State。除非用户明确修改持久 WorkRect 或实际加入/移除窗口，这几种界面状态转换不得移动、缩放、隐藏普通主窗口。

## 3. 窗口加入空间的主要操作：拖动其他窗口缩略图

- 用户从另一空间的某个**具体窗口缩略图**拖动到目标 Space/Workspace 行，即申请将该真实窗口加入这个空间并按目标空间现有窗口数重新平铺。也可以由产品将来提供经验证的窗口选择来源，但**主要交互是缩略图拖放**。
- 这与原来的“**单击空间行切换整个空间**”完全兼容：click/press=切换 Space；明确开始拖动某窗口缩略图且达到拖拽阈值=拖移该窗口。缩略窗**不是独立点击激活目标**，但可以是有明确身份的 drag source。禁止把拖放误识别成点按或反过来。
- 拖动悬停目标行可显示轻量、真实可行的布局预览；预览本身不能抢焦点或先移动窗口。用户真正 drop 后才校验源/目标模式、window identity、权限、当前 Space membership、目标容量、最小尺寸限制、当前 revision 与跨显示器变换，再提交真实操作。
- Native 向其他原生 Space 移动窗口只在对应 OS build 有经过验证的能力时启用；Virtual 通过其经验证的逻辑工作区调度实施。不得把从一个 Space 往另一个 Space 的拖移简单用“画面交换”冒充成功。
- 成功后更新来源/目标空间的成员和布局。目标空间达到**8 窗默认分流阈值**时按本 ADR 的“超过新建 / 无限分割”设置路由；未取得跨 Space 创建/移动能力时不伪造新空间，而尝试安全继续分割。失败或取消必须保留/恢复窗口的可访问状态，不能无声丢窗。

## 4. 渐进布局与两个可选扩容模式（8 窗默认阈值）

`W1, W2, …` 按空间中普通主窗口的加入顺序编号，布局相对于当前显示器的 WorkRect 计算。**前 8 窗的默认几何保持原方案**：

| 当前窗口数 | 默认布局 |
|---|---|
| 1 | W1 填满 WorkRect |
| 2 | W1/W2 左右平分，各占 1/2 |
| 3 | W1/W2 上下平分右侧 1/2（各占 1/4）；新加入 W3 独占左侧 1/2 |
| 4 | 把 W3 左半区二分，形成四个 1/4 |
| 5 | W1/W2 进一步平分一个 1/4（各占 1/8）；新 W5 独占另一个 1/4；W3/W4 分别占 1/4 |
| 6–8 | 继续按可预测的稳定顺序渐进二分，尽量保留已有相对槽位，无重叠、无越界 |

**第 9 窗不再一律拒绝，8 不是硬上限。** 在设置里提供两种明确可切换的 **Window Overflow Policy**：

1. **超过阈值新建空间（默认，Create New Workspace Above Threshold）**：目标空间达到 **8 个受管理普通窗口**后，用户拖入或第三方 App 自行产生的新增窗口，优先由当前 Native/Virtual 引擎**创建或分配到新的合法工作空间**，新空间从一个窗口开始继续正常平铺。Native 创建原生 macOS Space 和跨 Space 移窗**必须经过对应 OS build 的技术能力、权限与用户选择验证**；不能创建或迁移时，**自动降级为在当前 WorkRect 继续渐进分割**，不因技术限制直接拒绝第 9 窗。Virtual 只创建 Nearpane 逻辑 Workspace，不冒充系统 Space。
2. **无限分割（Continuous Split）**：不因第 8 个窗口而主动新建空间；第 9、10……窗继续在**同一空间**的 WorkRect 里按稳定规则分割现有分区，优先从原来的 W1/W2 等已有小块进一步二分，保持无重叠和可操作性。这里“无限”指**没有预先规定的数量硬上限**，不代表实际可以无限缩小第三方应用窗口。

对于默认模式无法新建时的分割回退，设计的主要极端示例是由 8 窗继续分割旧区域，逐步容纳至 **16 窗**；再多则沿同一递归二分规则处理，暂不专项设计新的手绘模板。**16 也不是产品硬上限。** 4 窗以内是需要最高质量优化的常见场景，5–8 窗必须正确，9–16 窗重点保证身份、容量、无重叠及可恢复；超过 16 的极限使用不应挤占首版工程优先级。

**新窗口来源一致：** 无论是用户通过缩略图 drop，还是第三方 App 自行打开新普通窗口，都应用当前空间的扩容策略；不得只有拖拽路径才能处理容量。若 Native 的系统约束、权限不足或窗口最小尺寸使创建与继续分割都不可行，Nearpane 只能明确标记 **unmanaged / overflow / needs-attention**，保持窗口打开且用户可访问；不能擅自关闭、隐藏、离屏停放、错误转移，也不能宣称全空间无重叠已达成。

两模式都遵循应用的真实最小宽高、身份/权限、显示器可用区域和用户的明确布局偏好。任何自动创建/分割必须对真实窗口 frame/空间归属取得后验确认；技术能力不足时提示实际状态，而非绘制期望结果。

## 5. 用户可以移动真实窗口、改变分区；增加第三窗触发模板重排

- 用户拖动真实窗口改变在平铺布局中的**方位/槽位**，与相邻窗口**交换/重排**，始终保持窗口无重叠、无出界、无侧栏侵占。
- 用户手动拖动分隔边界或改变某窗口尺寸时，其相邻分区同步调整，避免窗口回弹至固定 50:50；用户编辑后的布局可保存为当前空间用户布局。
- **明确的例外/重排触发：** 用户在两窗布局下即使已经调整比例或左右方位，**加入第三个窗口时依然采用标准三窗模板**：旧 W1/W2 上下平分右半区，新 W3 占左半区；完成加入后依然可调。**移除窗口（例如三窗恢复两窗）时，若剩余这组窗口保存过两窗的自定义排列/比例，优先恢复那份历史；没有对应历史才使用默认 50:50。** 窗口身份必须确认，不能误用另一组应用的布局。
- 当用户只是隐藏、打开、切换 Saytile、Riftlet 或 Space 界面时，**不触发窗口重排**。当用户真正加/减窗口或主动调整布局时，才更新窗口 frame。
- 完成一次平铺前必须确认实际 window frames、最小尺寸与跨屏身份；失败时不虚报成功，不把系统弹窗作为普通主窗强行平铺。

## 6. 原生全屏录音浮层：位置稳定比智能追逐重要

- 用户之前选择或拖到的位置是主锚点；重新进入同一显示器/全屏环境时尽可能保持**原位**。
- 智能避让只为避免遮挡可确认的交互按钮、系统安全区或不可操作区域，按**最小必要位移**计算；不持续跟随鼠标、焦点、文字更新或窗口动画移动浮层。
- 用户手动拖动具有最高优先级，位置改变后更新锚点；若无法识别底层 App 的按钮，应允许用户自行摆放，不能自信声称“绝不遮挡所有第三方按钮”。
- 原生全屏状态下仍然只有用户点击小状态条才展开浮层；不展示 Spaces 调度，不自动打开文字流。
- 真正的 macOS 原生全屏才可使用整个屏幕；任何普通最大化、macOS 非原生 Fill 或占满窗口都仍被限制在 WorkRect（默认 7/8），不是把非全屏当作全屏。

## 7. 退出 / 恢复窗口状态

- **隐藏、收起、暂不显示 UI**：Nearpane 继续运行，Docked 模式的保留区不变，窗口 frame 不因 UI 显隐改变。
- **用户明确退出 Nearpane**：停止对窗口的管理并结束预留区占用，按接管之前记录的原生 macOS 窗口/显示器/空间及有效 frame **安全恢复原有布局**；不再长期留下无意义的 1/8 空白。恢复须核对身份、状态和可操作性，部分窗口不可恢复时给出明确结果，不能把未完成的恢复标为成功，也不能操作已变化身份的其他窗口。
- **崩溃/异常退出**：不得重复启动不受控的移动循环或丢失窗口；按经过验证的恢复日志提供安全的恢复路径。重启后恢复 Nearpane 的显示器、Docked/Floating 和窗口布局偏好，但不自动越权重新接管窗口。

## 8. 验收要点与工程边界

- [ ] 主屏和副屏 **Docked** 都在非原生全屏时保留本屏独立配置的工作区域，UI 显示/隐藏均不能改变；副屏切为 **Floating** 后，无论浮窗出现/消失，都不产生预留。
- [ ] 用户在设置里明确切换 Docked/Floating 才触发该显示器一次受控 WorkRect 变更和真实窗口重排，其他显示器不受影响。
- [ ] 两种扩容模式均可在设置里选择，**默认 8 窗阈值优先新建**；Native/Virtual 能力不支持新建时回退分割。用户选择“无限分割”时第九窗不新建空间。
- [ ] 1—8 窗遵守既定逐步分割布局；9—16 窗递归二分并遵守最小可操作尺寸，不把 16 当硬上限，超出不作为首版重点。
- [ ] 第三方 App 自行创建第九窗与缩略图拖入第九窗都遵守同一策略；两条路径在无法新建/分割时都不丢窗、不偷偷隐藏或挪离屏幕，明确表达受限状态。
- [ ] 用户调过双窗布局，加入第三窗按三窗模板重排；再移除第三窗，**恢复原先保存的双窗自定义比例与槽位**；无历史则 50:50。
- [ ] 明确 Quit Nearpane 后停止接管并安全恢复接管前的原生窗口布局，不再保留 1/8；仅 Hide Nearpane 保留配置及 WorkRect。
- [ ] 主/副屏的空间面板可见性与 Docked/Floating 占用形态分离；全屏不显示 Spaces，录音等精简浮层用户主动唤出、位置保持优先。
- [ ] 跨 Space 拖放、Native 新建/迁移、Virtual 新建/恢复、异常退出均先以自建测试窗口验证，未验证不对真实用户窗口执行危险动作。

**最终裁决：Nearpane 以稳定 WorkRect、真实窗口几何和持续可恢复的空间管理为核心。主/副屏默认 Docked 保留工作区域，副屏可独立选 Floating 不保留；超过八窗默认新建工作空间，做不到就继续分割，亦可由用户选择始终分割；窗口退出恢复已有自定义布局、Nearpane 明确退出恢复接管前的系统布局。8 和 16 都不再是不可突破的硬上限。**
