# LyricTile 1.0 · 视觉与交互定稿

日期：2026-11-26。本文数值为最终设计起点，不是已经测得的性能或 macOS27 原生呈现结果。高保真 HTML 的 CSS 只表达视觉，不作为 Swift/AppKit 实现代码。若展示稿与规格产生差异，以本文的尺寸、状态、动作和可访问性要求为准，再更新展示稿；不得在实现中随意重做产品方向。

## 1. 命名与品牌

- 正式工作名：**LyricTile**。大小写固定，用户界面不写 LYRICTILE；HOLDSNOW 母品牌仍全大写。
- 中文描述名：**歌词板**。首版不另建中文商标名；“词页”只作为视觉方向的名称。
- 一句话定位：**随音乐同步，在桌面右侧安静显示歌词；需要时，就近控制原播放器。**
- 面向用户的主文案：**歌词，自然在旁。** 副文案：“照常听歌。需要时，歌词与控制都在这里。”
- 图标是三条歌词笔画与一个阅读游标，珠白基底、石墨笔画、微量紫灰点。母品牌的雪花/齿轮不叠在小图标里；不同产品靠主体符号识别。
- 生成图 `assets/app-icon-concept.png` 表达材质。确定性 SVG 符号与 Light/Dark 母版定义几何。发布时用 Icon Composer/Xcode 生成系统需要的资源；24/32/64 px 必须仍识别为“阅读中的文字”，不保留生成图毛边。
- 名称是本轮产品裁决，不是商标/域名可用性的法律结论；没有购买域名或创建远端仓库。

## 2. 三个方向的独立评价

| 方向 | 结构 | 独立优势 | 主要代价 | 裁决 |
|---|---|---|---|---|
| A 雾白词页 | 176–224 pt 窄竖页，歌词居前，悬停显示内部控制层 | 桌面伴随感最强；与语音/截图共列；对背景与封面质量不敏感 | 必须精心设计长歌词；有一部分空间为控制预留 | **选作唯一正式方向** |
| B 封面回声 | 封面铺满，底部歌词，较大沉浸卡片 | 情绪与音乐辨识强；适合独立聆听 | 封面质量主导结果，字底对比波动；侵占工作注意力 | 保留设计探索，不进入1.0主题菜单 |
| C 双行字幕 | 横向两行歌词，短而宽，控制同一横条 | 独立屏幕角落占高少，长句易读 | 与共同列宽冲突；完整hover控制挤；容易再长出第二种窗口模式 | 不作为1.0分支 |

三个方向不需要做成三个皮肤让用户代替产品团队选择。正式版只实现 A；从 B 吸收极低强度封面色，从 C 吸收简洁的文字层级。

## 3. 桌面几何

所有数字以 macOS **point** 为单位，不用物理像素。独立产品的默认宽度：

`W = clamp(176, 224, 4 × round(visibleFrame.width / 32))`

等价于将可见宽的1/8四舍五入到4pt，并设置可读上下限。例如1280pt屏为176、1470pt屏为184、1664pt屏为208、1920pt屏为224。使用 visibleFrame 排除菜单栏和 Dock；坐标计算统一以左上归一后再转换 AppKit 坐标。

| 项目 | 定稿 |
|---|---|
| 默认高度 | 272pt；悬停/暂停/缺词不改变外框 |
| 外圆角 | 22pt；控件局部按原生形状，不做多层发光描边 |
| 桌面边距 | 右16pt，顶部16pt；单独运行默认右上；用户可拖至空闲处 |
| 同列间距 | 10pt；同显示器共享W和列锚点 |
| 内边距 | 左右16–18pt，顶部14pt；内容不可侵入圆角 |
| 控制中心 | 当前歌词区域顶部约87pt；hover不移动当前行字形 |
| 封面 | 32×32pt、7pt圆角，悬停顶栏显示 |
| 传输按钮 | 32×32pt点击区域，图形16–18pt；间距15pt |
| 返回播放器 | 28×28pt点击区域，14pt图形 |
| 拖动区域 | 上沿约10pt与非文字空白处；不能把歌词滚动/选择误识别为拖窗 |
| 完整歌词 | 显式打开360×520pt原生popover/辅助窗，向左展开并避让工作区；不是hover自动变大 |
| 无播放 | 正常隐藏；用户主动唤出显示高62pt等待条。协调占位仍保留272pt，等待条位于占位顶部，不触发其他组件上移 |

用户改文字大小时保留读得清的字号，不缩字体硬塞。272pt容纳不下时隐藏上下文，当前词句仍完整可跟随。无真实词时间的长句转为可读的整句滚动/展开，不用省略号隐藏正在演唱的内容。

## 4. 材质与颜色

阅读底层使用 `NSVisualEffectView` 标准材质（起点 `.popover`，behindWindow、active），叠加极轻的中性色保护层。控制使用 SDK 提供的原生按钮/玻璃样式，最低支持系统没有对应 API 时退普通材质。**正文层不叠多块 Liquid Glass**。苹果对材料的当前定义把 Liquid Glass 主要放在导航/控件层，普通材质用于内容分层。[Apple HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

以下RGBA为设计参考，真正材质会随系统合成变化；验收看最终对比、密度和层级，不要求系统模糊逐像素复现浏览器 CSS。

| Token | 浅色 | 深色 |
|---|---|---|
| 主文字 | #272A31 | #F1F1F3 |
| 未唱部分/次文字 | #656A73 | #C2C6CF |
| 上下文 | #70747C | #B0B6C1 |
| 阅读保护层参考 | rgba(250,250,249,0.87) | rgba(36,41,50,0.90) |
| 静态强调点 | #7566CE，少量 | #A59BDC，少量 |
| 降低透明度 | #F6F6F5，实色 | #282C34，实色 |
| 外描边 | 明亮环境中1px轻亮边 | 低透明白描边 |

封面取色只在身份匹配后进入顶部柔和色晕，透明度上限0.10；同一曲缓存一次，封面不持续流动。中/小歌词正文对比目标≥4.5:1，大号正文也按4.5验收；支持文字不得靠透明淡到不可读。Increase Contrast 会提高保护层密度、强化文字与细边；Reduce Transparency 彻底关背景透视；Reduce Motion 停掉位移，保留短淡变。

不会为“读取壁纸决定字色”申请屏幕录制；使用系统材质响应、明确浅深外观和保护层即可。无需假装网页的 backdrop-filter 就是已验证原生 Liquid Glass。

## 5. 字体、多语言与长歌词

- SF Pro Text/系统字体；中文由系统 PingFang SC 回退。正文 Medium 500起点，视觉较重的字形可退Regular，禁止全界面粗黑。高保真Linux字体仅是近似呈现，正式稿需在Mac复核字面。
- W≤184正文18pt/行高25pt；W≥188正文20pt/行高27pt。较大档22pt，缩减上下文，不自动压到小字号。歌词最多三条物理行构成当前块。
- 上下句12pt/18pt；曲名11pt，歌手10–11pt；进度10pt且等宽数字。可交互文字至少11pt；10pt时间为非主操作信息，读屏仍提供完整值。
- 默认为自然阅读起点对齐；中文/英文左对齐，RTL按段落语义右对齐。正文不做描边、投影、字距拉大或横向跑马灯。
- 分离原始文本与匹配规范化文本。字形布局按CoreText UTF-16范围并验证grapheme边界；不能使用Swift Character计数直接做UTF-16切片。
- 英文优先单词换行；超长单词必要时分断。中文按合法断行避开开头标点。emoji、组合音符、阿拉伯连写与双向混排按实际glyph runs绘制遮罩。
- 翻译/音译只有来源提供时显示；主原文优先，译文11–12pt。1.0不新增AI翻译、不为每词开网络请求。
- 有词级时间的长句按真实演唱token选择当前子行，切换最多移动一个物理行，不能整个长段突然滚完。没有token时间时保持行级高亮，提供滚动与“完整歌词”。
- 双唱/和声在模型保留；窄板先呈现主唱，有同步背景人声时以下一级短行呈现。不能把重叠时间强制串行重排。

## 6. 动画与输入节奏

| 事件 | 参数 | 行为 |
|---|---|---|
| 指针进入 | 连续进入140ms；控件淡入160ms | 极短路过不闪烁；当前歌词与外框不动 |
| 指针离开 | 延迟280ms；淡出180ms | 进度拖动、按压、popover、读屏/键盘焦点仍在时不隐藏 |
| 行切换 | 220ms，cubic(0.22,0.72,0.18,1) | 主要为opacity与≤8pt垂直位移，稳定阅读锚点；无弹簧过冲 |
| 词高亮 | 真实词时码+健康媒体时钟驱动，线性语义 | 只更新活动词遮罩；不把高亮本身套缓动，不跟随字数均分 |
| 切歌 | 新身份到达后旧词120ms淡出，新词160ms淡入 | 旧词不能留到新曲上；封面较晚到达不得回填错歌 |
| seek | 读回确认新位置后立即定位新cue，再做≤120ms淡变 | 拖动阶段只显示独立预览；失败回真实位置；不从旧句滚过中间二十句 |
| 封面更新 | 220ms交叉淡变 | 仅同generation结果；模糊取色不逐帧计算 |
| 明暗变化 | 原生系统过渡或180ms淡变 | 不闪白；减少动画时直接稳定落位 |
| 列布局变更 | 新位置180ms淡入，opacity使用cubic(0.2,0.8,0.2,1) | 旧窗淡出并确认撤下，隐藏中setFrame后在新位置淡入；不做跨槽滑动，不声称多进程WindowServer原子移动 |

纯文本不自动切句；只有行时码加健康时钟才逐行同步；真实词时码加健康且合格的时钟才逐字。整个歌词板不用持续呼吸、弹跳、流光或频谱。只有真实播放与交互引起变化。仅活动token可运行60Hz屏幕刷新，低电量30Hz；普通逐句按下个边界安排更新；暂停、隐藏、没有歌词时停止帧时钟。最高帧率与CPU预算必须一起实测。

## 7. 状态与用户动作

| 状态 | 常态内容 | 悬停/动作 | 退出条件 |
|---|---|---|---|
| 播放+同步歌词 | 当前行、上下文、来源小字 | 封面/曲名/传输控制/真实进度/返回 | 歌曲或播放态变化 |
| 暂停 | 保留当前位置，底部来源行显示“已暂停”轻提示 | Play；只在能力允许时seek | 真实恢复事件；不能因为动画自动调用play |
| 间奏 | 静态三点+“间奏” | 控制保留 | 仅真实cue end到下个start存在空白时适用 |
| 行尾未知、等下一句 | 保留上句或“等待下一句” | 控制保留 | 不把长间隔擅自判成间奏 |
| 纯音乐 | “此刻，只有音乐。” | 封面与控制 | 必须有可靠instrumental标记/用户确认 |
| 搜索中 | 新歌曲信息+短暂“正在找歌词” | 不反复spinner抢眼 | 通常≤3s后可改“仍在查找”，整体请求预算明确 |
| 无歌词 | “还没有找到歌词” | 选择版本/导入文件/来源记录 | 新来源命中或用户绑定 |
| 纯文本 | 静态歌词、明确“未同步” | 手动滚动；可导入时间歌词 | 不以估计时间冒充同步 |
| 临时进度未知 | 已知歌名+“正在重新连接播放器” | 禁用seek，高亮冻结；返回播放器 | 获得新有效锚点 |
| 源不提供进度 | “此播放器暂不提供进度” | 文本可读，不自动同步，不无限重连 | 源能力变化或切换播放器 |
| 没有播放 | 默认15s后隐藏；手动打开为等待条 | 菜单栏“显示歌词板”可找回 | 真正开始播放；暂停不算没有播放 |
| 播放器退出 | 停止媒体观察、清理旧任务 | 重新打开原播放器入口按需 | 新实例启动 |
| 授权拒绝 | “连接Apple Music”等具体入口 | 用户主动重试或打开对应设置 | 不反复触发TCC |

不可用能力按场景处理：首次不支持seek就显示不可拖的进度线；能seek但临时失去位置时禁用并用短提示解释；不要摆一个看似可用、实际什么都不做的滑块。返回播放器总是针对当前歌曲的来源App，不用系统任意frontmost app。

## 8. 完整歌词、滚动与校准

主板滚轮在歌词阅读区浏览附近行，显示“回到当前句”；停止主动滚动5s再自动跟随，鼠标正在阅读/选择时继续保持。用户点击任一歌词行不默认seek，避免误触改变音乐；可从明确操作“从这一句播放”发seek。完整歌词窗的点行seek必须有能力与时间标识。

悬停后的歌名是带小下拉指示的按钮，点击使用原生NSMenu打开歌曲菜单；返回播放器箭头独立。菜单包含：选择歌词版本、时间校准、导入歌词、查看来源。时间校准以“提前／延后”显示，每步100ms，范围默认±10s；数据层正advance表示歌词提前，`lookup=media+sourceAdvance+userAdvance`。偏移绑定录音身份和歌词hash；换版本不继承错误值。不要把动画提前量、设备音频延迟和歌词源偏移混成同一个神秘常数。

## 9. 首次安装与极简设置

首次启动1个欢迎页。先检测运行的播放器，不为了检查授权把未运行的播放器启动。首次实际连接Apple Music/Spotify才请求对应Automation；解释“读取当前歌曲和进度，并响应播放按钮”。默认不请求辅助功能、屏幕录制、麦克风、完全磁盘访问。

在线查词说明只一句：“查找在线歌词时，会向歌词服务发送歌曲名称、艺人、专辑与时长等匹配信息。”来源与缓存页提供关闭在线查词、清理缓存、查看来源条件，不要求注册LyricTile帐号。平台标识只展示最终验收通过的，设计稿中的目标支持不是已经通过。

设置分显示、播放与歌词、通用三组。主设置保留外观、字号、显示位置、协作排列、跟随播放器、已有翻译、无播放时隐藏、登录启动。歌词来源与缓存折叠进入。登录启动默认关，由用户开；不强制快捷键、不要求记快捷键。

菜单栏：显示/隐藏歌词板、跟随的播放器、设置、检查更新、退出。诊断只在帮助里，默认不记录歌词全文、cookie或用户文件路径。

## 10. 多产品、显示器与辅助功能

默认顺序Saytile→Riftlet→LyricTile，可拖动调整后持久化。只与支持同版本TileKit协议的产品自动协调；未迁移旧版不能被远程重新定位。无需AX去猜同品牌其他窗口，单独运行仍完整可用。

多屏按display UUID保存位置，不用临时display ID作为长期主键。只在用户选择的屏显示一份；屏幕断开时优先迁到主屏空闲槽，放不下再按稳定顺序选择其他有效屏；都不足则待放置。重新接上不立即把正在操作的面板抢回。默认普通Spaces显示，单独提供“在全屏时显示”开关，默认关；不盖住系统安全窗口、菜单、Mission Control。

Nearpane内采用同一LyricView和领域核心，但遵循Host的宽度/高度约束，不强行把Nearpane改成1/8，也不把独立NSPanel嵌到Host里。独立App与Host使用模块拥有者协议，避免双套媒体观察和双面板。

VoiceOver给歌曲/来源/状态、每个按钮与slider提供标签；默认不逐词直播播报打断其他工作，可选择按行通知。标准键盘焦点只在用户主动进入面板/菜单后建立，不能为了可访问性在hover时抢key。透明区域不得形成横跨桌面的鼠标拦截窗口。
