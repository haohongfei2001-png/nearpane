# 本机歌词板实测

2026-11-26，macOS 27.0（26A428），内置 Retina 2940×1912，窗口以逻辑点计。使用签名的独立应用、真实 Apple Music 和原创验收音轨。截图仅包含应用自己的窗口。

| 操作 | 实际结果 |
|---|---|
| 首次启动 | 欢迎页显示在线歌词开关、发送的曲目字段及 Apple Music/Spotify 自动化说明。“开始使用”后首次访问 Music 出现系统授权请求，允许后读到歌曲。 |
| 导入歌词与同步 | 从歌词板进入“选择歌词”，在系统选择器导入本地 LRC。在 83.98 秒读到第 17 句，随后第 23、24 句与进度一致。 |
| 悬停及离开 | 在同一个 184×272 pt 窗口显示歌曲、返回播放器、上一首、播放/暂停、下一首、可拖动进度。指针移出后恢复歌词主体。 |
| 集成包复测 | b28d988，1.0.0 (2)。进度 3.6 秒，点击播放后按钮显示暂停。两张截图中同一句文字位置一致，控件按指针进出显示/隐藏。重启后恢复已绑定歌词与原窗口位置。 |
| 邻近组件 | Riftlet 1.0.10 的窗口 (1278,118,184,86)，Saytile 0.20 的语音板 (945,51,280,166)。LyricTile 在 (1270,214,184,272)，与 Riftlet 间隔 10 点。退出 Riftlet 后 4 秒内 LyricTile 回到 (1270,49,184,272)，Saytile 保持原位置。记录使用 WindowServer 左上原点。 |
| 全屏与 Space 切换 | 用临时原生应用进入独立全屏 Space。关闭“在全屏时显示”时歌词板未出现；打开后 WindowServer 读到 184×272 pt 的歌词板。两次都收到退出全屏回调并返回原桌面；已恢复默认设置。 |
| 跨屏拖动、重启、热拔除 | a8c470d，1.0.0 (3)。在同一台 Mac 上创建临时 1920×1080 1× 虚拟显示器。通过歌词板抓手拖入，窗口停在 (3150,46)，宽 224 pt。退出并重启新进程后停在同一位置；移除显示器后窗口回到内置 2× 屏 (1270,49)，宽 184 pt。只在松开鼠标后提交新位置。见同目录 window-observations.json。 |
| 深色、字号与更新页面 | 同一 build 3 的应用内切换测试。较大歌词文字开关读回 0→1→0。窗口截图同一背景点在深色时为 sRGB (56,61,69)，跟随系统时为 (247,247,247)，截图尺寸保持 368×544 px。旧包该点在两种设置下均为 (247,247,247)。菜单“检查更新…”通过实际 Sparkle 界面报告 LyricTile 1.0.0 已是最新版。 |
| 登录启动与退出 | 通过真实设置开关读回注册状态从关到开，注销后回到关。通过菜单退出后窗口和进程都消失。未注销当前 macOS 用户以执行实际的重新登录。 |

首次启动、导入、组件、全屏、登录项及退出使用 2e515ada 上的 Developer ID 候选，悬停截图使用 b28d988。跨屏及外观回归使用 a8c470d。系统当前只有一个普通桌面。未连接物理 DELL，未强制整机睡眠。
