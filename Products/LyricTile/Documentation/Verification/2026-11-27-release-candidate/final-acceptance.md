## 已完成的实际修复

### 欢迎页尺寸与内容

CI36 的 `PASS` 没有阻止欢迎窗口达到 2157pt。原因是未约束的 `NSHostingView` 在可靠宽度建立前，把 SwiftUI 拟合高度作为窗口最小尺寸。现在关闭这条自动 sizing 路径，显式给定内容尺寸并限制窗口调整；验收在内容挂载和布局稳定后读取真实窗口。

目标为欢迎页 **400×360pt**、设置页 **450×620pt**。欢迎页的标题、预览、在线查询说明、权限说明和操作五个区域必须存在、在内容边界内且不重叠；负例测试明确拒绝原来的 2157pt。中文/英文与深/浅色分别运行。设置页有真实尺寸与完整截图，但其低频折叠项不冒充已逐项操作。

### 播放身份与暂停时钟

真实 QQ 音乐 seek 后曾把暂态媒体 UUID 当成新歌曲，导致已导入歌词消失；网易云也出现相同现象。修复只对已观察的 QQ build 73284/73285、网易 build 3459 稳定同一录音身份，保留真实的歌曲标识、元数据变化与未知版本行为。CI40/41 的原始负例保留在同目录。

QQ 和网易曾在已暂停时继续报告 `rate=1` 与旧 seek 锚点，造成时间回跳。对于上述精确版本，缺少可用暂停时钟时进度设为不可用，保留当前歌曲与歌词文档；界面显示“已暂停 / Paused”，不制造新的锚点。真实 `rate=0` 暂停读数继续使用，恢复后回到新的真实播放器时间。CI44 的网易 756ms 回退原件及修复后的原生读回独立保存。

### 常驻开销

隐藏控制层时，歌词模型不再每秒发布整幅视图的时间更新；按下一个真实歌词边界调度，切歌、seek、文档和偏移变化会重排。继续保留播放器健康读取、15 秒锚点过期、hover 进度和具备资格时的逐字更新。每次性能采样后重新检查实际 cue 与源时间区间，不能用停更歌词降低 CPU。

## 原生视觉与交互的范围

生产布局覆盖 12 个原创场景：176/208pt、长中文与英文、深浅色、hover、无歌词紧凑态、缺少元数据和无播放透明态。长句正常态可显示多行，hover 为控制区留出空间后显示较少的完整文本行，其余可原生滚动并有 tooltip；不承诺任意长度同时全见。欢迎/设置另有中英 × 深浅四组合。现场截图只证明其记录的显示比例；本轮主机为实际 **1× backing scale**。

真实播放器流程独立检查开始播放显示、无歌词 104pt、导入后扩容 192pt、seek、暂停与恢复、鼠标移入/点击暂停/移出、隐藏与重新出现。输入来自系统 CGEvent，并检查真实 AX 命中及播放器读回；不是手工固定 hover 状态，也不称为物理硬件鼠标测试。Music 的两首不同原创 WAV 另检查 next 清除旧文档、第二首导入扩容，以及 previous 返回第一首后自动恢复原绑定。

CI44 的壁纸测试使用同一进程、同一窗口，在实际桌面浅色、深色和繁忙背景上采集 WindowServer 图片，并恢复原壁纸与 QQ 窗口状态。它覆盖浅色 App 在三种壁纸上的实际显示，不扩展为所有屏幕、所有缩放或多屏热插拔结果。CI49 的系统桌面 API 未读回所请求的新壁纸，矩阵如实记为 BLOCKED、没有新矩阵截图；原壁纸和 QQ 窗口状态已恢复。

TileKit 的排列、收缩释放 88pt、扩容撤回确认、退出清理、顺序持久化与跨实例授权有生产逻辑/临时 registry 测试。尚没有把 Riftlet、Saytile 与 LyricTile 三款最终签名应用同时启动的实际画面；这一边界不写成三应用实测。

## 歌词、网络与权利

真实服务探针使用三首中文、三首英文及四个版本/纯音乐/缺失元数据/不存在歌曲对照。报告只保留元数据、结果、耗时与 hash，不发布歌词正文。现场版和缺时长的候选列表与自动选中正确录音是不同结果；小样本不能用于宣称全曲库准确率。

真实服务返回文档后二次读取与同进程新建离线 repository 检查缓存 hash 和零新增请求。429、Retry-After、迟到结果、串行请求、重连及偏好开关撤销由注入测试覆盖；没有把这些测试称为真实断网、实际服务限流或整机睡眠唤醒。

另用 Jonathan Coulton 官方发布的 **Code Monkey** 原始 MP3 做普通应用在线链路检查：原标签、文件 SHA-256、实际 Music persistent ID、真实播放状态、全新生产缓存及原生当前句 hash 都独立读取。测试用音频和歌词只临时保存在 CI 主机，结束后清理；不随应用、官网或 Release 证据包分发。该样本仍不构成独立声学对齐或逐字误差资格。

[歌词服务审查](../../LYRIC_SERVICES.md#official-source-review-2026-11-27) 区分 LRCLIB API 接入条件与歌词内容版权。公开 API、服务授权文件和服务端 MIT 代码许可不能自动合成为所有歌词的商业展示/持久缓存授权。已比较 Musixmatch、LyricFind、看见音乐和 TME 官方路线；当前没有可直接替换且已获相应授权的匿名商业凭据，因此保留现有可关闭的 LRCLIB 与本地导入，不接入非官方私有歌词端点。没有附带第三方歌词库或把内容权利审查伪装为法律许可。
