# LyricTile 1.0.0（4）实机发行记录

2026-11-26 在 Apple M5、24 GiB 的 MacBook Air 上验证，macOS 27.0（26A428），内置 Retina 2×，SIP 开启。独立 App 已安装至当前用户的 Applications。运行时代码为 `8bc782ca2bed54e62ea3004e9e92c7706609804b`，包内记录的 `3e83b5cfaf944dd1bf51308918d96912cb7b615e` 仅追加了界面验证资料。CLT 27.0 的 SwiftUI 宏缺失，本机采用可用的 26.5 SDK 构建，安装下限为 macOS 27.0。

| 实机项目 | 结果 |
|---|---|
| Apple Music 1.7（1.7.0） | 实际授权、两首本地曲目、播放/暂停、上下曲、播放及暂停中定位、自然切歌、退出重启后重新识别。通过系统文件面板导入 LRC 后，原生面板的歌词与进度一致。另以已知元数据通过生产仓库向 LRCLIB 获取 60 句带时间戳的歌词。 |
| QQ 音乐 11.11.0（73284） | 播放本地 WAV 时，持有系统媒体会话可播放、暂停、切歌及播放中定位。暂停时禁用定位。其他应用持有会话时仍能读取 QQ 曲目，控制按条件停用。 |
| Spotify、网易云音乐 | Spotify 实际进入登录页。使用者确认没有可用会话。网易官方下载链路返回 HTTP 403。两者都缺少实际播放验收。 |
| 时钟精度 | 10 场播放、130 个独立编码的音频标记，Music 实际数字输出对生产时钟的绝对偏差 P95 为 139.2 ms。系统输出时间戳的系统误差与物理声学延迟上界未知。没有签发逐字时钟资格。 |
| 面板与桌面 | 实际验证同框悬停、退出悬停、深色模式、较大字号、首次引导、登录项开关、正常退出。Riftlet 与 Saytile 共运行时读到 10 pt 间距，退出 Riftlet 后 4 秒内重排。实际进入、退出原生全屏 Space。内置屏与临时 1920×1080 虚拟屏之间拖动、重启恢复、热拔除回退均通过。未连接物理 DELL。 |
| 包与更新 | 采用独立 bundle ID、图标、Developer ID 和专用更新密钥。App 与 DMG 公证 Accepted，装订并经 Gatekeeper 验证。打开最终 DMG、复制 App、卸载卷，再次检查签名。通过受控更新源将原样公证的构建 2 升级到 4，文件与 DMG 一致。错误签名 ZIP 在隔离验证中被拒绝。 |
| 实际逐行开销 | 在内置屏上，原实现 120.13 秒的 CPU 为 3.59% 单核。减少隐藏控件布局及重复绘制后，同一首歌 120.20 秒为 2.79%，RSS 中位/峰值 81.56/81.86 MiB。13 次读回均为播放中且显示歌词，残余 CPU 高于 1% 目标。 |

最终运行时代码的 [macOS CI](https://github.com/haohongfei2001-png/nearpane/actions/runs/45809025341) 通过 81 项原生测试（13 XCTest、68 Swift Testing，零失败、零跳过）。在已安装的构建 4 面板操作 QQ 音乐，两次暂停、两次恢复均获播放器独立状态读回。

最终包自然进入无播放器空闲状态后，预先划定十分钟窗口。41 次应用清点均无目标播放器，564 次进程采样，CPU 均值 0.61% 单核、RSS 中位/峰值 80.50/80.58 MiB。CPU 高于 0.3% 预算。随后十秒剖析中，主线程 7,638 个样本中有 7,542 个位于事件等待，出现周期性组件及播放器发现，没有观察到连续歌词绘制。[空闲测量](2026-11-26-local/idle-performance.json)

2026-11-26 19:20（北京时间）开始对用户 Applications 中的最终安装实例进行八小时连续采样。该段包含 QQ 实际交互与随后普通空闲使用，逐字模式没有计入。
