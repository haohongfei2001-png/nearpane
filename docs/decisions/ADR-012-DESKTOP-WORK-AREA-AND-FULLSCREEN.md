# ADR-012 — 预留桌面、无重叠平铺、全屏工具浮层与统一产品

**状态：ACCEPTED（产品目标）；真实系统控制仍须逐项验证**  
**日期：2026-11-09**  
**覆盖范围：** 默认窗口编排、完整/精简界面与空间占用、原生全屏生命周期、空间整行点击、跨屏目标、Native/Virtual 初始模式和整体产品交付。  
**覆盖旧约束：** 原有“窗口自由重叠及逐窗口点击预览”“桌面侧栏不管理其余应用窗口”“全屏中空间面板仍可自动出现”等冲突表述，以本决策为准。  
**保留权威：** Saytile 单文字流与三态语义、Riftlet 截图队列/附加不自动发送、ADR-010 双模式身份互斥、ADR-011 一块主驻留屏+副屏 Space-only、全部尺寸可在设置中精调。  
**执行边界：** 本轮授权文档与独立工程计划修订；不修改 Nearpane / Saytile / Riftlet 生产运行时或系统设置。

## 1. 一个产品：默认完整、设置可调

Nearpane 是**单一完整产品**，不是 Saytile、Riftlet、Spaces 三个分别收费或必须分别购买的功能包。它们作为 Nearpane 第一方能力共用统一界面，仍保留各自必要的领域状态与安全边界。独立产品代码仓库可作为开发/迁移来源，不构成用户必须单独购买的要求。

Native Spaces 与 Nearpane Virtual Workspaces 是**低频切换的内部模式**，只在独立设置中选择，主界面不增加快速模式切换器。首次使用直接进入已配置好的默认 **Native** 模式，不出现强制二选一向导。Virtual 未完成真实设备及恢复验收前不可声称可用；用户主动切换时采用 ADR-010 的 preflight、事务恢复和独立配置，不自动将两类 Workspace ID 对应起来。

## 2. 普通桌面：完整 Nearpane 占一条真实保留区域

- Nearpane **完整/顶天立地表面**在主驻留屏默认占本屏**可用桌面区域**约 1/8 宽（默认靠既有视觉权威确认的边缘，全部尺寸可以设置精调），并贯穿该区域的可用高度；菜单栏、Dock、安全区以实际系统可用几何为准。
- 其余 **7/8** 是该屏默认的可管理普通应用窗口工作区域（WorkRect）。若用户调整 Nearpane 宽度，WorkRect 相应变化，并不死守 7/8 数字。若用户选择将副屏 Space-only 面板固定为完整驻留，副屏可单独配置是否保留其实际占用区域；只有半浮层/临时按需面板不强制挤压整个副屏。
- 其他受管理的**普通顶层应用窗口**默认不得进入 Nearpane 保留区、不得超出该显示器实际 WorkRect 边界、彼此不得重叠。不能只是视觉上盖一条半透明侧栏，必须实际调整受管理窗口的 frame。
- **预留区不是更改 macOS 的 NSScreen.visibleFrame**：该属性只反映系统菜单栏、Dock 等安全可用范围。Nearpane 在权限/适配器能力允许时独立观察、移动与调整应用窗口；不向系统谎称其自动保留了空间。
- 新建、关闭、最小化、还原、用户切换 Workspace、换屏、分辨率/旋转变化时重新计算真实受管理窗口几何；必须去抖、避免重复调度/焦点抖动，必要时保留原始布局恢复日志。
- 非全屏时用户仍可主动打开精简工具浮层，但这不授权其他普通窗口侵入完整 Nearpane 的保留区；若完整表面关闭，仅显示精简浮层，则精简表面采用覆盖策略，不把浮层宽度误当成强制预留区。
- 其他 App 的模态 sheet、菜单、系统警告、Tooltip、画中画、受保护的系统界面及不可调整窗口不是普通可平铺顶层主窗口；**不强行移动、隐藏、关闭或改写它们**。系统不允许管控时必须将该对象标记为 unmanaged / degraded、提供清楚提示，而不是宣称已实现全系统绝对零重叠。

## 3. 自动平铺的默认几何

每个**显示器 × 当前模式空间**分别计算 WorkRect，只有该空间关联的**可调尺寸的普通主窗口**参与平铺。初次布局：

- **1 个窗口**：填满该显示器 WorkRect（默认约 7/8 宽，纵向占满该屏工作区域），不盖在 Nearpane 下方。
- **2 个窗口**：左右各占 WorkRect 的 1/2，间距采用已确认的默认 token，任何额外 gap 都从 WorkRect 内扣除。
- **3 个窗口**：一个窗口占 WorkRect 左 1/2；另两个窗口上下平分右 1/2。布局方向、指定主窗口、比例可以在设置里修改。
- **4 个窗口**：默认 2×2 网格；5 个及以上采用可验证的自适应平铺/分页策略，必须确保每个被纳入的主窗口最小尺寸与屏幕内边界可满足，不能通过重叠伪装成功。
- 每个 App 可配置自己的默认偏好（例如优先主窗、宽度占比、最低面积、倾向左/右列、与其他窗口同屏的优先级）。按 app bundle identity 保存，并允许显示器/模式覆盖；不为实现规则去移动不属于该 workspace 的窗口。
- 用户明确改变平铺宽度、选择窗口排列或调整模块尺寸时，按其配置生成真实窗口 frame 并重绘预览，预览不能只显示“应该这样”而实际窗口未变。只有操作完成且观察重新确认后才显示成功。
- **不可兼容的窗口最小尺寸、禁止调整大小、无法取得权限、系统全屏/安全对象或过多窗口**不允许进入“已完成自动平铺”的状态。不要偷偷跨系统 Space 移动、创造新原生 Space、缩放到不可用尺寸或隐藏用户窗口；提出明确可选处理与异常状态。真实系统不能保证任何任意组合零重叠，是已知能力边界。

同一 Space 下的平铺窗口可以来自不同 App，也可以来自同一 App 的多个文档窗；不引入“同 App 可以叠放”的默认例外。

## 4. 空间预览的操作单位是“整个空间”

- Nearpane Space 缩略图一行代表一个 Native Space 或 Virtual Workspace。**整行只有一个主要点击目标**：切换/进入该空间，**不针对单个窗口划分独立点击热区**，即使同一行画出两窗或三窗。
- 切入目标后默认保持该空间最近一次有效前台窗口及焦点，或由系统本身的真实焦点规则决定；不能随机激活半屏中的某个窗口。
- 预览严格按已完成/已验证的真实平铺后窗口 frame 绘制；布局失败或尚在重排时标记为未知/过渡，不能虚构平铺成功。
- 撤销此前要求“每个被遮挡的非主窗口在空间缩略图中保留可点击露出区域”的规则；普通主窗口默认不叠放，空间行负责切换，窗口焦点由空间内原生键盘/鼠标操作或未来另行定义的窗口操作承担。

## 5. 原生全屏、退出策略与精简浮层

- 用户进入**原生全屏**时尊重 macOS 将该窗口放入原生全屏 Space 的生命周期：全屏 App 使用整块屏幕，Nearpane **不保留 1/8、不显示完整侧栏、不显示空间调度**，不擅自替换为 7/8 的伪全屏。
- **退出全屏默认返回进入全屏前的原 Space/Workspace 和普通平铺布局**。记录源 Space、display、窗口身份和之前的受管理 frame，返回时验证身份仍可访问，恢复 WorkRect 的窗口编排；如果系统已经回到源空间则不额外切换。该体验目标不代表 macOS 允许应用任意操控原生全屏 Space。
- 设置中提供**退出后保持独立空间/单开空间**的可选行为。Native 若要求保留单独的原生 Space，只有在目标系统、权限与已验证实现均允许时才启用该选项，否则解释不支持并禁用；Virtual 可以在验证后将该窗口保留为独立逻辑 Workspace。不得对 Native 无验证承诺可创建/保留系统 Space。
- 全屏中允许用户**主动**从一个极简、低干扰、可配置的小状态条（mini status strip）打开其允许的精简功能（如 Saytile 语音板）。默认**不自动展开，不因语音检测或空间变化自动出现完整 Nearpane**；状态条本身可在设置中决定是否显示、位置与允许的功能。
- 全屏精简板是**浮层覆盖**，非 WorkRect 预留区：可拖动，记住位置，尽可能结合鼠标热点、AX 可见控件、当前窗口边界和上次手动位置进行智能避让，不遮住常用按钮/用户当前交互对象；无法可靠判定按钮归属时保守展示或允许手动移动，不宣称可以识别所有第三方 App 按钮。
- 全屏浮层同样遵循 macOS 全屏 Space、`NSWindow.CollectionBehavior` 与系统窗口层级限制；能否在第三方全屏上稳定可见必须独立验收。用户主动关闭浮层不等于停止语音采集，明确“隐藏界面 / 暂停模块 / 停止采集 / 退出”四个不同动作，隐私状态按单一领域契约执行。
- 副屏空间调度：默认**按需出现**；用户可在设置中选择固定、多目标自动，但即使用户启用自动策略，处于系统全屏/演示/游戏/安全状态时也默认抑制空间面板，除非用户对可实现的例外有明确设置并通过验收。

## 6. 跨屏工作链路与焦点连续性

- 主屏只存在一套 Saytile/Riftlet。用户在副屏发起截图、语音、拷贝、附加时，不复制完整模块，也不自动将工作焦点抢回主驻留屏。
- 每个用户发起的跨屏操作跟踪：发起 display、原前台 App/窗口、Native/Virtual Workspace 身份、目标草稿绑定、操作版本及有效期；来源与目标可能位于不同屏幕/空间。
- 操作开始后只有确认过的动作才能改变指定目标焦点；完成/取消/失败时只在目标仍有效、当前用户未主动改变工作现场的情况下恢复原焦点；不把过期窗口作为写入对象。
- Riftlet 点击附加仍不自动发送，目标不明时 fail closed；Saytile 的连续转写仅进入用户明确的流和受控复制/输入流程。
- 该链路是 Nearpane 单产品的首要端到端验收目标，而不是若干模块静态放在一起的展示。

## 7. 隐私、性能与冲突处理

- 预留区与平铺需要辅助功能等权限时按实际动作申请；撤销权限后停止写操作、明确当前是 degraded，**不把仅有浮层覆盖的状态假装成窗口已避让**。
- 并存其他窗口管理工具、Stage Manager、macOS 原生平铺/窗口缩放、全屏切换和未知前台窗口时，必须明确唯一写操作所有者，避免双方争抢 frame。
- 界面隐藏、休眠、卸载、崩溃、模式切换应可恢复 Nearpane 主动移动的窗口布局，不能遗留被放到屏外的窗口。
- 全屏工具条/浮层及窗口预览需有屏幕共享与锁屏隐私策略；未经用户选择不自动暴露文字流、图片内容或截图缓存。
- 内置模块只作为同一 Nearpane 产品的可开关功能，不因收费或设置界面将整体产品拆成多个必须购买的 SKU。

## 8. 分阶段工程准入与验收

1. **P0 文档/Mock**：更新 visual、interaction、architecture 和实施路线；用合成区域/窗口验证 1/2/3/4 窗布局、Space 整行点击、全屏转场、浮层位置与设置，不能等同真实 App 测试。
2. **P1 实机最小证明**：在获准的自建窗口中验证 WorkRect 与 frame 控制、AX 窗口识别/移动/缩放、跨显示器定位、最小窗口尺寸限制、原生全屏进入/退出与来源身份；Native/Virt 独立验证，未经批准不调整用户现有窗口或系统 Spaces 配置。
3. **P2/P4 工程对齐**：在现有 Host 代码演进，不重新发明应用或重复审计三个仓库；增加 DesktopWorkArea / ManagedWindowTiler / FullscreenTransitionCoordinator / FloatingToolSurface / CrossDisplayTargetContext 接口，以 ModeCoordinator 和 MultiDisplayPresentationCoordinator 衔接。新旧设计必须显式列出差异后才能认定工程符合最新规范。
4. **真实验收门槛**：单/双/旋转显示器、不同 Workspace、1/2/3/4/5+ 窗、同 App 多窗口、最小尺寸冲突、无权限、不可调整窗口、全屏退回/独立、手动唤出/收起/移动避让、失去焦点和崩溃恢复、屏幕共享都分别取得证据。验证“受管理普通主窗口 WorkRect 内无重叠/无出界”，不将系统弹窗纳入不可能实现的绝对承诺。

**最终产品裁决：普通桌面完整 Nearpane 占有并预留边缘区域，受管理的普通应用窗口自动使用剩余区域且不相互重叠；全屏恢复真正全屏，空间调度隐藏，用户主动调用可移动的小型工具浮层；空间缩略图只作为整体切换目标；软件作为一款完整产品交付。**
