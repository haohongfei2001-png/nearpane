# Nearpane — 产品定义与功能规格

**文档状态：** 产品定义基线（Product Definition Baseline；2026-11-09 双空间模式修订）  
**适用范围：** 产品定位、核心架构、功能边界、模块体系与关键交互原则。  
**配套规范：** [视觉权威](design/NEARPANE-VISUAL-AUTHORITY.md)；[双空间模式 ADR-010](decisions/ADR-010-DUAL-WORKSPACE-MODES.md)；[多显示器 ADR-011](decisions/ADR-011-MULTI-DISPLAY-PRESENTATION.md)；[预留桌面、平铺、全屏 ADR-012](decisions/ADR-012-DESKTOP-WORK-AREA-AND-FULLSCREEN.md)

> 本文定义 Nearpane 应该是什么、由哪些能力组成，以及各能力之间如何协作。它不代表所有功能已经实现，也不替代工程可行性验证。产品定义、视觉设计、工程实现和真实验收必须分别记录，不得混为一谈。

## 1. 一句话定义

**Nearpane 是面向 macOS 的常驻桌面交互与编排层：提供用户可选的原生 Spaces 和 Nearpane 虚拟 Workspaces 两种空间模式，忠实呈现窗口与显示器状态，并融合语音输入、截图暂存和用户自选常驻工具。**

英文定义：

> **A persistent, modular interaction layer for the Mac desktop — with user-selectable native macOS Spaces or Nearpane-managed Workspaces, faithful window views, voice, screenshots, and the tools each user chooses to keep at hand.**

Nearpane 的目标不是再增加一个孤立的窗口管理工具，而是让用户在使用任何应用时，都能以很低的切换成本理解桌面状态、取用常用能力，并直接完成桌面层面的操作。

## 2. 产品本质与三层架构

Nearpane 由三个相互协作、边界清晰的层次组成。

### 2.1 桌面空间与窗口编排层（Desktop Orchestration）

这是产品的基础层，也是 Nearpane 区别于普通工具栏、Dock 和小组件集合的核心。

- **原生 Spaces 模式（Native）：** macOS 保有 Space 身份、切换和生命周期；Nearpane 负责可视化、读取与经验证的用户操作，不另建虚拟桌面。
- **Nearpane 虚拟工作区模式（Virtual）：** Nearpane 管理逻辑 Workspace 身份、窗口归属和调度，通过可恢复的窗口操作实现切换；这些工作区不等同于 macOS Spaces，也不要求关闭系统 Spaces 或 SIP。
- 两种模式共用统一的边缘侧栏、Saytile、Riftlet、可选模块与窗口几何规范；**同一时刻只有一种 Nearpane 工作区引擎拥有窗口调度权**。
- Native 的预览基于系统实际 Space 和窗口 frame；Virtual 的预览基于明确分配的窗口和可恢复的目标可见布局，不将隐藏窗口的屏外停放坐标当作实际布局。
- 点击空间预览**整行**只执行空间切换，不拆分为逐窗口点击。普通受管理应用窗口按本屏 Nearpane 保留区之外的 WorkRect 自动平铺；真实窗口身份、frame 与权限均需确认，不虚构用户可用能力。

**模式选择是已确认的产品目标，不是现有实现证明。** 首次启动直接使用默认 Native，不弹出强制选择向导；Native/Virtual 仅是独立设置中的低频配置。Virtual 必须由用户明确启用、独立验收，并有恢复/回滚机制。模式切换不自动修改 Mission Control 设置、不关闭系统 Spaces、不关闭 SIP，也不擅自移动、关闭或删除现有窗口。主表面不提供创建/删除 macOS Spaces 的入口，Virtual 的工作区管理可在独立设置完成。

### 2.2 第一方常驻工作能力（First-party Always-on Modules）

Nearpane 将两个已经独立定义的产品能力作为一体化体验中的第一方模块，而不是重新发明一套相似功能。

#### Saytile — 连续语音输入

继承 Saytile 的产品定义与交互边界：

- 持续可见的语音文字流，用户自然讲话即可持续形成文字。
- 用户始终面对一份连续、可编辑、持续修正的文本，不需要在多个识别结果之间选择。
- 忠实记录用户表达，不擅自改写成润色稿、摘要或另一种表达。
- 提供轻量的复制与识别状态控制。
- 语音采集、识别和文本处理遵循 Saytile 自身的权限、状态与数据规则。

Nearpane 负责把 Saytile 放入统一桌面界面；Saytile 的核心识别质量、文本忠实性和状态语义不得因集成而退化。

#### Riftlet — 截图捕获与暂存

继承 Riftlet 的产品定义与交互边界：

- 捕获系统截图，并将截图送入紧凑的暂存队列。
- 通过可辨认的缩略图快速查看和取用截图。
- 保留原始截图比例与内容，不拉伸、不随意裁切。
- 延续 Riftlet 已定义的目标草稿识别、点击附加、上传状态反馈和失败恢复流程。
- 附加截图不等于发送内容；**不得未经用户明确操作自动发送**。
- 保留 Riftlet 对截图队列、历史和数据恢复的既有约束。

Nearpane 负责统一呈现和提供入口，不得为了视觉整合而破坏 Riftlet 已验证的截图生命周期与安全边界。

### 2.3 用户可配置的常驻模块（User-configurable Modules）

Nearpane 不应被限定为只有 Saytile、Riftlet 和空间预览的固定组合。它还应允许用户按自己的工作方式，选择加入其他长期放在手边的功能。

可选模块方向包括但不限于：

| 模块 | 主要用途 | 典型内容 |
|---|---|---|
| AI 助手 | 随时提问、辅助理解和处理任务 | 对话入口、上下文辅助、快捷 AI 操作 |
| 便签（Notes） | 快速记录与随手查看 | 临时想法、片段、备忘 |
| 待办（Tasks） | 管理下一步行动 | 待办事项、优先级、截止时间、完成状态 |
| 日历（Calendar） | 感知日程与时间安排 | 即将开始的事件、当天安排、日程入口 |
| 时间（Clock） | 快速掌握当前时间 | 本地时间、可选的其他时区 |
| 天气（Weather） | 快速了解环境信息 | 当前天气、温度、短期预报 |
| 后续模块 | 根据用户需求扩展 | 其他适合常驻、快速查看或轻量操作的工具 |

模块体系应遵循以下原则：

1. **由用户选择。** 用户决定添加哪些模块、启用哪些模块，以及哪些模块需要长期显示；不强迫所有人使用同一套功能组合。
2. **独立配置。** 每个模块拥有自己的设置、数据来源、权限和启停状态，不要求用户为了使用一个模块而启用其他模块。
3. **轻量常驻。** 模块优先提供一眼可读、一步可达的内容和操作，不把侧边界面变成多个完整应用窗口的堆叠。
4. **可扩展。** 新模块可以逐步加入，不应要求重写桌面空间编排层或 Saytile/Riftlet 的核心逻辑。
5. **不破坏核心能力。** 可选模块不能以挤压、遮挡或削弱当前模式的空间预览、语音输入和截图暂存为代价。
6. **配置入口与常驻界面分离。** 复杂的模块添加、授权和配置可在独立设置界面完成；主界面继续保持无标题、无 Logo、无产品名和低控制密度。

模块在侧栏中的具体排布、折叠、滚动、展开和空间分配，需要在后续交互设计中单独定义与验收。模块配置不应**自动**更改出厂视觉比例；用户则可以在独立设置中精细修改所有可视尺寸，窗口真实几何不可伪造。

**范围说明：** 用户可配置模块是产品方向；这不等于首版已经承诺公开第三方插件市场、任意代码扩展或完整插件 SDK。此类生态能力需要另行评估和决策。

## 3. 核心功能规格

### 3.1 双模式空间映射

- **Native：** 一行对应一个经确认的真实 macOS Space，点击后切换对应系统空间；不按应用、项目或工作生活类别重组原生 Spaces。
- **Virtual：** 一行对应一个 Nearpane 逻辑 Workspace，点击后调度该组的真实窗口；区分“当前实际可见状态”和“保存的目标可见布局”，不把临时屏外停放位置当作空间内容。
- 常见 2–4 行，优先保证最多 5 行清晰；超过常规行数时只缩小空间缩略视图，不压缩 Saytile/Riftlet。
- 不在主表面增加创建/删除系统 Space 或布局编辑入口。Virtual Workspaces 的管理入口位于独立设置。
- 原生 Space ID 与虚拟 Workspace ID 不可直接转换或混用；切换模式前必须确认恢复状态、受影响窗口和调度互斥。
- 系统不可观测或虚拟窗口恢复不可保证时，必须降级或禁止相应操作，不虚构状态。

### 3.2 预留桌面区域、自动平铺与真实窗口映射（ADR-012）

- **普通非全屏桌面**：完整、贯穿可用屏幕高度的主侧栏默认预留本屏约 1/8 宽度；其他受管理普通顶层应用窗口使用剩余约 7/8 的 WorkRect，界面尺寸修改后按实际侧栏边界重新计算。该保留区由 Nearpane 的实际窗口管理而非仅仅视觉覆盖实现。
- WorkRect 内的**受管理普通窗口不得相互重叠、超出本屏、侵入侧栏下方**；相同 App 的多文档窗口不例外。一个窗口填满 WorkRect；两个窗口左右平分；三个窗口为一侧独占半区，另一侧两个窗口上下平分；四窗口 2×2。应用级布局优先级、主窗口、区域比例可在设置精细调整。
- 窗口最小尺寸限制、禁止调整、系统模态/菜单/Tooltip/安全界面等不属于可强制平铺的普通主窗；动作失败必须显示 degraded/unmanaged，不能隐瞒无法满足的“零重叠”目标，也不自动创建系统 Space 或关闭窗口。
- 空间缩略预览忠实反映**实际完成并确认的平铺后**窗口 frame、比例、位置与边界；未完成或未知的窗口保持待确认，不得画出虚构的漂亮布局。
- **点击整个空间行切换该 Workspace**。单独窗口不是缩略图中的独立点击目标，不再要求每个窗口露出可点击边角；进入空间时尽可能保持该空间原有焦点。
- 全屏是单独状态，显示器恢复真正的全屏，不预留侧栏、也不显示空间调度。用户如需在全屏工作，手动从小状态条打开可移动、智能避开控件的精简工具浮层，不自动弹出。
- macOS 的 Dock、菜单栏、全屏 Space 与第三方窗口可移动能力仍需独立技术验证；所有“应该如此显示”均不构成系统已经执行成功的证据。

详见 [ADR-012](decisions/ADR-012-DESKTOP-WORK-AREA-AND-FULLSCREEN.md)。

### 3.3 多显示器角色、独立尺寸与出现策略（ADR-011）

- 用户指定唯一 Nearpane 主驻留屏（无需等于系统主显示器）。**Saytile 语音板和 Riftlet 截图板只在该屏常驻显示，全局各只有一份领域实例与数据队列**；主屏的空间调度区可独立关闭。
- 其他每块显示器至多提供一个**Space-only 空间调度面板**，不复制语音、截图或其他主面板模块；副屏不是新的 Host 实例。
- 副屏默认按需唤出，**绝不自动弹出**；用户可在设置中主动启用“多个有效可切换目标时自动出现”或“固定显示”，原生全屏/演示中默认抑制空间面板。出现规则以可验证、可操作目标为依据，不直接按 CGWindow 原始记录计数，不抢焦点。
- 主、副屏的面板宽度、高度、边缘位置、垂直位置、空间行尺寸和启停/显示策略**分别配置并保存**。主屏默认全功能形态保留 1/8 宽、工具区约 3/8、空间区约 5/8；关闭主屏空间区后允许缩短主面板高度。副屏不强制套用 1/8 或 3/8+5/8 比例。
- 各屏按照真实分辨率、旋转、镜像、可用桌面区域和坐标变换呈现真实窗口几何，不逐窗口拉伸。Native 只显示该屏经确认的系统 Spaces；Virtual 只显示该屏明确管理的逻辑 Workspaces，不能在 separateSpaces=false 时把 SkyLight 的 3+1 scope 记录当作独立用户桌面。
- 显示器拔插时保留 per-display 偏好，主驻留屏失联则只迁移主表面角色，不重建 Saytile/Riftlet 或切断已进行的任务；副屏面板隐藏不得产生持续高帧率捕获。

本决定详见 [ADR-011](decisions/ADR-011-MULTI-DISPLAY-PRESENTATION.md)，目前是产品目标，不代表已在真实 macOS 多显示器环境中完整验收。

### 3.3.1 出厂即完整，全部可视尺寸可按屏精细调整（ADR-011）

Nearpane 保留已经设定好的尺寸和视觉比例作为默认值；**所有呈现尺寸都可以在设置中修改**，包括主屏与副屏的宽高/留距、各模块高度、语音文字/按钮大小、Riftlet 缩略图、Space 行和预览容器、字号/行距、边距/间距、圆角及可选模块尺寸。支持精确数值输入、细步进、预览、逐项/模块/显示器恢复默认。主界面本身不提供尺寸调节控件。

每屏单独存储配置；用户只改一项不应影响其他自定义值。默认 1/8 和 3/8+5/8 是出厂 preset，非硬性限制。允许的用户调节不得破坏真实窗口/截图宽高比、正确点击区域与基本可操作性，显示不下时采用滚动/分页或给出清楚的约束说明。

### 3.4 跨模块连续工作

Nearpane 的价值来自模块之间的协同，而不仅是把它们放在同一个容器里。

典型场景：

- 用户在一个应用中工作，同时通过 Saytile 连续输入文字。
- 用户捕获当前屏幕，通过 Riftlet 暂存截图，并在确认目标草稿后逐张附加；不自动发送。
- 普通桌面下，用户不离开当前应用即可观察并切换当前模式的各个工作空间；Native 为系统 Spaces，Virtual 为 Nearpane Workspaces。原生全屏时空间调度隐藏，只有用户明确开启的状态条/精简工具允许浮层覆盖。
- 用户根据自己的工作方式加入 AI 助手、便签、待办、日历、时间或天气模块，在桌面边缘快速查看和取用。
- 用户可以组合这些能力，但不必为了使用一个模块而启动全部模块。

跨显示器操作需要记住发起屏幕、原活动窗口、工作空间和已确认的目标草稿；完成或失败时按身份与新鲜度安全归还焦点，用户主动改变前台工作时不抢回焦点。模块之间可以在用户授权和明确交互下协作，不得默认共享所有数据、音频、截图、窗口内容或账户信息。

### 3.5 原生全屏与工作空间退出策略（ADR-012）

- 全屏使用真正的 macOS 全屏 Space，不把用户限制为 7/8 的伪全屏；Nearpane 完整侧栏和空间预览默认消失。
- 用户退出全屏时，产品默认**回到进入全屏前的原 Space/Workspace**，由身份校验和系统可行性决定实际可执行路径；可在设置中选择“退出后保持独立空间”，但仅在对应 Native/Virtual 模式验证后启用。原生系统 Space 的创建/保留不保证公开 API 能够实现。
- 用户可以通过显式的小状态条打开被允许的录音等轻量浮层；浮层可拖动、记忆位置，尽可能避让当前 App 控件，不自动展开；隐藏显示不等于暂停采集。
- Native/Virtual 模式选择属于低频设置，不在日常侧栏增加切换器。Nearpane 是整体交付和购买的一款产品，不要求分别购买 Saytile/Riftlet/Spaces 模块。

## 4. 主界面与视觉边界

当前已确认的默认视觉基线如下，完整规范见 [NEARPANE-VISUAL-AUTHORITY.md](design/NEARPANE-VISUAL-AUTHORITY.md)。

- 完整 Nearpane 贴近主屏边缘，默认宽度约为屏幕可用宽度的 **1/8**，占据可用屏幕高度；默认其他受管理窗口避开该保留区域，只在剩余约 7/8 WorkRect 内排列。
- 作为持续可用的桌面边缘界面，而非普通居中应用窗口。
- 主界面不显示标题、Logo、产品名或常驻 Header。
- 当前默认结构：上方整合 Saytile 与 Riftlet，合计约占纵向可用空间的 **3/8**；下方当前模式的空间调度区约占 **5/8**；这是主屏完整组合默认布局，主屏关闭空间区后可缩短高度，副屏 Space-only 面板独立配置。
- 上方工具模块保持紧凑；空间预览是下方的主要视觉内容。
- 使用克制的 macOS 毛玻璃材质、柔和边界和阴影；强调色不能破坏截图和窗口内容的真实性。
- 不在空间预览区域增加新建空间、空间管理、逐窗点击或布局编辑等入口；布局偏好仅在独立设置里。

用户自选模块是产品的扩展能力。它们的默认展示位置、多个模块同时启用时的密度与溢出策略，必须通过独立设计决策解决；不得直接推翻上述默认视觉基线。

## 5. 产品原则

1. **真实状态与明确语义（Truthful State）：** Native 显示真实系统 Spaces，Virtual 明确显示 Nearpane 管理的 Workspaces；任何模式都不得伪造窗口身份、几何与实际/目标可见状态。
2. **常驻但不打扰（Always available, not intrusive）：** 用户无需反复打开应用或切换工作现场，就能取用常用能力。
3. **统一而不混杂（Unified, not bundled）：** 模块共享一个桌面交互层，但保留各自清晰的职责和数据边界。
4. **用户决定组合（User-defined composition）：** 用户决定哪些可选能力值得常驻，不把产品做成不可配置的固定工具集合。
5. **轻量而可扩展（Lightweight and extensible）：** 每个模块只占用与其价值相称的注意力和空间。
6. **尊重原有产品（Preserve first-party semantics）：** 集成不能削弱 Saytile 的文本忠实性，也不能破坏 Riftlet 的截图队列、附加和恢复语义。
7. **权限明确（Explicit permissions）：** 麦克风、屏幕录制、辅助功能、日历、天气位置或外部账户等权限应按模块和实际能力分别请求；不得默认进行无关采集。
8. **尊重系统与选择（Respect Native and Choice）：** Native 不修改系统 Space 身份；Virtual 不伪装成原生 Spaces、不要求禁用系统 Spaces；两种引擎不同时争夺同一窗口调度权。

## 6. 明确不做什么

Nearpane 不应被实现成：

- 传统的窗口平铺/快捷键管理器，只负责把窗口排列成网格。
- macOS Dock 的换皮版本或单纯的应用启动器。
- 强制所有用户使用单一工作区模式，或把 Nearpane Workspaces 伪装成真实 macOS Spaces。
- 只能浏览、不能对应窗口真实身份与当前模式空间状态的静态桌面缩略图。
- 把 Saytile、Riftlet、日历、便签等简单堆在一起、缺少统一空间与交互逻辑的小工具集合。
- 强制用户使用固定的一组小组件，或默认收集用户所有桌面内容的监控面板。
- 一个以大面积聊天界面为主体的 AI 助手应用。

## 7. 产品能力与工程状态的区分

本文件描述目标产品和应有行为，不构成实现完成证明。

后续项目状态必须分别标记：

- **Designed：** 产品定义和交互设计已经明确。
- **Implemented：** 对应功能已经进入工程实现。
- **Validated：** 已在真实 macOS 环境和真实使用场景中完成验证。

尤其需要按模式分别验证（不可把一个模式的 PASS 当作另一个模式通过）：

- Native：Space inventory、窗口 membership、跨屏关系、系统切换及私有接口兼容性。
- Virtual：窗口归组/停放/恢复、崩溃或强退恢复、显示器拔插、全屏限制、权限撤销及其他窗口管理工具冲突。

- macOS 对 Spaces、窗口 frame、窗口层级和多显示器状态的可访问范围。
- 屏幕录制、辅助功能、麦克风及其他系统权限的申请和用户体验。
- 跨 Space 切换、窗口激活和多显示器场景中的真实系统行为。
- 多模块同时常驻时的性能、内存、能耗和布局稳定性。
- 可选模块的数据权限、账户连接、刷新策略和失败恢复。

不得把产品愿景、静态原型、API 理论可行性或单项测试描述为完整产品已交付。
