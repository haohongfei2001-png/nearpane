# R3 → R4 · 设计复核与改动理由

2026-11-18（北京时间）。此页记录设计判断及其取舍；实际静态检查结果见 [VALIDATION](VALIDATION.md)，原生能力状态见 `engineering/native-spaces/STATUS.md`。

## 判断

R3 已建立合适的结构：无标题的窄侧栏、上方工具、下方单列真实窗口、背景与前景分离。问题集中在表面边界偏平、选中框偏重、独立窗口密度不足，以及新增工具的状态多停留在文字说明。R4 在这些具体位置完善，没有重建产品形态或增加主界面功能层级。

原图的优点是柔和连续的玻璃边界、内容优先和安静的操作区。原图中的壁纸环境色不等于产品自身必须染成紫色；R4 继续用中性表面接纳环境色，同时保持正文底板的遮蔽。

## 具体改动

| 项目 | R3 观察 | R4 决定 | 为什么值得改 |
| --- | --- | --- | --- |
| 表面结构 | 外壳26 pt、内卡18 pt、内距12 pt的圆角关系不完全一致 | 外壳28 pt、内卡16 pt、内距12 pt；细边与轻微表面深度 | 内外转角同心，保留玻璃感而不加装饰 |
| 选中反馈 | 1.5 pt深灰围框比轻质工具卡更抢眼 | 选中轮廓0.75 pt，键盘焦点独立区分 | 对象状态仍明确，窗口内容回到视觉前景 |
| 浅色透明度 | 内容底板比外壳更白，方向成立 | 保留默认0.58/0.88 | 避免无依据换数值；将工作重点放在合成和真实光学 |
| 深色透明度 | 复用浅色覆盖率，深色层次缺少独立定义 | `#24272B`/0.72外壳、`#202226`/0.94内卡 | 在明亮或复杂背景上保持深色正文底板稳定 |
| 独立窗口密度 | 全宽等比预览在近方形窗口上占高较多 | 可用图宽×0.50的图槽上限，18 pt徽标尾部、11 pt行距 | 更快扫到更多窗口，仍保留完整源图及真实比例 |
| 窗口内容一致性 | 部分场景按目标尺寸构造窗口，可能形成“像同一窗口但内容重排” | 桌面和预览复用不可变窗口源；组合统一变换 | 让图稿本身遵守将交给实现者的几何规则 |
| 宽度比较 | 窄款同时缩成一行托盘，混合宽度与容量两个变量 | 所有宽度使用同样内容及托盘高度 | 比较结论可归因于宽度，不以少展示内容美化窄款 |
| 使用构图 | 四窗完全均分适合校验，但不足以代表自然工作场景 | 保留四窗图，新增不同比例和重叠的自然桌面 | 既检验规则，也能判断产品在真实工作关系中的气质 |
| 新功能 | 托盘、计算、翻译等尚缺完整视觉状态 | 增加图10–13，与背景压力和密度对照图配套 | 开发不再凭描述自行发明另一套表面和交互 |
| 原生基线 | R3依据5.19及原生专项计划 | 同步 `c5e0533` 的5.20进展 | 保留已经通过的同桌面能力，避免设计交接回退代码 |

## 密度的收益与代价

独立窗口密度是本轮最需要明确说明的取舍。在240 pt侧栏中，卡内图宽约208 pt，预览槽最大高104 pt。近方形窗口会缩得比R3更小，并在左右留白；高窄窗口的内容也不适合直接阅读。它们依然是用来识别和到达窗口的缩略图，不能宣称与完整画面等同可读。

图15使用同样宽度和内容比较两种密度。默认选择较紧凑的R4，但保留现有独立设置中的行密度调节，不在主表面新增开关。不同屏高、三个工具、更多窗口时允许滚动，不强制凑齐四个可见窗口。

组合和Space卡仍按WorkRect或全屏画布比例呈现，不能为了密度把两个实际窗口各自拉宽。真实图像、几何和命中对象要保持一致。

## 保留的产品约束

- 文字、图标和窗口图像不透明；透明调节只改背景。
- 两/三个工具都从顶部按实际高度占位，调度列表紧接其后。
- 独立窗口按稳定打开序列；关窗补位，聚焦不触发最近使用排序。
- 同桌面、相邻、重叠、自动平铺都不自动产生明确组合。
- 点击到达或聚焦，不附带恢复或重新平铺；真实迁移仍需系统确认。
- 截图附加、不自动发送、失败恢复、语音连续正文和文件数据寿命不因视觉改变。
- 计算归备忘；翻译在原词附近；待办可选；文件空入口用途延期。

## 证据边界

R4是完整设计参考，不是本轮原生实现。5.20已有同桌面窗口卡、受权面板四窗画面、隔离最终安装实例的双窗自动平铺与恢复证据；完整跨Space能力仍有未覆盖项。R4没有重跑这些原生场景，也没有进行AppKit最终光学校准。后续实施应保留现有证据，针对改动补回归，并按最终安装身份提交新增结果。
