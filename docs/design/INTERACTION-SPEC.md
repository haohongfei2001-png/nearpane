# Nearpane — 完整交互模型与主表面行为规格

**状态：交互设计基线 · 0.1 · 2026-11-08**  
**范围：桌面边缘主表面、Saytile、Riftlet、Native Spaces / Virtual Workspaces、可选模块与异常状态。**  
**权威：PRODUCT_DEFINITION.md 与 NEARPANE-VISUAL-AUTHORITY.md 优先于本文件的示意性描述。**

## 1. 交互总原则

Nearpane 应该像桌面边缘自然存在的一部分，而不是一个需要用户持续管理的控制中心。

- 默认常驻、低干扰、低认知负担。
- 不使用标题、Logo、产品名或顶部导航。
- 不以鼠标悬停、动画或自动弹出打断用户。
- 所有状态变化有明确因果；不自动发送、不自动切换、不擅自读取跨模块内容。
- 核心区域默认尺寸稳定，不因 Space 数量变化自动压缩；用户可在设置中精细改变任意尺寸，可选模块展开不得扭曲真实窗口几何。
- 空间预览既是状态表达，也是可操作映射；显示位置与点击目标必须一致。

## 2. 主表面结构

主表面贴近用户指定的显示器边缘，完整形态默认占可用屏宽约 1/8、贯穿可用高度，使用 macOS 玻璃材质且没有 header。完整主表面是 **WorkRect 的真实保留区**，其他普通受管理窗口默认只使用剩余约 7/8；不能只把侧栏覆盖到应用窗口上。

默认垂直结构：
1. 上部核心工具区（约 3/8）：Saytile 与 Riftlet，维持各自尺寸和既有交互。
2. 下部空间编排区（约 5/8）：逐行呈现当前模式的 Native Spaces 或 Nearpane Workspaces，以经确认的窗口几何作为缩略预览。
3. 用户模块区：以紧凑状态入口存在于模块控制层；完整内容通过覆盖式展开表面出现，不侵占固定的核心比例。模块数量超过紧凑入口容量时，模块入口可滚动/分页，Spaces 不被压缩。

上述比例是**出厂默认**而非用户无法修改的锁定值；系统不会因模块数量变化自动改写，但用户可以在设置中独立调整全部布局尺寸。

## 3. 显示、隐藏与边缘召回

- 用户可以在设置中选择主表面固定位置（显示器、左/右边缘、垂直位置）。
- 首次默认位置遵从已确认的视觉设计，不在运行时自行跳屏。
- 表面隐藏/召回由明确的用户设置和系统允许的交互触发；不与 macOS Dock 热区争抢。
- 显示器拔除时，Nearpane 将表面迁移到仍可用的主显示器，并保留用户配置；不在消失的显示器上留下不可访问窗口。
- 屏幕分辨率、缩放、方向变化后重新计算安全区域，避免覆盖菜单栏、Dock 或系统交互区。
- 只有一份全功能主表面与 Saytile/Riftlet 域实例；副屏允许额外 Space-only 呈现窗口，但不是第二个 Host 或第二套工作区引擎。

### 3.1 主驻留屏与副屏独立交互（ADR-011）

- 用户在独立设置中选择一块主驻留显示器，**不必是系统主显示器**。主屏常驻 Saytile 与 Riftlet，可独立打开或关闭主屏空间调度区；关闭空间区时主面板高度可收缩。
- 每块副屏只显示空间调度，不显示 Saytile/Riftlet、AI、便签或其他主屏模块。
- 每屏单独设置面板宽度、高度、左右边缘、纵向位置、空间行密度、启停、动效和透明度；副屏无须套用主屏尺寸和 3/8+5/8 分配。
- 副屏 **On-demand（默认）**：用户在该屏明确唤出才出现。**Contextual Auto（可选）**：该屏至少两个可确认且有意义的可切换窗口目标，或至少两个可确认工作区时出现，减少后延迟收起；必须过滤系统临时窗口、Nearpane 自身窗口与无效目标，防止抖动。**Pinned（可选）**：持续显示。
- 副屏按需唤出不应抢当前 App 焦点、破坏全屏演示或劫持 Mission Control 系统快捷键/热角；任何自动出现行为必须由用户在设置中主动启用，全屏/演示默认强制抑制空间调度；未通过真实 OS 验收的行为应降级或关闭。
- 任何 Space/Workspace 行必须属于该屏实际可确认的空间关系。Native 独立 Spaces 关闭时不能把 3+1 私有 scope 记录直接表现为 3+1 个可独立切换的桌面；Virtual 只展示其对应显示器的逻辑 Workspace。
- 主屏拔除时迁移唯一全功能表面，保持录音、截图队列不变，保留每屏配置；副屏拔除时撤销 Space-only 窗口，重连后恢复原来独立设置。

### 3.2 精细尺寸设置交互

- 设置内按照显示器 → 主/副屏面板 → 模块 → 内部元素，逐级提供**所有视觉尺寸**的精确输入、可选滑杆与细步进微调；默认加载视觉规范已经确认的值，不要求用户首次使用进行配置。
- 可调面板宽高、边缘与纵向留距、Saytile/Riftlet/Spaces 高度、字级与行距、按钮/图标、微图/预览显示框、空间行高/间距、内外边距/圆角、可选模块尺寸。主要使用逻辑 pt，允许基于显示器可用宽高的相对比例并显示清晰单位。
- 改动提供预览、应用/取消及逐项/模块/显示器恢复默认；每屏独立保存。修改一个尺寸不得静默改写其他尺寸，超出安全显示范围需明确提示并提供滚动或分页。
- 调整的是 UI 尺寸而非实际窗口几何：空间窗口只统一等比缩放，Riftlet 图片仍使用 Fit，点击热区与实际内容对应。独立设置之外不显示缩放把手或尺寸按钮。

### 3.3 普通桌面的保留区与自动平铺（ADR-012）

- 非全屏时，完整 Nearpane 在主驻留屏占一条贯穿可用高度的边缘预留区。其余受管理的普通主窗口必须在扣除预留区后的 **WorkRect** 中真实移动/缩放，默认约 7/8 屏幕宽；侧栏调整尺寸则重新计算，未经权限或写操作验收不得宣称已预留成功。
- 对 WorkRect 内的普通可调整窗口自动平铺：一窗占满；两窗左右各半；三窗一个占半区、另两个上下平分另一半；四窗 2×2。应用级尺寸/优先区/间距由设置管理，不允许同 App 多普通主窗叠放。
- 不允许受管理窗口相互重叠、越过本屏边界或藏在完整 Nearpane 之下。系统级对话框、菜单、受保护/不可缩放窗口作为明确不可强控例外；处理不了要提示并保留可访问性，不能误报布局成功。
- 用户在普通桌面使用只包含录音等功能的**精简浮层**时，浮层采用覆盖+可移动策略；不因此允许普通主窗口侵入完整 Nearpane 仍占有的边界。完整面板关闭后可释放保留区，经确认再重新布局。
- 原始工作区 frame、用户自定义布局和撤销恢复信息须可恢复。新窗、关窗、最小化、换屏、调边栏尺寸时禁止抢焦点或反复跳动。

### 3.4 真正全屏、手动状态条与可移动浮层（ADR-012）

- 全屏 App 使用系统原生全屏 Space、整块显示器；不在其下方强行保留 1/8，也不显示主、副屏空间调度条。用户默认不会被自动出现的 Nearpane 面板打断。
- 用户若允许在全屏使用工具，可自行在设置中启用一个**小状态条**作为显式入口；点击它后只展开用户允许的精简能力（例如录音板），并不是展开完整 Nearpane。不会在用户开始说话或鼠标经过时自动浮出录音全文。
- 浮层可移动、记住每块屏幕及全屏 App 情境中的位置。智能避让优先于遮挡正在使用的按钮；可以借助 AX 可确认的控件矩形/指针区域/系统安全区，自检失败时保持用户可手动移动，不能假称所有按钮都能识别。
- 默认退出全屏回到**进入全屏时所属原 Space/Workspace**，恢复平铺 WorkRect；可在设置中选择“退出全屏保留独立空间”，但 Native 模式必须验证系统是否允许相应 Space 生命周期操作。不能为了实现该选项私自创建系统 Space。
- 隐藏工具界面 ≠ 暂停录音 ≠ 停止采集 ≠ 退出。录音状态由 Saytile 一份领域状态管理；用户隐私暂停则必须停止相应采集。

## 4. Saytile 交互

### 4.1 状态

- **Paused**：初始未启用或用户明确暂停；使用暂停态的按钮视觉。
- **Ready**：已启用、待命，等待用户讲话。
- **Listening**：正在识别；状态按钮中的竖条声波根据真实音频能量变化。

主状态严格只有以上三种。权限、网络或识别管线故障作为独立诊断/恢复提示，不新增第四种主状态。

用户说完后回到 Ready，而不是 Paused。Paused 与 Ready 必须在按钮形态和可操作语义上清晰区分。Nearpane 不重新定义 Saytile 状态机，只映射状态和命令。

### 4.2 用户动作

- 点击状态按钮：Paused → Ready；Ready → Paused；Listening 结束后自然回到 Ready，用户主动暂停才进入 Paused。
- 点击复制：复制当前唯一正式 transcript。
- 文本流可在 Nearpane 内有限滚动和选择；不因新片段到来强制把用户正在阅读的位置拉回底部。
- 用户编辑文本时，系统修订不能覆盖用户已明确编辑的内容。
- 识别失败保留已有文本，显示轻量错误状态，允许恢复；不得清空或静默丢弃。
- AI Assistant 不自动订阅语音流；用户明确选择文本后才可作为上下文。

## 5. Riftlet 交互

- 新截图按 Riftlet 队列顺序进入托盘；缩略图尺寸、原比例和队列语义由 Riftlet 正式规范决定。
- 点击缩略图执行既定的附加/选择动作，不重新设计成拖放工作流。
- 当前目标草稿必须可确认；目标变化时，未完成操作要明确提示，不能把截图附加到未知目标。
- 附加成功后截图从待附加队列消失或按 Riftlet 规则更新；已附加内容不能被清空队列操作删除。
- 上传/附加失败保留截图与恢复入口，不通过假成功动画掩盖错误。
- 捕获入口与截图占位的相对位置、队列数量、滚动和展开遵从 Riftlet 的冻结规格。

Nearpane 不应重新实现 Riftlet 的截图采集和附件上传；交互只通过 Riftlet domain contract 发出。

## 6. 双空间模式、工作区与窗口预览交互

### 6.1 空间行作为整体点击目标

- 每一行对应当前模式下一个经确认的 Native Space 或 Virtual Workspace。缩略图可以准确展示多个平铺窗口，但**整行是唯一的空间切换点击热区**，不因点在左窗、右窗或空白处而执行不同操作。
- Native Space 切换仍由系统执行，Virtual Workspace 切换由经过恢复验收的窗口调度引擎执行。行身份、revision、权限或能力不明时禁用动作。
- 切换后保持空间最近一个有效前台窗口/当前应用焦点；不因鼠标点击某个缩略窗形状就激活另一个实际 App。

### 6.2 普通窗口平铺与不可管理窗口

- 受管理普通主窗口根据 WorkRect 无重叠平铺。一个窗口填满工作区、两个左右各半、三个一个半区另两个上下、四个 2×2；同一 App 的多窗口同样适用。App 定制规则只能改变**真实 frame**，不能只是缩略图视觉顺序。
- 原生全屏窗口、模态对话框、菜单、受保护 App、不可调整/不符合最小尺寸约束的窗口，需要独立标识能力，不进入“全部已平铺”验收统计。系统不支持时不强制移动或隐藏它们。
- 真实的窗口框架、WorkRect 边界与显示器安全区以同一坐标变换供渲染；窗口操作失败时展示 stale/degraded，不把期望的理想矩形当成实际完成结果。

### 6.3 几何真实性

- 统一缩放整个 Space，不对单个窗口分别 fit。
- 对受管理的普通主窗保留真实平铺后的宽高比、位置、间距和 WorkRect；不可控系统弹窗等例外仍按实际状态呈现，不为了美观伪造它们的 frame。
- 完整侧栏占据的边缘区域必须真实避让；未管理窗口或无法满足最小大小时保留真实桌面状态并明确标记。
- 真实三分屏、非对称布局和高度占满的窄窗口都必须按实际尺寸表达。
- 预览只简化窗口内部细节，不改变窗口几何。

### 6.4 模式选择与切换安全

- 独立设置包含**低频**“空间模式”：原生 Spaces / Nearpane Workspaces。首次使用按默认 Native 进入，不强制弹出二选一屏幕；主侧栏不新增标题、快速模式开关或创建系统 Space 按钮。
- 默认原生模式；Virtual 只能在已通过功能与异常恢复验收并得到用户明确确认后启用，未达到要求时设置中标记不可用。
- 选择另一模式时先执行 preflight：当前录音与截图任务状态、窗口归属/控制权限、第三方窗口管理器冲突、恢复日志与显示器配置。
- 未经用户明确同意不隐藏/移动现有窗口；模式切换过程中不可同时运行两套写操作引擎。
- 返回原生模式、退出 Nearpane、系统异常后必须恢复 Virtual 曾移动/隐藏的窗口；无法完整恢复则明确提示并保留修复入口，不宣称成功。
- 不自动更改 Mission Control 设置，不关闭 SIP 或 macOS Spaces，不自动关闭应用，也不影响 Saytile/Riftlet 既有状态和数据。

### 6.5 跨屏目标和焦点连续性（ADR-012）

- 用户从主屏或副屏发起 Saytile/Riftlet 操作时保留原前台 App、目标窗口、显示器/Workspace 身份与快照版本。录音或截图界面只有一份，但目标可在任意屏。
- 截图暂存后仍由用户确认附加目标；附加不等于发送。若目标窗身份变更、用户切换了实际工作窗口、窗口进入其他 Workspace，则不得恢复已过期焦点或向错误草稿附加。
- 用户主动完成、取消或失败后，在原目标仍有效且用户没有自行换工作现场的条件下恢复原焦点。不要为了操作侧栏而无理由激活 Nearpane。
- 模式切换不是高频动作，必须保留两套配置与原空间/窗口恢复日志，不能把 Native/Virtual 做成随手快速切换按钮。

## 7. 可选模块交互

模块入口不使用常驻标题。用户在独立设置中添加模块，主表面只展示用户固定的紧凑状态入口。

### 7.1 展开行为

- 点击入口打开模块 Expanded Surface。
- 展开层覆盖部分 Space 预览区域，不改变下层窗口布局数据或缩略图比例。
- 关闭后恢复之前的空间列表滚动位置、当前选中 Space 和窗口状态。
- 用户在展开层内编辑时，Space 事件仍可后台更新，但不应强行切换视图。
- 语音 Listening 时打开模块不得抢夺麦克风或输入焦点；需要键盘输入的模块只有用户明确点击输入区域后才获得焦点。
- 多模块同时展开只允许一个主 Expanded Surface；模块间切换需保留未保存状态或明确提示。

### 7.2 模块典型动作

- AI Assistant：打开空白对话；用户明确附加文本/截图；AI 生成的任务或外部操作先作为草稿。
- Notes：点击入口直接新建或打开最近便签；自动保存显示保存状态。
- Tasks：显示下一项任务；完成操作立即反馈并可撤销。
- Calendar：显示下一场事件；点击进入当天/近期日程；只读优先。
- Clock：紧凑显示本地时间；展开管理额外时区。
- Weather：紧凑显示城市与温度；展开查看短期预报；手动城市优先。

## 8. 交互状态与恢复

| 场景 | 主表面行为 | 禁止行为 |
|---|---|---|
| 当前模式空间数据新鲜 | 正常显示、可按能力操作 | 使用旧快照执行切换 |
| Native 切换或 Virtual 调度正在过渡 | 保持最后稳定快照，标记短暂更新 | 反复闪烁、重复触发 |
| 私有适配器失败 | 降级到可确认能力 | 崩溃或伪造 Space |
| WorkRect 平铺无法执行 | 明确 degraded/unmanaged，保留真实可访问窗口 | 画出虚假已平铺预览或强制改动系统弹窗 |
| 进入原生全屏 | 释放整屏工作区预留、隐藏完整空间调度；用户可选状态条 | 默认自动展开浮层或把全屏限制成 7/8 |
| 退出原生全屏 | 默认核对并返回来源 Space、恢复普通平铺；可选独立空间需能力验证 | 盲目新建/保留系统 Space 或误激活窗口 |
| 麦克风权限撤销 | Saytile 保留当前文本并显示独立权限提示，主状态仍按三态语义呈现 | 影响截图/Spaces |
| 截图目录失效 | Riftlet 显示恢复入口 | 清空队列或假成功 |
| 日历账户离线 | Calendar 显示最近更新时间 | 把缓存冒充实时 |
| 单个模块崩溃 | 隔离并允许重启 | 关闭 Nearpane 全部功能 |
| 显示器拔除 | 迁移主表面并重新映射 | 遗失用户位置偏好 |
| Nearpane 重启 | 恢复用户配置；Virtual 按恢复日志恢复曾移动/隐藏的窗口 | 复用旧系统 Space ID 或遗失虚拟窗口 |

## 9. 动效原则

- 动效解释空间关系和状态变化，不装饰性循环。
- 主表面召回/隐藏轻量、短促、可中断。
- 模块展开使用稳定锚点和柔和过渡；不得让窗口预览在展开中被重新缩放。
- Space 切换由 macOS 系统动画主导，Nearpane 不叠加假切屏动画。
- Listening 的声波竖条由真实音频状态驱动，不播放伪造波形。
- 错误、权限或降级状态不使用令人误解的成功动画。

## 10. 验收场景

- [ ] 主表面无标题、Logo、产品名和 Header。
- [ ] 主屏全功能默认宽约本屏 1/8 且保留核心纵向比例；主屏关闭空间区可缩短，副屏面板宽高独立。
- [ ] Saytile 与 Riftlet 的原有状态和数据生命周期保持不变。
- [ ] 说话结束回到 Ready，不进入 Paused。
- [ ] 截图附加不等于发送，队列清空不删除已附加文件。
- [ ] 每行对应一个当前模式下的 Space/Workspace；Native/Virtual 身份不混用，未知映射不伪造。
- [ ] Virtual 从强退、切换模式、权限撤销、显示器变化后安全恢复曾调度窗口；无法恢复时明确阻断并给出修复状态。
- [ ] 一/二/三/四窗口按真实 WorkRect 平铺；两个左右各半、三个一个半区另两个上下、四个 2×2；同 App 普通主窗不重叠。
- [ ] 每个空间预览行全域只用于切换整体 Space/Workspace，不再执行逐窗点击；能力和快照身份过期时禁用。
- [ ] 用户模块展开不压缩真实窗口预览几何。
- [ ] 任一模块失败不影响其他模块。
- [ ] 权限按模块独立请求与撤销。
