# Revision 02 · 内容优先的交互修订

日期：2026-11-17（用户对话日期）

状态：用户约束已记录；补全方案为 Designed / Recommended。没有新的原生实现或实机验证；没有新的高保真视觉验收。PR #10 转为 Draft，停止按 Revision 01 视觉、导航与交接指令执行。

## 0. 优先级与范围

本文件记录两轮用户纠正，优先于本目录 Revision 01 中与其冲突的产品、布局、模块、tokens、HTML、SVG、PNG 与 Codex 任务描述。保留旧文件用于追溯，不把旧图继续称为已接受方案。没有覆盖仓库外层权威规范或修改任何产品工作分支。

标记：
- U：用户明确提出的约束。
- R：本轮为消除歧义作出的推荐补全，尚需新交互原型验证，不能冒称用户逐项批准。
- OPEN：用户明确暂不决定，不能擅自实现成新功能。

本轮只修订整体减法原则、托盘、语音、计算与翻译。未重新研究第三方 API；旧平台研究只能作为有日期与证据边界的参考，不能据此宣称功能已经实现。

## 1. 恢复产品本来的视觉与行为原则

U：无标题、少按钮、透明白底。取消上一版整体紫色染色、彩色模块底、装饰性渐变、功能标题和多余状态说明。内容优先；用位置、内容形态和留白组织，不增加“截图 / 文件”标签切换栏。

U：宽度不是必须等于屏宽 1/8，允许略宽，以实际内容可读、易点选及桌面占用为准。1/8 只能是起点，不再是验收等式。不得把正文缩小来满足比例。

R：宽度以用户稳定偏好与屏幕可用区域决定，不能每来一个文件、每一段语音或每次计算就自行伸缩；不同屏幕可保留各自宽度。具体默认点数待白色原型对照，不在本轮另造“刚性最优宽度”。

U：功能应智能呈现。R：这里的智能首先指可预测的内容与状态规则，不是增加一个 AI 模式，也不是悄悄移动、改写、上传或删除用户数据。

## 2. 一个托盘，两个有方向的内容流

### 2.1 用户约束

U：无截图、无文件时只出现两个格：截图入口、文件入口。不是预留四个空框。

U：新截图从第一位置进入，旧截图与入口向后排；文件入口可以移到第三、第四位置，超过当前可见容量后隐藏。保留现有截图获取、附加、吞噬与失败恢复语义，不因混合文件重新发明一套截图流程。

U：新导入或新下载的文件出现在末端；四格形态的最新文件以第四格为位置锚，紧凑两格形态为第二格。

U：容量参考整个侧栏空间。常态最多四格，紧张时只保留最新截图与最新文件。不能因为内容更多一直加格、加行或挤掉 Spaces。

OPEN：文件入口点击后的用途，用户明确暂不决定。本轮不把它冻结为文件选择器、上传器、Finder、历史或云盘入口。设计原型可表现位置；正式版本不能交付一个无行为却伪装可用的按钮。行为定义未完成前，该入口不标完成，其余独立行为可推进。

### 2.2 推荐补全

R：必须区分“文件入口”与“实际文件缩略项”。前者可以被截图挤出可见区；存在实际文件时，最新文件不应被持续截图挤走。截图与文件同时存在时，至少各保留最新一项。

R：截图侧从前向后、文件侧从末端向前排列，各自内部顺序稳定。不用混合时间线把两类内容交错排列；不加分区标题，不加第三种彩色边框区分类别。

R：一行/两行是展示容量，不是存储容量。空态一行两格；有内容且空间允许时至多两列两行。只占用真实需要的位置，不绘制占位空格。超额记录留在各自队列或档案，不能因隐藏而删除、成功消费或改写时间。

R：普通四格模式尽量保持已有截图入口可直接操作；文件空入口首先让位。紧凑双内容模式允许两格均为内容，不为保持按钮常驻再加一行。截图动作通过既有托盘上下文操作取用，不把点击缩略图的附加动作改成截图；不得只给快捷键回退。具体入口可发现性必须纳入新原型评审。

### 2.3 推荐状态样本（位置示意，不是视觉稿）

S1 是最新截图，S2/S3 是更早截图；F1 是最新文件。C 是截图入口，F 是用途待定的文件入口。序号按左上、右上、左下、右下。空位不画格。

| 状态 | 上行 | 下行 | 说明 |
|---|---|---|---|
| 无内容 | C · F | 不存在 | 只有两个空态入口 |
| 1 张截图、空间允许 | S1 · C | F · 空位 | 文件入口后移；不绘制第四空框 |
| 2 张截图、无文件 | S1 · S2 | C · F | 文件入口到第四位仍可见；超过容量才隐藏 |
| 3 张以上截图、无文件 | S1 · S2 | S3 · C | 文件入口退场，保留截图既有主路径 |
| 1 张截图、1 个文件，空间允许 | S1 · C | F · F1 | 两个入口位于两类内容之间 |
| 多张截图、1 个文件，空间允许 | S1 · S2 | C · F1 | 隐藏文件入口与更老截图，最新文件留在末端 |
| 截图与文件均存在、空间紧张 | S1 · F1 | 不存在 | 仅保留各自最新一项，不新加格 |

这些样本用于验证空间方向。两类均有大量内容时的中间格额度、仅文件时的入口位置仍属 R，不借样本宣称完整布局已最终验收。必须满足：前端最新截图、末端最新文件、不超过四格、窄态各保留一项、截图单击语义不变。

### 2.4 不被隐藏规则破坏的行为

- 文件已成功持久保存后默认约 60 秒退出临时展示；不删除真实文件。仍可从既有档案重新取用。
- 正在导入、写入失败、尚未完成的下载，不得因超时看似“已收好”。文件下载完成与成功入库后才开始展示寿命。
- 容量隐藏与 60 秒退场是不同原因；不能每次重绘重新开始计时。截图不套用文件 TTL。
- 接收来源决定领域：系统截图仍归 Riftlet；拖入或下载的 PNG 仍可属于通用文件，不能只按扩展名误分类；同一入库事件不重复出现于两侧。
- 正在悬停、按下或拖动的项不能在手势中途换成另一项。按下时锁定对象 ID，新内容先排队，手势结束再更新布局，避免点击附加了错误文件。
- 空间不足优先减少可见旧内容，不通过减小文字、裁剪缩略图或扩张到第三行解决。保留比例、不拉伸；额外历史不加常驻角标和解释文字。

## 3. 语音：暂停单行，启用展开

U：暂停/用户关闭收音时，只留单行，不显示正文；启用后才展开为能显示文字的区域。不要给暂停状态保留两行空白、历史正文或“点击开始”等说明。

R：把用户语音里的“原书版”按上下文记为语音输入板，不把转写错误引入产品命名。

| 状态 | 推荐显示 | 行为 |
|---|---|---|
| 明确暂停收音 | 单行，主要是原有恢复控件 | 停止新音频采集；正文隐藏但不删除 |
| 已启用、等待说话 | 轻量展开，基准可容纳约两行文字 | 沿用已有待命状态，不因几秒无声反复折叠 |
| 正在识别/已有内容 | 同一连续可编辑文字流，按既有上限增长或内部滚动 | 保留真实波形与原有操作，不增加标题和工具条 |
| 暂停后重新启用 | 恢复原内容与上下文 | 不另起第二份流、不自动发送、不清空已保存录音 |
| 权限拒绝/撤销 | 精简单行，必要时就地说明可恢复动作 | 不显示“正在听”或假波形；不影响其他功能 |

R：单行化只改变当前呈现；数据寿命独立。不要把关闭显示、暂停采集、删除历史混为一谈。用户主动暂停/恢复可以触发一次布局结构更新，连续识别和短暂静音不能使 Spaces 边界抖动。暂停前存在未写完数据时只完成必要的安全落盘，不继续采集。

## 4. 计算：备忘录的能力，独立草稿的数据

U：计算不是和语音、截图、待办平级的独立模块，不设常驻计算卡片、独立开关或侧栏计算标签。平时可完全不出现。

U：备忘录中可按需计算；备忘录内部有“计算草稿”入口，作为不污染普通备忘的独立草稿本。

R：入口放在备忘录现有的轻量导航或上下文，不另添全局工具条。计算草稿与普通备忘共用编辑器组件但使用不同命名空间/类型，跨类型保存必须由用户明确执行。

R：“无限草稿本”优先解释为可不断续写、自动保存、可检索的纵向草稿，不擅自扩展为需要平移、缩放和画笔的二维无限画布。

U 延续：输入表达式并按等号临时查看结果，取消只撤去结果，原表达式完整保留。

R：普通备忘中的临时计算不自动生成另一篇普通备忘，不替换正在编辑的文字。连续大量计算在计算草稿中完成。重新计算同一表达式修订时，不因每个按键/流式更新污染历史；保留可恢复的计算记录，不要求每算一步再按一次“保存”。

## 5. 翻译：原处显示，单词本自动积累

U：译文在所查单词或选中文本附近出现；用户不必去侧栏打开“翻译模块”或把原文粘贴进另一张卡片。

U：单独的单词本自动记录用户主动查询/翻译过的内容，用户可回顾。取消上一版“默认不保存、每次再点保存”的流程；不再要求用户每次点击收藏。

R：在用户已启用划词翻译的前提下，明确选中并发起的查询触发译文。不要把“自动记录”解释为后台扫描整屏、鼠标经过任意文字就保存，或所有正常复制都上传。

R：同一查询的流式片段不各存一条；一次成功结果对应一个查询记录。再次查相同词可以合并展示为同一词条，但保留每次查询时间与语境/义项，不能在去重时丢掉新的上下文。短语与句子也可作为条目保存，不因为名称叫单词本就截成单个词。

R：词条至少保留原文、译文、语言、查询时间、实际可得且被允许的来源、可选备注；原文/译文不混入普通备忘。原地翻译提供主结果，详细释义和回顾进入已有主窗口的单词本，不增加常驻侧栏卡片。

R：浮层避让原词、光标、选区及屏幕边缘。被动显示时不主动抢键盘焦点；用户明确与浮层交互时才获得必要焦点。未知目标位置不冒充“精准原地”，给轻量明确的近处回退或不弹出；跨应用选区/几何/权限尚未经过本轮原生验证。

R：请求失败保留原文，不写入伪造译文；输入仍被用户修改时不先占据词条。用户显式不记录、暂停记录或删除记录可生效。安全输入/明确排除场景不旁路采集；云翻译需用户已选择服务与发送边界。本轮不增加冗长首次设置流程。

## 6. 与 Revision 01 的冲突清单

| 旧方案 | 处理 |
|---|---|
| 紫色主题、紫色表面与装饰渐变 | 设计被用户否定；停止作为视觉目标 |
| 1/8 严格几何验收 | 撤销；改为宽度参考、可读性与用户偏好 |
| 便笺/计算/待办/语言四个平级标签 | 撤销计算与语言的平级常驻入口；待办本轮不重新定义 |
| 截图/文件切页展示 | 替换为同一托盘双向内容流，不加文字标签切换 |
| 暂停仍展示语音正文 | 替换为单行收起，历史不删除 |
| 翻译回侧栏编辑后手动保存 | 替换为原处翻译，主动查询成功后自动记入独立单词本 |
| 泛化的内容出现触发布局增长 | 以两/四格容量和旧内容隐藏吸收变化；不无限增高 |

保留：既有截图附加/失败恢复/不自动发送、语音数据完整性、Spaces 真实能力门槛、统一档案与设置、独立领域、文件实际持久保存、第三方能力不伪造、当前工作分支与用户数据不受本轮修改。

## 7. Codex 修订入口与验收

先读本文件与 README，再读旧任务单。不得按旧交接指令直接照搬旧 HTML、SVG、PNG、紫色 tokens 或四标签导航。开发工作分支不应仅因设计 PR 变 Draft 而停止不冲突的修复；停止的是已被否定的呈现方案。

下一轮设计/原型工作（本轮未完成）：
1. 先做透明白底、无标题的托盘空态/单截图/多截图/双内容/窄态/超额隐藏状态；展示明确的可见物与隐藏物，不再做宣传画替代交互检查。
2. 补语音暂停单行、启用展开与短时静音稳定状态；验证与托盘共享空间不会抖动或误点。
3. 将计算收回备忘录内部，提供独立草稿；把翻译移到文本附近并自动记入单词本。
4. 只对必要的空间容量与控件出现规则做交互验证，再制作完整高保真视觉。尚未决定的文件入口行为不得虚构为完成。

最低验收样本：
- 空态没有四个空框；没有“截图/文件/计算器”常驻标题或新增标签栏；默认无紫色染色。
- 连续截图从首端进入；文件入口可移出但最新实际文件被保护；当前可见容量不超过四格。
- 两格混合态只显示最新截图与最新文件；更老记录仍可恢复，未被误记为已消费。
- 按下/拖动期间到来新内容不会把点击对象偷换；60 秒退出展示不删文件，截图不套此 TTL。
- 语音暂停后单行无正文，恢复不丢内容；没有声响不等于主动暂停。
- 普通备忘与计算草稿互不污染；取消结果原表达式完全不变。
- 成功主动翻译无需再点保存即可进入单词本；重复查词语境不丢，普通划过、失败请求和流式片段不制造垃圾记录。
- 新原型与原生能力分别标 Designed / Implemented / Validated，不使用 Revision 01 的检查通过来证明 Revision 02。

本轮交付仅为修订决策和执行优先级；未宣称新图、新原型、原生功能或实机验收已经完成。
