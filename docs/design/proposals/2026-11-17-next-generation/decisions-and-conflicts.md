# 05 · 替代决策与重大冲突

本文件把下一代设计与旧规则的关系写明。**不原地修改旧权威文件。** 本次用户已授权完整产品设计研究与对固定比例等决定提出替代，因此以下为设计负责人的推荐裁决，足以启动隔离实现；不等于已发布或已获得所有系统权限。

## 权威关系

审查不能只看main。原生分支的视觉V2、ADR-010—013、P5.12/P5.13状态，晚于main旧产品定义；未合并PR仍是候选，不能按编号决定权威。实施时以本目录列出的**具体替代条款**取代对应旧布局决定；其它条款继续生效。产品定义、设计、实现、验证分别记账。

## 决策登记

| 决策 | 原规则或现状 | 推荐方案及理由 | 保留的替代方案 / 取舍 |
|---|---|---|---|
| ADR-NG-01 自适应布局 | 默认上3/8、下5/8；工具不随空间数量自动缩小 | 使用模块footprint、空间行需求、可读下限与稳定预算；工具和空间独立滚动。适应新模块及不同Space数量 | 旧布局作为已有用户的legacyManual保留。代价是布局算法与结构变化时机更复杂，必须以纯函数和场景验证约束 |
| ADR-NG-02 直接分区调整 | V2要求所有尺寸在独立设置调整，主界面无拖动把手 | 分区细缝悬停/聚焦才出现可拖柄；双击恢复自动，精细参数仍在高级设置。减少为简单调整离开工作现场 | 若真实用户误触高，可仅菜单/设置调整；原型阶段先采用低可见分隔与最小命中安全区 |
| ADR-NG-03 工作页替代覆盖式扩展 | 可选模块横向rail位于Spaces底部，展开覆盖空间 | 工作页统一外壳、独立数据，一次一个主要编辑页；在上方展开或进入既有主窗口。空间入口不被盖住 | 可固定短摘要增加一眼可见信息，但不允许每个模块都独占完整大卡片 |
| ADR-NG-04 三圆角区域的含义 | V2固定语音/截图/空间三段 | 延续外实内透、同心圆角、紫色控件；把三层视觉理解为外壳/工作表面/空间表面，工具内部用细分隔 | 保留核心三段的兼容布局；新默认降低卡片数量，代价是工具组内部边界需更清楚 |
| ADR-NG-05 配置的层次 | 已实现全部尺寸精调，用户值丰富 | 常规设置五组，精确数值移到高级并完整保留。未有显式覆盖才能自动迁移；不能根据相同数值判断默认 | 不删除高级能力，不重置透明度或副屏值；主界面克制不等于禁止深度配置 |
| ADR-NG-06 文件永久收纳 | 截图专属托盘；用户希望任意文件永久集中并可改变位置 | 独立FileStore，默认复制真实字节，允许显式选择“移入”；60秒只影响ShelfEntry，浏览器可直接下载到Inbox | 默认直接移入更接近单一位置，但首次拖动惊讶和源丢失风险高。本轮推荐复制+可选移动；这是一项产品取舍，实施时不得偷偷改为仅保存路径 |
| ADR-NG-07 系统待办权威 | 本地Tasks样例，没有真正提醒事项连接 | 本地Tasks与EventKit来源并列，系统记录由系统权威管理；Siri/App Intents进入同一命令服务 | 首期只本地会更快，但无法满足系统协作目标；因此EventKit进入正式后续阶段，权限拒绝时本地仍有完整价值 |
| ADR-NG-08 有限目标插入 | 已有Saytile手动插入源码，但只接受严格目标证据；真实目标尚未广泛验证 | 抽取目标验证低层服务，剪贴板/翻译分别定义动作；支持清单逐App验收，失效后明确复制 | 模拟快捷键可扩大表面覆盖，却不能可靠证明目标与完成；不作为默认路线。该限制属于诚实能力边界，不把用户需求降格为只做复制 |
| ADR-NG-09 本地翻译优先 | 无产品级翻译领域 | Apple Translation默认；云provider显式选择；语言笔记独立保存 | 云优先可能有更好特定术语质量，但有网络、费用、隐私与配置成本。质量测试可以调整推荐，绝不暗中切换 |
| ADR-NG-10 媒体按能力显示 | 尚无音乐/播客模块 | 元信息/控制/进度/歌词/章节分别声明；有歌词默认歌词，无歌词显示信息；不支持时打开原App | 不承诺全播放器统一控制或全曲库歌词。QQ音乐待实际验证；缺能力时隐藏失效控件 |
| ADR-NG-11 桌面真实与双模式 | main说不做Virtual；后来的ADR-010/013已经接受双模式与新窗新空间目标 | Native默认守真实证据；已有Virtual偏好与设计保留、明确命名、独立门槛。不取消也不借新模块打开系统写权限 | 将Virtual长期目标移除需要另一次重大产品决定；本轮不需要它作为新本地模块的前置依赖 |
| ADR-NG-12 分发路线 | 当前完整助手含AX、自动化和特定版本私有Spaces读取；现有 Nearpane 仍为开发签名 | 采用 Developer ID 签名与公证的目标发行路线；正式签名、公证与干净设备验收仍待完成。所有新公共API能力与私有读取隔离，不假称全版本/MAS支持 | Mac App Store可以另行评估受限版本；它不是无代价的发行开关，不为可能上架承诺能力等价 |

## 明确保留的原则

- 主驻留屏默认1/8、一主多副、完整侧栏无Header；副屏不复制采集模块。
- 所有真实几何统一变换，不能美化成未执行布局。
- 持久WorkRect不随隐藏/折叠改变；原生全屏不被压成7/8。**停用编排**与**隐藏预览**明确区分。
- Saytile忠实连续文本、用户手改保护；Riftlet点击附加/不自动发送/失败恢复。
- 现有普通窗口、Native/Virtual写入准入和退出恢复规则；本轮设计不会解锁其BLOCKED状态。
- 现有单一Host、领域锁、统一档案主窗口和旧用户数据。

## 需要产品负责人知晓，但本轮不必停工等待的分歧

1. **默认复制还是移入文件**：推荐复制并让移动成为清楚可选模式；若负责人以后决定默认移动，应只替换ADR-NG-06并完整验收事务恢复。
2. **完整助手与未来沙盒发行**：推荐先完整Developer ID路线；不能把未确认的App Store同等能力写进营销。
3. **歌词价值与接入成本**：推荐先可靠媒体行，再为获准歌词来源逐一开放；不把未取得接口的QQ全功能列为阻塞全产品的交付目标。
4. **旧自定布局迁移**：推荐保持旧值，新默认只用于干净配置。需要更激进统一外观时，提供用户主动采用的入口，不静默覆盖。

这些决定均已给出推荐与替代，Codex可沿推荐继续；只有遇到新证据使其不成立时，先记录更小的可行替代，并继续独立任务。
