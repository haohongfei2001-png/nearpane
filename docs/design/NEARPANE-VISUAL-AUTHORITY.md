# Nearpane — 视觉权威与空间窗口几何规范

**状态：视觉方向冻结（Visual Authority）；2026-11-09 双空间模式语义修订，不改变已确认视觉比例与素材**  
**适用范围：** Nearpane 桌面侧栏的视觉结构、空间缩略预览与窗口几何呈现。  
**本文件优先级：** 后续原型、界面实现和视觉迭代必须遵循；若实现与本规范冲突，以本规范为准。  
**注意：** 本规范冻结的是当前确认的视觉方向与几何规则，不代表产品功能、系统 API 或工程实现已经完成。

## 1. 产品形态

Nearpane 是贴近屏幕边缘的 macOS 工作空间调度层。它把原本分散、难以形成秩序的空间与窗口切换入口，组织成一条连续、受约束的侧边工作区，并将语音输入、截图暂存与空间窗口调度整合在同一视觉系统中。

它不是传统 Dock 的简单扩展，也不是一个带标题的应用控制面板。它应像桌面环境自然延伸出来的一条窄侧栏：用户仍然在原应用中工作，Nearpane 负责在边缘提供输入、截图和空间切换能力。

## 2. 视觉权威

当前确认的是出厂默认视觉方向和桌面行为；用户仍可在设置中精调尺寸，但不能关闭已约定的普通窗口避让语义而不显式选择例外：

- 侧栏贴屏幕边缘，主屏完整形态**默认**宽度约屏幕宽度的 **1/8**；用户可在设置中精细修改，副屏也完全独立可调。
- 在**非原生全屏**的工作区，默认持续保留约 1/8 屏宽作为 Nearpane 边缘区域；其他普通受管理窗口仅在约 7/8 的 WorkRect 内平铺，不能进入该区域。只有真正原生全屏可使用完整显示器。**Nearpane UI 可顶天立地、仅露出部分模块或完全隐藏，但保留区域不随 UI 显隐改变。**
- **精简 Nearpane（如全屏语音板）** 是可移动、由用户手动唤出的浮层，其自身不改变持久工作区域；优先保持用户上次的位置，仅为避开可确认的按钮作最小必要移动。
- **不显示标题、产品名、Logo、品牌栏或顶部应用 Header。**
- 不添加“新建空间”、空间数量管理、布局编辑、设置或其他并未要求的控制入口。
- 整体采用克制的 macOS 玻璃质感：浅色半透明材质、适度背景模糊、柔和边界与阴影。紫蓝色可以作为环境与交互强调色，但不能让内容缩略图失真。
- 视觉秩序来自稳定的边界、间距、比例和内容分组，而不是依靠大量标题、标签或装饰图标。

### 2.0 全屏不显示空间调度

- 原生全屏尊重 macOS 全屏 Space：应用占满显示器，不压缩为 7/8；完整 Nearpane 和 Spaces 调度区默认不显示。
- 只有用户配置允许的小状态条可以在全屏提供明确唤出入口；用户点击后才展开录音等指定工具的浮层，不允许自动展开。
- 全屏退出默认返回进入前的原空间并恢复普通平铺；若用户在设置中启用了经验证的“退出后单开空间”选项，则遵从该模式。系统限制不允许时标记不可用。
- 所有浮层可移动、可记忆位置，智能避让仅以真实能确认的控件/焦点为依据，不能承诺识别所有第三方按钮。

### 2.1 纵向分区

侧栏纵向可用空间**出厂默认**按以下比例组织；用户可在独立设置中精确调整主/副屏面板及内部区域的全部尺寸：

| 区域 | 目标高度占比 | 说明 |
|---|---:|---|
| 语音输入 | 与截图区合计约 3/8 | 紧凑、常驻，不做成大型聊天窗口 |
| 截图托盘 | 与语音区合计约 3/8 | 以小型截图缩略图为主，维持既有截图托盘的交互语义 |
| 空间调度 | 约 5/8 | 主要功能区；连续、规整地展示各个显示空间 |

上方两个工具模块出厂默认明显小于空间调度区。它们不能因空间数量变化而被**自动**缩小；用户可在设置中明确调整任意模块高度与分区比例。各模块之间以留白、容器和轻分隔建立层次，不依赖文字标题。

### 2.2 语音输入模块

- 继承 Saytile 已确认的产品形态和交互语言，不重新设计成通用语音助手或聊天卡片。
- 以持续出现、持续修正的文字流为主体。
- 控件保持极少：复制与状态/麦克风控制。
- 状态通过既有状态控件和实时竖条声波表达；不增加冗余状态文字。
- 模块高度受约束，常态不超过上方工具区可用空间。

### 2.3 截图托盘模块

- 继承 Riftlet 已确认的截图暂存语义与微图设计，不将其改造成通用相册。
- 默认以紧凑、规整的缩略图网格呈现最近截图；捕获入口可占据一个缩略图位。
- 保持截图原始比例与可辨识内容，不为了填满格子而拉伸图片。
- 空间数量增加时，截图托盘尺寸和内容不随之缩小。

### 2.4 主屏常驻 + 副屏按需 Space-only（ADR-011）

- **只有一块用户指定的主驻留屏**常驻显示 Saytile 和 Riftlet，不因连接副屏创建第二份语音、截图面板或 Host。
- 主屏默认全模块形式延续约本屏宽 1/8、工具区 3/8 与空间区 5/8；主屏 Space 调度区有真实空间/多窗口需求时必须可见，只有单空间单窗且无其他调度目标时才可省略，主界面可缩为仅语音/截图；**这不释放持久 WorkRect**。
- **其他每块副屏**至多一个仅包含空间调度的浮板；副屏呈现及工作区保留策略单独设置。副屏不显示 Saytile/Riftlet 或其他主屏模块；主屏 Space 区由真实多空间/多窗口需求决定，存在需要调度的窗口时不得自动隐藏。
- 每块显示器的面板宽度、高度、左右边缘、纵向位置、空间行密度和显示条件独立配置。副屏不强制使用主屏的 1/8 宽和纵向分区；竖屏与旋转屏独立适配。
- 不改变真实窗口几何原则：缩略图内部的窗口必须统一缩放，保留真实宽高比、坐标和重叠。副屏的面板大小变化不能导致单个窗口被各自拉伸。
- Native 与 Virtual 只影响展示哪些空间和窗口，不影响一主多副的呈现角色；主屏与副屏不得自行运行不同的工作区调度引擎。

### 2.5 全部尺寸都能在设置中精细修改（ADR-011）

本规范定义的是**出厂默认设计**，不是一套永久锁定的尺寸。主/副屏面板宽度与高度、主屏 Saytile/Riftlet/Spaces 各自高度、文字区、字体与行距、按钮与图标、截图微图与展开图显示框、Space 行高和桌面预览容器、间距/内边距、圆角及可选模块的显示尺寸，均可在**独立设置窗口**中逐项精确输入、微调、预览并恢复默认。主表面不增加尺寸滑块或拖拽缩放把手。

默认保留原来确认的 1/8 宽度、3/8+5/8 组合、Saytile/Riftlet 视觉尺寸和空间行设计。用户可以只改某一尺寸，其它用户自定义值不能被静默覆盖。显示器之间保持独立配置；点数与显示器比例单位明确，并考虑安全区域、可读性与溢出反馈。**可调的是呈现容器与控件，不是将真实窗口或截图拉伸变形**：窗口仍使用统一的 Space 坐标变换，截图保持 Fit，空间不足采用独立滚动/分页或清楚提示。

## 3. 空间调度模型

### 3.1 一行代表当前模式的一个工作空间

- **Native 模式**：空间调度区展示 macOS 真实存在的 Spaces；一行即一个经确认的系统 Space。
- **Virtual 模式**：空间调度区展示 Nearpane 管理的逻辑 Workspaces；一行即一个明确的虚拟 Workspace，不把它称作系统 Space。
- 两种模式使用同一侧栏、相同比例、窗口尺寸/位置/层级映射规则；模式开关只放在独立设置，不增加主表面标题或模式管理栏。
- 虚拟非活动窗口可能暂时停放在屏外，缩略图展示该工作区**经确认的目标可见布局**，不以停放坐标绘制虚假窗口位置；未知布局必须标为未知，不能手绘补齐。

本节的“一行一空间”表示当前模式的真实管理对象，而非要求所有模式的行都对应一个原生 macOS Space：

- **一行对应一个空间**，不是一个应用，也不是用户自定义的项目分组。
- 常见使用数量为 **2–4 个空间**。
- 最多优先展示 **5 行**。
- 不在该区域提供新建空间、删除空间或布局编辑按钮；Native Space 由系统管理，Virtual 工作区的管理入口单独位于设置中。
- 不把多个空间合并成一张卡片，也不把一个空间拆成多行。

### 3.2 行的尺寸与数量适配

- 主屏完整形态**默认**空间区约占侧栏可用高度的 **5/8**，可在设置中独立改高。
- 2–4 行是主要设计状态，应保证每一行具有足够高度，让窗口形状和布局关系可以辨认。
- 5 行时仍应保持清晰、稳定的行间距与边界。
- 超过 5 个空间时，优先只压缩**空间窗口缩略预览本身**，以容纳更多行；不得同步缩小或挤压语音输入和截图托盘。
- 空间数量增长不得**未经用户选择而自动**改变侧栏宽/高或隐藏工具；用户可在设置中精细调整这些参数，超出安全显示区域须明确提示。

## 4. 窗口预览必须忠实于真实几何

空间缩略图不是装饰性示意卡片，而是对**Nearpane 已执行且确认的自动平铺窗口**之实际 frame 的微缩映射。默认普通主窗口在 WorkRect 内不重叠、不出界、不进入侧栏保留区；如果因权限或系统限制尚未平铺成功，必须如实呈现未知/不受管理状态，不得画出理想的伪平铺。

### 4.1 坐标映射

每个空间预览都应以该空间对应显示器的实际可用桌面区域作为几何基准：

- 使用显示器对应的实际宽高比和可用区域。
- 将窗口的实际 frame 按统一缩放比例映射到预览区域。
- 对所有窗口使用同一空间坐标变换；不得逐个窗口独立拉伸。
- 保留窗口的相对位置、宽高比例、间距和层级。
- 预览容器边界代表显示器/空间边界；超出边界的窗口部分按真实边界裁切。
- 预览中的窗口缩略图应保留可辨识的窗口边框、标题栏或内容轮廓，但不能用这些装饰改变实际几何。

### 4.2 用户拖入窗口后的 1—8 窗渐进平铺（ADR-013）

以用户将具体窗口缩略图**从其他空间拖入目标行**作为主要增加成员方式；布局以加入顺序 W1—W8 和该空间实际 WorkRect 为准：

- **1 窗：** W1 使用 WorkRect 全部。
- **2 窗：** W1/W2 各占 1/2。
- **3 窗：** W1/W2 在右侧 1/2 内上下平分（各占 1/4），新 W3 独占左半区。此前手动调整的双窗分割在加入第三窗时恢复为这一模板，之后仍可再调。
- **4 窗：** 将 W3 所在半区分成两个 1/4，W3/W4 各占一个；W1/W2 继续占右侧各 1/4。
- **5 窗：** W1/W2 共享原 1/4、各占 1/8，W5 占新 1/4；W3/W4 各占 1/4。
- **6—8 窗：** 继续对既有分区渐进二分，不重叠、不出界，不自动新建空间。第九个窗口被明确拒绝。
- 用户可拖动真实窗口交换槽位、调整边界比例；相邻分区联动。应用级窗口偏好可以改变默认模板，但须真实执行，不能只改缩略图。
- 平铺不能满足 App 最小尺寸、权限或系统窗口限制时必须拒绝并提示；“支持最多 8 窗”不等于任何 App 都能在任意分辨率达到八窗。

空间缩略图中每个窗口必须依据已经验证的真实 frame 等比绘制，不能为了美观模拟未执行的布局。

### 4.3 真实工作区与预留区域

- 窗口可用区域以当前屏幕 `visibleFrame` 等安全区为基准，扣除**持久配置的 Nearpane 保留区域**，再扣除明确间距。NSScreen.visibleFrame 不会因 Nearpane 的 UI 显隐改变；即使 UI 隐藏，WorkRect 仍需对普通窗口维持原边界。
- 默认普通窗口彼此无重叠，不能侵入 Nearpane 保留区或超出对应显示器。缩略图保留 WorkRect 外的空白/侧栏边界，不允许把窗口任意放大到覆盖保留区。
- 弹窗、菜单、sheet、系统警告、受保护应用窗口与原生全屏不是普通可平铺主窗；这些需独立显示状态并遵守系统限制，不能通过强制调整使 App 失效。
- 如果真实窗口因最小尺寸/权限/系统限制没有达到平铺目标，缩略图忠实呈现该状态与能力警示，不能以装饰性整齐冒充“无重叠已通过”。
- 截图和空间窗口内容维持 Fit 与原始宽高比；用户在设置中改变缩略容器尺寸时，只能统一等比变换与必要留白，不得逐窗拉伸。

## 5. 交互表达

- **点击空间行任何位置只切换整个 Native Space 或 Virtual Workspace**；但按明确拖拽手势开始移动**具体窗口缩略图**，可将其拖至另一个空间行并申请加入。拖拽不等于点击激活某个窗口，drop 前不改变实际所属空间。
- 若目标空间正在重排、身份过期、切换不可用，禁用整行操作并明确状态；进入后保留该空间最近有效的前台窗口，不根据点击空间缩略图中的哪个窗口区域随机改变焦点。
- 用户使用真实桌面上的应用窗口完成具体窗间操作；近似屏幕调度的主缩略区不提供逐窗选择、拖放、创建系统 Space 等额外控制。
- 主屏完整/部分/隐藏是随真实窗口数、空间数与工具使用状态决定的呈现，不改变普通主窗的 WorkRect；有多个可切换空间/受管理窗口时空间调度不能自动隐藏，只有单空间单窗可省略空间区。原生全屏无 Spaces 调度，用户主动点小状态条才打开精简工具浮层。

## 6. 必须通过的视觉验收

实现前后均应使用真实显示器尺寸和真实窗口 frame 验证，不以手绘示意图代替。

- [ ] 主屏全功能形态宽度约为该屏的 1/8；副屏 Space-only 面板宽度独立可调。
- [ ] 无标题、无 Logo、无产品名、无 Header。
- [ ] 主屏全功能形态语音与截图合计约占 3/8，副屏不显示语音与截图。
- [ ] 主屏全功能形态空间区约占 5/8；仅无多空间/多窗口调度需求时可以隐藏该 UI，主面板高度可收缩，WorkRect 不变；副屏面板独立配置。
- [ ] 常见 2–4 个空间时，每行预览足够清晰。
- [ ] 5 个空间时布局仍然稳定。
- [ ] 超过 5 个空间时，只缩小空间预览，不缩小语音和截图模块。
- [ ] 一行严格对应当前模式的一个 Space/Workspace，Native 与 Virtual 不混用身份；Virtual 不伪造系统 Space。
- [ ] 从 1 到 8 个窗口的渐进平铺、第五个窗口的 1/8 + 1/8 + 1/4 + 1/4 + 1/4、九窗拒绝均经真实 frame 验证；应用级自定义比例按真实 frame 映射。
- [ ] 单窗口占 WorkRect，双窗平分，三窗 W1/W2 右半区上下/W3 左半区，四窗四分区；用户改双窗后再加第三窗仍恢复标准三窗模板。
- [ ] 非原生全屏始终保留固定 WorkRect；UI 全部隐藏、只显示语音/截图或 Space 区不改变已存在的普通窗口 frame；普通窗口不出界、不侵入预留区。
- [ ] 同一 App 的多个受管理主窗口也不叠放；系统临时窗口/模态框作为明确例外，不伪造完全可控。
- [ ] 不同 App 的平分布局不会被错误地画成层叠窗口；平铺动作失败不画假成功。
- [ ] 单击整行切换 Workspace；具体窗口缩略图可作为 drag source 拖进另一个 Space，松开后验证/加入，不能混淆点击和拖拽。

## 7. 设计原则总结

Nearpane 的关键不是把更多工具塞进侧边栏，而是把它们组织成一个稳定、可预测的边缘工作界面：

- 上方工具保持紧凑、独立、尺寸稳定。
- 下方空间调度成为视觉主体。
- 一行一个当前模式的空间（Native Space 或 Virtual Workspace）。
- 一个被管理的普通窗口对应一个真实平铺后窗口 frame 的几何投影，完整侧栏与被管理窗口在非全屏时不相互覆盖。
- 空间越复杂，缩略图越需要忠实；不能为了美观牺牲宽高比例和布局事实。

**最终裁决（ADR-013）：非原生全屏的 1/8 持久保留区与 UI 显隐解耦；空间调度随真实需要展示，普通受管理窗口按缩略图拖入的成员进行最多八窗无重叠渐进平铺，点击整行切空间；真正原生全屏可占满整个显示器，精简浮层原位优先、必要时最小避让。**
