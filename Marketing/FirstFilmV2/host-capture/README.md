# Native Host scene: production one-row / two-row Riftlet height

This bounded camera scene opens an executable-bound empty disposable profile in
the complete packaged Host. It uses real Music playback, the production
HostLyrics lifecycle, the real module management window, real drag/drop ordering,
the production Riftlet tray, and a real region capture on the owned original
desktop. Observed take records identify whether the PDF or wallpaper is visible. The normal player and screenshot routes are selected, with no verification
playback snapshots and no seeded screenshot images.

`prepare_host_camera.py` instruments only a disposable git worktree. Main product
source is not rewritten. The two-line actual Music artwork fix already proven in
run 46109639614 is present on the creative branch, and remains unreleased.

The photography composition uses the actual lyric card at 208 × 192 points.
Riftlet uses the production `TrayModule.rowCount` and the real
`LayoutComposer.compose(...).screenshots.height`: 208 × 76 points when empty,
and 208 × 144 points after a real screenshot adds a third slot. Both views are
uniformly enlarged to 280 points wide on a verified real 2× display. The empty
tray therefore has a single row of two normal-height entries; it is never
stretched into a lyric-sized 192-point slot. Its two-row state appears only when
the real model has content. The camera window follows the observed height and
keeps its right/top anchor. No artificial geometry tween is added.

Only the outer native material is matched to the lyric card. Text, icons,
cell proportions, screenshot aspect ratios and original opacity are retained.
`input-inspect.json` and `input-after-shot.json` contain actual AX rectangles;
`dual-state-timeline.json` records row count, production height and window frame
through the transition.
The management-window drag/drop updates the actual Host registry; this is not an
invented ability to drag cards directly on the desktop.

The full WindowServer movie includes the real cursor and ScreenCaptureKit system
audio. A separately preserved state timeline records actual playback, cue,
controls, Host order, screenshot asset IDs, frontmost app and window visibility.
Actual source audio synchronization is determined from captured waveform, not
assumed from an AppleScript return time. `host-result.json` independently reports
whether reorder and screenshot intake actually succeeded; recording success
alone does not pass these action checks.

No personal account, existing library, real user desktop or production profile is
used. No screenshot is sent to another person or online conversation.
