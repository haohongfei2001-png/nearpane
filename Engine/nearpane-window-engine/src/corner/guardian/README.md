# Corner recovery handoff

The signed development Host can create a Guardian only for a reviewed Corner backend, after explicit group consent and the coordinator's durable HIDE intent. The ordinary package currently has no approved Corner evidence. Its installed helper therefore stays dormant. The isolated fixture and the packaged helper use distinct signatures, authentication rules and compile modes.

## Packaged helper

From the repository root run `scripts/acceptance/window-engine/corner/build-guardian.sh OUTPUT_EXECUTABLE PRODUCT_RUST_STATIC_ARCHIVE`. Package the result as `/Applications/Nearpane.app/Contents/Helpers/NearpaneCornerGuardian`. Its identifier is `com.holdsnow.nearpane.alpha.corner-guardian`. Both it and `Contents/MacOS/NearpaneHost` require Developer ID team `ZB9D4T66QB` and their fixed identifiers. The helper checks running and on-disk code at their canonical paths. The product build uses the reviewed evidence list in the same Rust archive as the Host.

The Swift client starts `NearpaneCornerGuardian --watch JOB_DIRECTORY` with inherited stdin and stdout. The per-intent directory is created under the coordinator's active, exclusively leased profile at `Nearpane/.corner-guardians/<hide intent UUID>`. There is no socket, PID lookup endpoint, CLI registration or background daemon. Process death loses all retained AX references.

- `prepare(_:epoch:)` runs after the hide entry reaches `stage-visibility-v1.json` and before the first OS write. The Guardian matches the exact pending intent, active profile, group directory entry, signed Host hash, evidence, member, generation and window lifetime. It retains the original ordinary AX object and watches the kernel for exit of its original parent before sending the R acknowledgement.
- `observe(_:receipt:)` saves the actual Rust HIDE receipt in memory. After the coordinator independently reads back the result twice and persists its ownership, `confirm(_:verifiedFrame:)` sends the epoch, original intent, actual flags, native ID and measured frame. The Guardian checks the committed ledger, the same AX object and the AX and WindowServer postimage twice before sending P.
- While the Host lives, only its engine writes. Once the Host independently verifies SHOW or RESTORE and removes the owning entry, `disarm(_:)` requests D. The Guardian requires the matching released ledger and the measured original frame. `finish()` refuses to finish while a lease is unresolved.

A recovery attempt requires both EOF and the kernel's exit notification for the exact original Host generation. A shared lock on the existing profile writer lock excludes a replacement Host. A separate exclusive recovery lock serializes the surviving Guardians. Each Guardian rechecks the reviewed owner, active profile, signed target application, still-retained original AX object, current Space and display, exact parked frame, secure input and stable HID counters during takeover. The existing AX setter runs at most once. Two independent original-frame reads precede the machine receipt. An ambiguous postimage, missing permission, changed owner, failed readback, conflicting new Host or reused numeric window ID leaves recovery unresolved. After independently confirmed restoration, the Guardian can remove exactly its matching committed ownership while the profile excludes all Host writers and the recovery mutex is held. The update preserves all other journal fields, compares the original journal, then atomically replaces and verifies it. An interrupted batch or concurrent change retains the journal and receives a separate unresolved transaction result.

## Disposable qualification

The separately compiled test Guardian authenticates the exact signed fixture controller and its two signed child applications. A per-window, owner-only binary ledger contains the same control request the controller fsynced before sending it over the pipe. Unchanged input across the entire isolated crash trial is mandatory. Its supervisor observes a real SIGKILL of the sacrificial controller, verifies both fixture owners and their frames, then sends one complete gesture to the restored fixture window and checks its independent receiver.

Run the complete disposable test with `scripts/acceptance/window-engine/corner/run-hosted.sh NEW_OUTPUT_DIRECTORY`. The initial full A→B→C→A circle and verified teardown are prerequisites for the independent crash drill. Its evidence is under `recovery/`. The `--scope-only` option reads only display and ordinary Space identities. The `--build-only` option compiles and signs the fixture without opening windows. Physical qualification of the final installation and recovery after relaunch are recorded separately.
