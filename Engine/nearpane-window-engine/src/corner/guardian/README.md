# Corner recovery handoff

The signed development Host can create a Guardian only for a reviewed Corner backend, after explicit group consent and the coordinator's durable HIDE intent. The ordinary package currently has no approved Corner evidence. Its installed helper therefore stays dormant. The isolated fixture and the packaged helper use distinct signatures, authentication rules and compile modes.

## Packaged helper

From the repository root run `scripts/acceptance/window-engine/corner/build-guardian.sh OUTPUT_EXECUTABLE PRODUCT_RUST_STATIC_ARCHIVE`. Package the result as `/Applications/Nearpane.app/Contents/Helpers/NearpaneCornerGuardian`. Its identifier is `com.holdsnow.nearpane.alpha.corner-guardian`. Both it and `Contents/MacOS/NearpaneHost` require Developer ID team `ZB9D4T66QB` and their fixed identifiers. The helper checks running and on-disk code at their canonical paths. The product build uses the reviewed evidence list in the same Rust archive as the Host.

The Swift client starts `NearpaneCornerGuardian --watch JOB_DIRECTORY` with inherited stdin and stdout. The per-intent directory is created under the coordinator's active, exclusively leased profile at `Nearpane/.corner-guardians/<hide intent UUID>`. There is no socket, PID lookup endpoint, CLI registration or background daemon. Process death loses all retained AX references.

- `prepare(_:epoch:)` runs after the hide entry reaches `stage-visibility-v1.json` and before the first OS write. The Guardian matches the exact pending intent, active profile, group directory entry, signed Host hash, evidence, member, generation and window lifetime. It retains the original ordinary AX object and watches the kernel for exit of its original parent before sending the R acknowledgement.
- If the Host's independent read after R vetoes the hide, the original Rust handle can permanently exclude that intent under the same lock that admits HIDE tickets. An accepted ticket always prevents this withdrawal, including after cancellation, timeout or consumption. The Guardian rechecks its retained window, signature, membership, original AX and CG geometry and the exact pending transaction twice. It releases the reference, persists `WITHDRAWN_BEFORE_SUBMISSION` in `guardian-receipt.json`, flushes the job directory and replies W. The Host verifies that receipt against the original Host, Guardian and window generations before settling the pending entry. Missing evidence keeps the recovery record.
- `observe(_:receipt:)` saves the actual Rust HIDE receipt in memory. After the coordinator independently reads back the result twice and persists its ownership, `confirm(_:verifiedFrame:)` sends the epoch, original intent, actual flags, native ID and measured frame. The Guardian checks the committed ledger, the same AX object and the AX and WindowServer postimage twice before sending P.
- While the Host lives, only its engine writes. Once the Host independently verifies SHOW or RESTORE and removes the owning entry, `disarm(_:)` requests D. The Guardian requires the matching released ledger and the measured original frame. `finish()` refuses to finish while a lease is unresolved.

A recovery attempt requires both EOF and the kernel's exit notification for the exact original Host generation. A shared lock on the existing profile writer lock excludes a replacement Host. A separate exclusive recovery lock serializes the surviving Guardians. Each Guardian rechecks its own current Accessibility permission, the reviewed owner, active profile, signed target application, still-retained original AX object, current Space and display, exact parked frame, secure input and stable HID counters during takeover. The existing AX setter runs at most once. Two independent original-frame reads precede the machine receipt. An ambiguous postimage, missing permission, changed owner, failed readback, conflicting new Host or reused numeric window ID leaves recovery unresolved. After independently confirmed restoration, the Guardian can remove exactly its matching committed ownership while the profile excludes all Host writers and the recovery mutex is held. The update preserves all other journal fields, compares the original journal, then atomically replaces and verifies it. An interrupted batch or concurrent change retains the journal and receives a separate unresolved transaction result.

## Read-only fixture ownership report

`CornerGuardianFixtureReport.sample(pid:birth:number:executable:cdhash:scope:nativeID:)` runs in the Host for an enrolled `com.holdsnow.nearpane.engine-fixture.a` window. The two samples check the signed process generation and its WindowServer owner. With an independently established ordinary Space and existing Host Accessibility access they also check both membership directions, the original AX object and its geometry. The Host releases its temporary reference before returning. This command uses the Host’s existing permissions, posts zero events and starts zero helper processes.

`handoff` describes this Host’s actual in-memory Corner client. `NO_LIVE_HANDOFF_IN_THIS_HOST` records the absence of a prepared Guardian for the registered window. A real `R` or `P` acknowledgement identifies the instant when the signed Guardian verified the pending or committed ownership. The report reads no profile journal. It records the current child process generation separately. While the Host is alive the qualified Host alone can write. The crash drill and an independent, surviving Guardian’s post-exit permission, original object, locks and postimage checks remain separate evidence. A future or restarted process cannot acquire a recovery lease from this report.

The installed Host can call `await CornerGuardianIndependentProbe.sample(host:executable:)` with that registration. The nested signed executable independently queries its effective Accessibility permission twice. The receipt also records the OS-reported responsible PID. If another process is responsible, or the responsible identity is unavailable, only the registered WindowServer owner is sampled. The Guardian uses AX for the single fixture only after observing its own responsibility, existing permission and the supplied ordinary desktop. It compares the exact retained AX object and geometry twice and releases that temporary reference. The Host verifies the nonce, fixture, numeric window, source desktop, monotonic times and both canonical signed processes and their kernel generations before acknowledging the response. The child exits before the Host publishes the receipt. Neither process opens the profile journal in this exchange.

For an operational lease the original Host needs reviewed physical evidence for this installed environment, user consent, an active locked profile, a real group member, and its persisted pending HIDE entry. The directory `generations/<active>/Nearpane` under `Library/Application Support/Nearpane Alpha Profiles` contains `stage-groups-v2.json` and `stage-visibility-v1.json`. The latter holds the pending and committed ownership. The per-intent `.corner-guardians/<hide intent UUID>/guardian-receipt.json` records the actual end of that process. To disarm after a real park, the original Host first restores or shows the member, confirms its original geometry twice and releases the matching ownership. The Guardian now independently confirms the released journal, same signed window, display and original AX and CG geometry in two successive reads before acknowledging D. A report with no operational R or P cannot authorize a park, clear a WAL, or establish restored ownership. To release the profile, also verify the active generation, no profile transaction, no pending visibility transaction, zero owned entries, and no outstanding release before replacing the Host.

## Disposable qualification

The separately compiled test Guardian authenticates the exact signed fixture controller and its two signed child applications. A per-window, owner-only binary ledger contains the same control request the controller fsynced before sending it over the pipe. Unchanged input across the entire isolated crash trial is mandatory. Its supervisor observes a real SIGKILL of the sacrificial controller, verifies both fixture owners and their frames, then sends one complete gesture to the restored fixture window and checks its independent receiver.

Run the complete disposable test with `scripts/acceptance/window-engine/corner/run-hosted.sh NEW_OUTPUT_DIRECTORY`. The initial full A→B→C→A circle and verified teardown are prerequisites for the independent crash drill. Its evidence is under `recovery/`. The `--scope-only` option reads only display and ordinary Space identities. The `--build-only` option compiles and signs the fixture without opening windows. Physical qualification of the final installation and recovery after relaunch are recorded separately.
