## 一、结论与审计范围

Nearpane 的当前桌面窗口清单、逐窗画面和受控选窗已有实际进展；完整原生 Spaces 的状态模型、空间切换和跨空间迁窗还没有接入正式产品。空间体验薄弱的主要原因是核心动作后端缺失、早期只读约束长期固化，以及已安装产品与验收进程的权限不同。增加权限只能改善已实现的窗口画面与 AX 操作，不能补出尚不存在的 Spaces 后端。

建议保留已有侧栏、窗口身份、坐标转换、普通窗口布局、缩略图和恢复记录，集中重构空间状态服务与动作适配器。先验证可复用的原生 Spaces 切换核心，再把完整路径接回侧栏，最后扩展跨空间迁窗、创建/清理和布局政策。

本次完成 GitHub 最新分支与源码的静态审计，并核对 Apple 文档及上游项目。没有在用户 Mac 上运行新验收。本文中历史实机结果均来自仓库已提交的验收记录；大量原始 JSON、PNG、log 位于被忽略的 `build/verification/`，本次不能独立重放。源码结论、历史实测记载、待验证技术候选分开表述。

## 二、用户目标应落实为什么

Native 模式继续操作 macOS 自己的 Spaces、真实窗口和原生全屏。用户可以同时使用系统 Mission Control、系统手势和 Nearpane。Nearpane 提供常驻侧栏、空间预览、具体窗口选择、跨空间拖动、布局与恢复。

“像原生一样”应拆为四项：空间身份与系统一致，切换去向与系统一致，窗口焦点能立即工作，交互稳定且及时。Apple 的 Mission Control 不是一个可直接拿来换皮嵌入的公开 UI 组件；Nearpane 需要自己绘制侧栏，调用和观察系统机制。最终能否达到原生体验需实机证明，不能由一个 API 或一次事件发送推导。

用户此前同意 Native / Virtual 双模式，但本轮重点应为 Native。Virtual 不得暗中取代真实 Spaces，也不得用移到屏幕外的窗口组冒充系统桌面。新增的窗口管理政策应与空间切换能力分离，避免“单纯切换”同时触发未经请求的全桌面重排。

## 四、代码审计问题台账

### NP-S01 / P0：正式原生动作后端缺失

证据：

- `Sources/NearpaneCore/DesktopObservation.swift:8–25`：观察模型的 `spaceSwitching` 与 `windowActivation` 固定 false，解码拒绝 true。
- `Sources/NearpaneUI/DesktopSurface.swift:67–69`：空间指针层只在上述切换能力为 true 时安装。
- `Sources/NearpaneCore/WorkspaceActions.swift:109–113`：`NativeSpacesProvider.apply/rollback` 直接抛出 unavailable。
- 同文件 123–139：只投影当前见证行，layout 为 nil，grants 为空。
- `Sources/NearpaneCore/HostSession.swift:198–218`：正式 Host 使用的就是上述 provider。

只读模型本身不应任意授予写权限；真正缺的是独立、已验证且可被正式 UI 调用的动作服务。不能只把 false 改成 true。当前桌面卡片已有另一条窗口激活链，不能因此说所有窗口激活均被关闭。

修复方向：实现异步原生动作适配器，将 switchSpace、focusWindow、moveWindow、tile、createSpace、removeSpace 分开报告能力与结果。读取器只发布观察，动作服务独立核验目标并回读系统状态。

[源码](https://github.com/haohongfei2001-png/nearpane/blob/7e0a2c1d0ae962d7e8dbd9e6dbd2a7dad77741bd/Sources/NearpaneCore/WorkspaceActions.swift)

### NP-S02 / P0：多 Space 模型被当前桌面观察方式限制

- `SpaceInventory.swift:65–80` 仅为有独立窗口锚点的当前普通桌面生成可见证行。空桌面可能没有锚点。
- `DesktopPreview.swift:116–127` 不显示未曾见证的后台 Space。
- 同文件 51–54 把此前见证过的后台 Space 的窗口列表直接置空。
- `DesktopObservation.swift:61–112` 仅缓存空间身份，不缓存窗口几何；12 秒以上采样间隔、会话或拓扑变化可清除历史。

用户看到的因此主要是当前桌面的清单，尚无完整多空间地图。应从系统 inventory 与成员关系建立全部 Space 模型，将空桌面、无法确认内容、最后一次有效画面分别表示。不能将“未读取”画成“空桌面”；也不能因为用户从未点开过某个 Space 就让其不存在。

[预览源码](https://github.com/haohongfei2001-png/nearpane/blob/7e0a2c1d0ae962d7e8dbd9e6dbd2a7dad77741bd/Sources/NearpaneCore/DesktopPreview.swift)

### NP-S03 / P0：最终安装身份与验收权限没有闭合

5.18 记录的正式 Host 自报录屏与辅助功能均未授权。真实多窗截图、5.17 精确选窗的成功证据来自另一个已授权验收进程。

修复方向：固定应用、助手、bundle ID、安装位置和签名方案；按操作目的显示权限入口；授权返回后刷新能力；最终安装身份完成一次端到端验证。不要要求用户为开发阶段多个临时程序反复授权。OS 要求账户所有者确认的授权不能由工程代码自动绕过。

授权缺失不是 Spaces 未实现的替代解释，两项须分别解决。也不能未经证据认定是升级导致授权丢失；当前记录只证明正式身份下的权限状态。

### NP-S04 / P1：只支持单一精确系统 build

`Sources/CReadOnlySpaces/ReadOnlySpaces.c:69–84,114–124` 只接受 arm64 + `kern.osversion == 26A428`。其他 build 在加载私有接口前即被拒绝；部分 AX 窗口号读取也依赖同一检查。

修复方向：建立真正的支持矩阵、符号与结构探测、动作级能力检查、隔离 helper、限速恢复。已知失败版本保留禁用；新 build 必须验证，不能删除白名单后自称全面支持。现状属于早期实验准入条件，并非 macOS 必然只能在一个 build 工作。

`NativeDesktopProvider.swift:102–134` 还会记住一次私有读取异常；恢复通常依赖开关变化或显示器布局变化。短暂异常应允许有退避的重新探测，避免整个运行周期失去能力。

[只读桥接](https://github.com/haohongfei2001-png/nearpane/blob/7e0a2c1d0ae962d7e8dbd9e6dbd2a7dad77741bd/Sources/CReadOnlySpaces/ReadOnlySpaces.c)

### NP-S05 / P1：动作目标和快照刷新耦合过强

- `WorkspacePointerSurface.swift:44–50` 只接受当前 witnessedSpace，后台行不可成为目标。
- 同文件 25–26 在任意 revision 更新时取消拖动。
- `WorkspaceActions.swift:177` 在释放时要求整个快照完全相同。
- 同文件 183–199 将跨 Space 移窗与源、目标均可平铺以及所有行具备完整布局绑在一起。

这些是潜在的下一阶段阻塞；目前正式动作本就关闭，不能把它们说成已观察到的用户拖动失败。接入新后端时应以稳定 Space 身份、窗口号与进程代际绑定目标，只复核受影响条件；无关刷新不应取消合法拖动。迁窗成功与自动重排分开执行。

[指针交互](https://github.com/haohongfei2001-png/nearpane/blob/7e0a2c1d0ae962d7e8dbd9e6dbd2a7dad77741bd/Sources/NearpaneUI/WorkspacePointerSurface.swift)

### NP-S06 / P1：当前桌面的窗口激活仍有过强前提

`Sources/NearpaneOrdinaryWindowController/FocusCurrentWindow.swift:86–105` 在需要激活另一 App 时，会检查目标是 main window，且同 App 所有兄弟窗口都在当前桌面，或 focused window 已是目标。跨 Space 使用同一浏览器/编辑器时，正常目标可能被拒绝。

这是源码明确的拒绝条件及兼容风险，本次没有在真实 Mac 上复现。应借鉴成熟精确选窗路径，以目标 Space 与目标窗口为核心；保留进程代际和最终 focusedWindow 校验，去掉与当前动作无关的全局兄弟窗前提。

[焦点助手](https://github.com/haohongfei2001-png/nearpane/blob/7e0a2c1d0ae962d7e8dbd9e6dbd2a7dad77741bd/Sources/NearpaneOrdinaryWindowController/FocusCurrentWindow.swift)

### NP-S07 / P1：状态供给、设置解释与显示层逐渐分叉

旧 Host 桌面观察与新的 CurrentDesktopWindows 各有更新路径。当前画廊清单即便发送 experimentalSpaces:false，仍在 CurrentSpaceWindows 尝试私有 inventory；旧“实验性识别”开关与真实执行范围不再完全统一。侧栏主要显示当前桌面卡片，几何布局需另行展开。

修复方向：单一窗口与空间状态真源，分别输出几何、成员关系、焦点、内容预览；UI 的空间行与窗口卡消费同一模型。保留当前卡片功能，但恢复一个真实 Space 一行、内部反映真实几何和重叠的主结构。用户点空间与点具体窗口应具有清楚、独立的意图。

### NP-S08 / P1：验收路线在前置条件循环，核心功能没有正向成果

架构文档仍主要指定 Control+方向键的相邻 A/B 校准，以及 Mission Control AX UI 操作。历史实验多次卡于副屏只有一个桌面、加号位置、打开/关闭概览后的焦点归还；实验明确不开放生产 Host。

修复方向：一次准备可控、无私人内容的测试窗口与原生桌面，采用现成后端完成真实动作。用户日常点击、系统授权、明确目标和结果校验应构成产品动作链；实验限定时段与会话隔离约束属于测试环境，不应变成消费级每次操作流程。绝不能为了“通过”关闭身份或实际结果验证。

[现有路线](https://github.com/haohongfei2001-png/nearpane/blob/7e0a2c1d0ae962d7e8dbd9e6dbd2a7dad77741bd/architecture/MACOS-SPACES-FEASIBILITY.md)

### NP-S09 / P2：进度入口过期，关键原始证据不能远端审阅

main 仍主要为早期官网线，原生工作在 implementation 分支。README 和部分能力表仍有过期状态；完成状态文档累积大量旧版“当前”描述。关键原始收据位于被忽略的 build 目录。

修复方向：一个简短的当前产品能力表，明确实际源码/安装身份/版本/平台；历史记录另存；上传少量脱敏、关键的 JSON 与合成窗口图片至版本化 evidence 目录。进度以实际用户操作衡量，测试数量只作辅助证据。不要机械重做已经在新版本修复的 5.16/5.17 问题。

## 五、权限与分发裁决

| 权限/机制 | 对 Nearpane 的作用 | 不能替代的事情 |
| --- | --- | --- |
| 辅助功能 | 受支持窗口的 AX 读取、聚焦、移动、缩放 | 完整的公开原生 Spaces 管理接口 |
| 屏幕与系统音频录制中的屏幕捕获授权 | 单窗画面与缩略图；无需采集声音 | Space 写权限和窗口焦点 |
| 自动化 | 选用 Apple Events 控制某 App 时需要 | 通用 WindowServer 控制权 |
| 输入监控 | 采用某些全局输入监听路径时可能需要 | Space 管理能力；纯侧栏点击不应先默认索取 |
| 完全磁盘访问 | 本轮空间调度没有据此成立的必要性 | 不会解锁窗口或 Spaces |
| SIP / Dock 注入 | 某些私有路线的高权限操作 | 不应作为核心切换的默认安装要求 |

公开 API 可以覆盖大量普通窗口功能，但公开 API 没有完整的任意原生 Spaces 管理接口。保持 SIP 开启并不意味着只能用公开 API；使用私有接口也不必然要求关闭 SIP。三者必须区分。

建议原生增强版采用 Developer ID 签名、公证的官网分发路线；未公开 Spaces 机制与 Mac App Store 的公共 API 要求不能混为一谈。公证不等于 App Store 审核，也不保证所有私有实现永久兼容。

来源：[Apple 辅助功能](https://support.apple.com/en-az/guide/mac-help/mh43185/mac)、[ScreenCaptureKit 可捕获内容](https://developer.apple.com/documentation/screencapturekit/scshareablecontent)、[Spaces 变化通知](https://developer.apple.com/documentation/appkit/nsworkspace/activespacedidchangenotification)、[App Review 2.5.1](https://developer.apple.com/app-store/review/guidelines/)、[Apple 公证说明](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution/)。

## 六、复用技术选择

### 1. 优先验证 InstantSpaceSwitcher 的小核心

[InstantSpaceSwitcher](https://github.com/jurplel/InstantSpaceSwitcher) 使用真实系统 Spaces，README 明确无需关闭 SIP，许可 MIT。2026 年 10 月的 3.0/3.1 已涉及 macOS 27 支持。候选固定源码：`2b883a995d1c81fbc6d75704372a6a0b546bb1ff`。

复用范围应聚焦 ISS C target、手势序列化和系统空间观察，不搬独立应用的快捷键、设置与全局手势接管。它用未公开 CGS/手势机制，属于须维护的兼容适配；点击无需让用户配置快捷键。

重要边界：

- 这是合成系统切换手势；其 API 以当前屏幕的顺序 index 工作，不是 Apple 公共的任意 SpaceID 直接调用。
- Nearpane 应绑定 SpaceID 与显示器，在执行时映射当前顺序；不能长期缓存“桌面 2”数字。
- 返回成功和 callback 主要代表已投递或预测目标，不能当系统完成。
- 设计上不依赖目标必须有窗口，可用于验证空桌面；全屏、多屏仍需自己的实机证明。
- 它刻意缩短系统动画，不等于苹果原生动画完整保留；动画应作为单独体验指标。
- 初始化含全局 event tap，侧栏场景应拆出必要部分，按实际路线决定输入监听权限。
- 它不负责缩略图、精确窗口焦点、跨空间迁窗或创建/删除 Space。

依据：[发布记录](https://github.com/jurplel/InstantSpaceSwitcher/releases)、[固定源码](https://github.com/jurplel/InstantSpaceSwitcher/blob/2b883a995d1c81fbc6d75704372a6a0b546bb1ff/Sources/ISS/ISS.c)。

### 2. yabai 值得复用，但必须使用更新后的固定版本验证

[yabai CHANGELOG](https://github.com/asmvik/yabai/blob/master/CHANGELOG.md) 记录：7.1.19 增加 SIP 开启下的 space focus；7.1.25 恢复 SIP 开启下的窗口跨 Space 移动。不能继续采用“切 Space/移动窗口一律需要关闭 SIP”的旧判断。

macOS 27.0.1 有过切换失败报告，但上游最新 `b2dc8b4c892d74738a6e865d73048ed2dc3c9ed1` 已增加 Golden Gate 识别及部分通知、全屏、Mission Control 兼容更新。该提交北京时间为 2026-11-12 06:14。旧 issue 不能证明当前版本全面不可用，新提交也不能证明全面可靠。

跨 Space 迁窗可研究 `src/space_manager.c` 的 `space_manager_move_window_to_space` 与列表版本：优先检测 bridged window management operation，旧系统与 fallback 使用不同私有路线。函数没有在内部证明异步动作最终完成，Nearpane 必须独立回读窗口 membership。不能默认装入 Dock scripting addition，也不能自动走 SIP 修改路线。

“将一扇窗口移入另一 Space”与“移动/重排整个 Space”是不同能力；[当前 SIP 说明](https://github.com/asmvik/yabai/wiki/Disabling-System-Integrity-Protection) 对后者及创建/删除等仍列有额外条件。

依据：[近期提交](https://github.com/asmvik/yabai/commit/b2dc8b4c892d74738a6e865d73048ed2dc3c9ed1)、[固定迁窗实现](https://github.com/asmvik/yabai/blob/b2dc8b4c892d74738a6e865d73048ed2dc3c9ed1/src/space_manager.c)、[27.0.1 问题](https://github.com/asmvik/yabai/issues/2842)。

## 七、建议架构

1. **系统状态服务**：统一维护显示器、原生普通/全屏 Space、窗口身份与成员关系、焦点、Stage Manager 呈现。Space ID 以当前会话为界，序号只用于显示与执行时映射。
2. **内容服务**：ScreenCaptureKit 按窗口捕获、异步缓存与限频；活跃/可见区域优先。区分最新图、历史图、系统不可捕获内容。权限撤回与锁屏清理必须保留。
3. **原生动作服务**：切空间、聚焦窗口、迁窗分别独立；以当前能力选固定后端；异步返回 requested / confirmed / failed，而非把事件发送即视为成功。
4. **布局服务**：保留已有 WorkRect、渐进平铺、用户意图及恢复机制。跨 Space 移窗先确认目标归属，再执行用户指定的布局政策。
5. **侧栏**：真实空间为主层级，窗口内部位置/比例/遮挡反映系统状态；空间行点击与精确窗口点击共用目标身份、采用不同动作。系统自身切换也及时更新侧栏。

核心路径：用户点目标 → 解析稳定显示器/Space/窗口身份 → 切换请求 → 系统 current Space 确认 → 如需精确选窗则聚焦 → focusedWindow 与输入接收确认 → UI 提交完成状态。

快速点击采用明确的合并/取消策略。无关采样不能取消合法动作；用户已经转而操作其他目标时，不能执行迟到的旧焦点指令。

## 八、按真实成果推进的开发顺序

### 阶段 A：原生切换闭环

在原生工作分支最新基础上创建隔离实现分支。先比对固定 ISS 与最新 yabai 的可用路径，选一个最小后端接到真实侧栏。以用户当前系统为起点，SIP 开启，无需配置快捷键，验证已有的普通 A/B/C 与一个空 Space。先证明“点击正确到达”，不要先扩大设置与外围模块。

必须交付：可运行候选、实际目标与最终状态、焦点读回、至少一次真实端到端操作记录。成功后再继续下一阶段。失败必须定位具体 API、输入/映射或回读环节，并尝试有根据的替代方案，不能仅增加一页 BLOCKED 文档。

### 阶段 B：空间模型与用户可见操作

建立全部真实 Space 的模型；后台空间保持身份与有效缓存；接入具体窗口点击、同 App 跨 Space 窗口、原生全屏、多屏正确定位与连续操作。当前桌面卡片不得掩盖后台 Space 未实现。

### 阶段 C：窗口迁移与布局扩展

对固定 yabai 等路线验证指定窗口迁移；源与目标分别读回。将迁窗与平铺解耦，接已有窗口管理功能；最后实现创建、删除、8 窗溢出等依赖更高能力的规则。某项暂时受限只能限制相应操作，不应让全部窗口/空间切换失效。

### 阶段 D：最终安装与交付

使用最终签名应用和助手验证授权、升级后行为、重启、显示器变化、锁屏恢复。合并完成后更新单一当前状态页，保留关键脱敏证据。不能把隔离进程的授权、mock 成功或 CI 数量当最终安装版可用。

## 九、建议验收矩阵

以下是本次建议的工程验收，不是声称已经完成的测试。

| 场景 | 必须证明的结果 |
| --- | --- |
| 普通 A→B→A，含非相邻目标 | 系统 current Space 与目标一致，非仅侧栏高亮 |
| 空 Space | 无窗口锚点仍可显示、切换、返回 |
| 同 App 两窗分属不同 Space | 点击某一窗只聚焦该窗，正确接收键盘输入 |
| 原生全屏与普通 Space | 可达与返回正确；侧栏按现有全屏规则呈现 |
| 单屏 / 多屏 | 独立 Spaces 开启时，验证目标显示器正确切换及其他屏保持预期状态；关闭时，验证与原生操作一致的跨屏联动，不把正常联动判为误操作 |
| Stage Manager 开/关 | 不把 stage、可见性和 Space membership 混为一谈 |
| 快速连续选择及动画中改目标 | 无过冲、旧请求抢焦点或卡住；最后意图可确认 |
| 指定窗口跨 Space 迁移 | 迁移的是同一窗口，源/目标 membership 和布局可读回 |
| 权限缺失/撤销/恢复 | 清晰引导，权限恢复后可用；无虚假成功 |
| 系统重启/补丁/显示器插拔 | 状态重新识别，失效范围局部化，有明确版本支持结果 |
| 最终安装身份 | 与交付应用/助手/签名一致，无需把验收程序当产品 |

同时记录：点击到首个视觉反馈、系统 Space 到达、目标 key window 到位的各段耗时，CPU/内存与快速操作失败率。建议从重复 50 次基本往返和 20 次连续选择开始作专项压力验证；这些数字只是初始验收规模，不构成长期可靠性保证。性能用同机同场景原生操作作对照，不凭单次 175ms/805ms 历史截图数据承诺全部切换延迟。

## 十、可直接交给 Codex 的开工说明

你负责 Nearpane 原生 Spaces 与窗口调度整改。先阅读本审计，并从 implementation/host-foundation-20261109 最新 HEAD 核对差异；本报告基线为 7e0a2c1，个人安装记录为 5.18 Alpha（70）。在独立分支执行，保留既有语音、截图、资料及已完成窗口功能。

本轮首要产出是“侧栏点击真实原生 Space，系统到达目标，所选窗口能实际接收输入”。优先验证和复用 InstantSpaceSwitcher 的 ISS 小核心与最新 yabai 相关能力，固定来源和许可，不要求用户配置快捷键或默认关闭 SIP，不搬入不需要的全局监听和独立应用 UI。上游事件投递成功不等于完成，必须核对实际 Space 与精确窗口。

实现统一 Space/Window 状态服务和异步动作适配器，修复后台 Space 缺失、空桌面依赖窗口锚点、单一 build 硬门槛、常规刷新取消手势、无关兄弟窗阻断激活、移窗与全局平铺耦合的问题。不要只把只读能力 false 改成 true。

第一阶段先交付可操作的原生切换闭环，再补跨空间精确选窗、窗口迁移、多屏/全屏与布局政策。窗口卡片、合成诊断、mock 和单元测试数不能替代系统行为验收。测试使用可控的专用窗口和无私人内容的桌面；系统要求的账户授权不得绕过。

每个阶段以用户可执行的完整动作、关键实机记录和最终安装身份为完成依据，保存必要的脱敏证据与简短当前状态。失败要定位并尝试可依据的替代路径，避免反复扩展只读守卫却不实现产品后端。实机无法执行时准确记录具体缺口，不宣称通过。
