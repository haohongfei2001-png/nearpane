## WP1｜原生切换最小完整路径

### 交付

在真实 macOS 上使用已安装 Nearpane 的生产侧栏，列出受控普通 A/B 与空 Space，点选后系统到达目标。先证明准确性，再调顺动效；内部技术样本不等于最终体验通过。

### 实施

1. 固定 ISS v3.1 和 yabai 对照来源，记录许可与窄范围修改。建立后端探针，明确区分“读到空间”“事件发出”“系统到达”。
2. 将 ISS 核心状态与全局监听解耦；适配接口收 session/display/SpaceID，而非长期数字 index。
3. 提供最小正式状态服务与异步 NativeActionService；只读 Reader 不授予写能力。
4. 用系统 current Space 观察确认结果。失败区分映射错误、显示器路由、权限、投递、超时、结果不符。
5. 让生产侧栏调用该服务，替换当前永远 unavailable 的 NativeSpacesProvider 路径；保留旧观察降级作为可用信息来源。
6. 实测指定空 Space 和非相邻目标；不依赖该 Space 里先有一扇见证窗口。
7. 原生平滑 profile 和 ISS 快路径分别记录，不把后者自动作为默认动效验收成功。
8. 准备一条可重复运行的工程命令，驱动生产入口并输出实际 before/after。不把后端 CLI 成功当 UI 成功。

### 必须先改的现有文件

`Sources/NearpaneCore/WorkspaceActions.swift`、`HostSession.swift`、`DesktopObservation.swift`、`Sources/NearpaneUI/DesktopSurface.swift`、`NativeDesktopProvider.swift`、`Sources/CReadOnlySpaces/ReadOnlySpaces.c`。可以拆出新模块，但不要只在旧只读 DTO 加几个动作布尔值。

### 通过依据

ACCEPTANCE 的 S01/S02 最小样本有真实结果；明确还未覆盖的场景。若唯一候选失败，完成已定义对照与具体失败定位，不能直接声称“macOS 不允许”。

## WP2｜统一空间地图、预览与精确窗口选择

1. 合并 Host 主观察与 CurrentDesktopWindows 的重复库存，建立真实 Space/Window/Display 统一身份；事件驱动配合补漏。
2. 后台 Space 和空 Space 从系统 inventory 存在；把此前“未访问不显示”“后台窗口列表置空”的设计替换为真实成员与有效最近几何。
3. SCK 画面独立缓存与限频；窗口关闭、身份重用、权限撤回正确撤销，不因无关 revision 串图或闪空。
4. 空间行还原真实几何和遮挡；逐窗列表提供遮挡成员的直接访问；二者使用同一库存，保留 5.19 的工具后单列顺序、可读卡片尺寸及不透明前景。无图可保留真实窗口几何与图标；分区滚动保证全部 Space 导航可达。
5. 实现行背景 click、窗口 click、drag 三种意图；窗口点击跨 Space 后精确聚焦。
6. 去掉 allHere 兄弟窗全局前提，保留目标 PID/启动代际/windowID 和最终 focusedWindow 核验；最小化目标只恢复用户选中的那一扇。
7. 采用串行意图调度，未发出的选择可合并到最后目标；用户产生新意图后，旧回调不能抢焦点。
8. 暂时读失败有退避恢复；单窗失败不导致所有空间和内容全部永久降级。

代码重点：`DesktopPreview.swift`、`DesktopObservation.swift`、`SpaceInventory.swift`、`CurrentSpaceWindows.swift`、`CurrentDesktopWindows.swift`、`DesktopWindowGallery.swift`、`DesktopWindowSelection.swift`、`FocusCurrentWindow.swift`。

通过：S01–S03、W01–W03、V01。必须有实际浏览器/文档应用，不能只测自建 NSWindow。

## WP3｜真实迁窗与既定窗口管理

### 迁移

- 研究并采用固定 yabai 的 `space_manager_move_window_to_space` 对应无 SIP 修改路径，处理异步完成与系统实际 membership。不得默认启用源码里的 Dock 注入 fallback。
- 拖动源绑定窗口代际，目标绑定真实 Space。普通刷新不能取消手势；drop 时核验相关对象。
- 单窗移入目标不要求全部空间都可平铺；同 App 兄弟窗口保持原位。先确认迁移，后按现有管理政策排布。
- 部分结果分开报告；重试幂等，已迁移但布局失败不能盲目迁回。关闭/重建窗口不误投旧 ID。

### 布局与空间生命周期

- 按 D09/ADR-013 接回 1–8 窗、双窗比例、第三窗模板和历史恢复；以真实 AX/CG frame 验证，不能只移动缩略图。
- 接新窗独立 Space 默认、Join Existing、8 窗溢出、继续分割和排除规则。用户明确拖入的目标优先于默认路由。
- 创建/删除采用独立能力和真实系统后验。可先复用经验证的 Dock AX 操作，不能以假行/隐藏行代表系统新增/删除。
- 空来源清理只针对本次迁移/关闭导致的来源，确认完整空成员与系统保底桌面；最小化、未管理、全桌面驻留窗不是空。
- Hide、Docked/Floating、原生全屏、Quit 和重新启动沿用用户意图语义。避免两个控制器争夺同一 frame。
- 已有恢复记录保留，但不能把“实验结束还原焦点”变成用户每次切窗后的必做动作。

代码重点：`WorkspacePointerSurface.swift`、`WorkspaceActions.swift`、`WorkspaceAdmission.swift`、`ManagedWindowTiler.swift`、`OrdinaryWindowManager.swift`、`WorkspaceRecovery.swift`。

通过：D01、L01、C01、R02。创建/删除不足时基础能力可以如实交付，但相关条目仍未完成，不能将其删出本轮整体目标。

## WP4｜原生体验与系统组合

- 多显示器目标路由先验证，不根据鼠标所在屏猜。独立 Spaces 开/关分别按原生语义判断；设置切换需要注销时只在可控测试会话完成，不强制注销用户工作会话。
- 全屏用实际 App 覆盖；普通最大化不误判全屏；主侧栏与精简工具按既有呈现规则恢复。
- Stage Manager 是空间内部呈现，不当作 Space membership。与真实后台窗、最小化、重叠分别覆盖。
- 对照系统默认动效，修复闪黑、旧桌面闪回、非相邻逐段闪过、UI 阻塞、输入迟滞和快速连点过冲。
- 兼容策略覆盖本机实际 OS build，再验证支持矩阵；移除永久单 build 限制须以实测/probe 代替，不是直接删除检查。
- 性能记录包括全部 helper 和截图开销，保留已有正确功能；只为具体瓶颈增加回归或扩大压力测试。

通过：F01、M01、R01、R02、P01、N01 和支持矩阵。缺某个真实硬件组合不冒称通过，继续所有不依赖它的工作。

7. 更新本目录 STATUS 与顶层当前状态入口，整理旧过期说明；保留历史审计为历史，不反复追加互相矛盾的“当前”状态。
8. 创建/更新实现 PR 指向原生分支；只有必需场景通过才勾选完成并请求最终代码评审。
