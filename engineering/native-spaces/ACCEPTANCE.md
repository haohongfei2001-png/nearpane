# Nearpane 调度组正式验收合同

### 独立开发与窗口所有权

使用临时资料验证同应用两窗位于不同组、已保留成员所在的整个组保持原状、其余组可以切换。旧布局与引擎的并发写入必须争用同一窗口身份的文件锁。遇到无法解释的所有权时保留日志并拒绝调度。日常资料的原位安装门槛独立于以上开发与 CI。[窗口所有权回归](../verification/window-engine/stage-product/ownership.xml)

## 首次实体机单窗门槛

同机原位验收使用正式产品的单实例设置与已有授权。先核对标准安装签名并备份 App、资料、偏好与恢复记录。活动资料里尚有普通窗口恢复日志、StageGroup 所有权或 Spaces 写前记录时，保留原进程与日志。只有清单允许退出后才正常退出日常 Host，复核进程出生代已经结束，再原子交换包。依次核对新版 Host 的四项自读权限、同一进程的两次物理桌面与签名窗口读回、Spaces 自有面板及单窗、Corner Guardian 的真实恢复租约与单窗。任一未知结果停止新增写入。仅在候选进程、测试窗和后端所持资源均确认清场后换回原包，复核签名、资料及原版 Host 的权限。[同机入口与回执](../verification/window-engine/in-place-26A428/RESULTS.md)

每个后端分别记录 `BUILD_PASS`、`ABI_PASS`、`HOST_PERMISSION_PASS`、`TARGET_SCOPE_PASS`、`SINGLE_WINDOW_HIDE_RESTORE_PASS`、`PRODUCTION_QUALIFIED`。结果同时注明 Host 的签名标识、CDHash、源码 SHA、实际启动路径、PID、进程出生代和系统 build。辅助功能、输入监听与事件投递分别读取。启动探针和离线回归各有自己的收据。

1. 在 macOS 27.0（26A428）、SIP 开启的物理登录会话内，由同一个真实 Host 连续两次读取物理显示器、当前桌面清单、直接活动 ID、普通桌面类型、UUID 及签名夹具窗口的正反向归属。记录两读间的 AppKit Space 变更通知。全屏类型 4、缺 UUID、会话切换、没有登记窗口或两向归属无法互证都阻止窗口写入。
2. Corner 使用一扇签名普通窗口，记录初始几何与焦点、停放、真实鼠标按下/拖动/释放的接收者、旁窗与 Dock、还原后两次 AX/WindowServer 读回。分开验证 Host 的在场写入权和原 Guardian 的恢复资格。一次失败即停止。
3. Spaces 先在同一 Host 用自有透明非激活面板验证创建临时 Space、移入、还原、关闭面板、销毁临时 Space 和清单还原。通过后才进行一扇第三方窗的移入与还原，每步核对独立正反向归属。
4. GitHub CI 必跑 Rust、Swift 和生产 C ABI；可选托管只读报告独立保存。该环境缺少普通桌面时记录 `BLOCKED`。两后端的正式单窗和后续整组验收均要求指定物理环境。[本次原始收据](../verification/window-engine/first-window-26A428/)

## Rust Window Engine 的验收入口

两个后端共用同一份正式 Host 合同。按单次 A→B→C→A、10 次、50 次顺序验证整组。三项均通过后，在同一台实体 Mac 上按每方向至少 100 个有效样本与 Apple 台前调度配对，最后才进入 1000 次压力验收。单窗夹具、静态库回归、成功的系统调用和隔离开发 Host 的权限预检各自单列。任何输入安全失败或清理状态未知均阻止晋级。 [门槛与原始收据](../verification/window-engine/RESULTS.md) · [性能合同](../research/NEARPANE-STAGEGROUP-PERFORMANCE-STANDARD.md)

## 当前单次隔离门槛

使用两个签名且已注册的普通 App。一个 App 提供两扇分别归入不同组的文档窗，另一个提供第三组、独立旁窗、用户预先最小化的窗及辅助面板。系统 Stage Manager 全程关闭。独立记录每扇窗的进程出生代、CGWindowID、AX 身份、AX/CG/AppKit 矩形和可见性、前台焦点、真实输入唯一接收者、Dock 窗口图块及退出清理。捕获仅限临时登录环境。

- 一次 A→B→C→A 全部通过后再做 10 次和 50 次。正式 Host 的核心成绩还需要通过生产侧栏，包含双窗组合往返、精确键盘输入、原生桌面隔离及干净还原。
- 最小化须观察 Dock 的基线、每组切换和清理后计数。用户已经最小化的窗保持原样。角落停放须记录系统限位后的残条、遮罩实际覆盖和真实鼠标接收窗。即使画面被遮住，收到点击或窃取键盘焦点仍为 FAIL。
- 墙纸测试使用现有 Apple 设置点击两次。独立确认窗口移开、期间调度暂停、窗口原几何以及恢复后的可派发状态。找不到实际系统桌面或未见原生动作时如实记录。
- 原始证据分别列出夹具、生产模块与正式安装 Host。出现单次失败或可能已写但结果未知时留存原始输入输出，冻结扩大测试。 [可下载的原始矩形、输入、收据与录屏](../verification/stage-groups/5.22-90/isolation/RESULTS.md)

从 PR #15 的 StageGroup 重定向开始，本合同覆盖台前调度替代体验。验收主体为标准安装路径中的签名 Nearpane；观察器负责隔离夹具、物理输入与独立读回。每项记录候选 SHA/CDHash、OS build、屏幕 UUID/缩放、已有权限、执行者、单调时间、原生 Space 只读指纹、动作和清理。仅使用隔离文档，不发送用户消息。R4 保持冻结。

| 合同 | 通过条件 |
| --- | --- |
| SG0 每屏目录 | 同一原生桌面内至少两个组，一组含两款 App；每窗只属一个组。正式 Host 重开恢复目录、相对布局、活动引用。窗号复用不得误绑；物理双屏列表、断开/重连独立核对。 |
| SG1 完整切组 | A→B→A 从生产侧栏执行；双读 AX、CG、测试 App 回执、旁窗与系统归属。原组保留文档、目标全体显示、唯一输入进入指定窗。验证撤销、超时、手动改变、崩溃重开、退出。单窗最小化、PID、缩略图变化不计整组通过。 |
| SG2 组内精确选窗、组合 | 同 App 两窗 10 次唯一输入，AXFocusedWindow、CGWindowID 与两份测试文档对应；可跨 App 双向本屏拖放，两窗始终同一组；切组往返核对布局。旧候选作为回归参照。 |
| SG3 组预览 | 一组一张卡，两扇动态窗分别有可归属的画面，图像、前后关系、几何与落点正确。测首帧与同步，分开列实时、历史、缺图、丢帧。 |
| SG4 系统互操作 | Apple 手势、Mission Control、App Exposé、Spaces 增删排序与切换均由系统完成。独立观察 Nearpane 原生写为零，无全局设置变化。原生全屏/Split View 只核对适配；系统台前调度开启时 Nearpane 退出窗口调度。覆盖单/多屏、共享 Spaces 与生命周期。 |
| SG5 工具 | 已有授权隔离会话中验证截图到真实草稿、零发送；翻译气泡与词本重开，语音首尾/最终稿，隐藏预算及恢复。 |
| SG6 分发、速度 | 相同负载下与原生 Stage Manager 对照切组及可输入时间、退场、长帧、内存和隐藏能耗。签名、公证、Gatekeeper、干净首启、更新与回退分别对同一包验证。 |

**PASS** 仅适用于注明的主体和场景。**FAIL** 为已证实违反合同。**UNKNOWN** 为可能已投递或读回不足。**BLOCKED** 为先决条件缺失。**NOT_RUN** 为未执行。对可能发生的写入先核对持久状态；不重复投递。单元测试、托管 WindowServer 及干净包静态验签分别计账。
