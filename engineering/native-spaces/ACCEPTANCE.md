# Nearpane 调度组正式验收合同

## Corner 的单窗口可行性边界

实机验证退场画面时，在同一显示器的角落采样实时壁纸、壁纸与受控窗口、以及含正式遮挡面板的实际窗口叠放。所有样本只包含登记过的窗口和 Apple 签名壁纸。前后壁纸逐像素稳定、移除面板的采样能识别受控窗口、包含面板的采样还原整块壁纸，才算一次视觉通过。窗口顺序、真实键鼠收件及恢复责任独立判定。观察器自己创建的标记只验证测量方法；单窗和整组资格必须使用签名普通应用的真实窗口。

有窗口需要退场时，先检验该显示器的可用角落，再核准布局、焦点和首次窗口写入。其他系统面板、桌面图标层或实际 Dock 栏已占满预定区域时，应返回占用原因，并保留原工作集合与焦点。正式 Host 的 R4 侧栏须通过本进程面板身份、几何和层级核对；侧栏真实鼠标收件另行验收。

活动工作集合失去普通桌面读回、显示器拓扑改变或系统接管时，撤回现有调度意图并保留恢复记录。恢复须重新确认原显示器、原普通桌面及原会话，随后按窗口逐一核对所有权、原始位置和输入。真实切走及返回的试验应保留前后台窗口和焦点读回。

| 验证对象 | 最小条件与可得结论 |
| --- | --- |
| 内部只读生存性 | 公证票据不是 AX 读取或内核退出观察的参数。正常获系统准入的内部签名 Host 可在隔离 GUI、私有资料和受控窗口中验证子进程行为。按实际签名、权限责任和系统 build 记账。更换签名、父进程或会话所得结果只适用于那个主体。26A428 上，内部签名 Host `1b03f10` 已完成退出后原窗口的双读。标准安装版另行验收，既有系统拒绝记录保留。[退出后实机记录](../verification/window-engine/guardian-survival-26A428/internal-host/05-confirmed-original/session.json) · [签名开发 Host](../verification/window-engine/target-26A428/signed-development-host.json) · [正式包回执](../verification/window-engine/guardian-survival-26A428/admission-1329/result.json) |
| 本机正式 Host 只读交接 | 读取既有 AX 引用在技术上无需普通桌面。现有监督器还要退出唯一日常 Host，创建普通夹具、证明同桌面归属并将前台焦点交还。因此该入口在退出前要求普通 Space、原焦点及静止 HID 双读。保留该约束。若未来已有系统接纳的内部镜像和专用会话，可复用同一 Guardian 协议验证只读交接，自行记录真实主体；正式 Host 的权限结论仍须由其自身给出。[监督器](../../scripts/acceptance/window-engine/host/run-installed-stage.py) · [Host 登记](../../Sources/NearpaneHost/StageEnginePackageProbe.swift) |
| 真实遮挡画面 | 仅比较同一普通桌面、同一物理显示器上由系统实际合成的产品面板和 Apple 壁纸。必须限定确切窗口、阴影区域、像素尺寸和时间范围，读回前后核对身份与层级。验收用面板退出后须连续两次从 WindowServer 消失。单独通过此项只证明面板画面；第三方受控窗口的实际命中及恢复仍须独立验收。 |
| 真实窗口写入 | 只读双读 PASS 之后，先证实指定 Guardian 在正常退出和异常中断时能取得且履行持久恢复责任。再限一扇签名普通应用窗，核对画面、按下/拖动/释放、键盘落点、同应用旁窗、另一应用、Dock、原生归属和精确恢复。任一安全项 FAIL 或 UNKNOWN 即停止派发，保存原始结果并处理已有责任。只读生存不能证明可写。 |
| 正式分发 | 用将交付的包验证公证、装订、系统策略、干净安装、升级与回退。此门槛独立于产品源码开发、离屏交互测试和原有可用功能。 |

限定一次有新依据的单窗试验。缺少已接纳镜像或可恢复环境时保持 BLOCKED；实测出现输入穿透、错窗、归属改变或恢复失效时，对该机制与 build 作出 NO-GO。取得能够解释并改变失败条件的新证据前不重复实验。仅在单窗安全合同成立后开放隔离整组验证。

正式执行器可先在隔离签名 Host 中只读登记测试窗。须将两次 AX、WindowServer 几何及双向原生归属与窗口所属应用的两次读数交叉核对。收据单列窗口读取、停放资格和实际隐藏恢复。对真实窗口的鼠标接收者、键盘落点和恢复责任另行实测。

遇到 Host 在停放后退出，Guardian 须有原执行器的真实停放结果、Swift 已落盘的同一窗口所有权、匹配的内核退出与进程出生代，并独立复核原 AX 对象。分别覆盖所有权提交前中断、提交后确认包丢失、确认回复丢失和进程映像被替换。只有实际恢复并再次读回原窗口才能登记窗口恢复通过。

退场前按完整残边和阴影验证对应显示器的材质。采用显示器合成时只接纳同一普通桌面、同一显示器上已核验的 Apple 壁纸窗口；任何透明像素或失效来源都不能支持遮挡。材质读回与真实窗口遮挡、完整鼠标手势及键盘接收者分别计分。

## 同桌面窗口操作

正式生产流程沿用 Display → StageGroup → Window。原生桌面只读。单窗实验必须以同一授权 Host、物理显示器、普通 Space、可交还的原 AX/CG 焦点及无新 HID 输入连续双读开始。全部夹具另需逐窗核验正反向归属和原几何。这里只被动观察系统是否正在接管。Mission Control 的展示、桌面条及收起属于独立系统兼容项。历史临时 Spaces 迁移单独保留为研究。

1. 用已注册的两款签名应用记录目标、同应用兄弟和另一应用窗口的独立身份、文档、显示器、焦点、布局及 Dock。
2. Guardian 持有确切对象，恢复责任持久化并获确认后，仅停放目标窗。正式 Host、独立观察器及夹具从 AX、WindowServer、画面、鼠标完整手势及键盘文档响应核对实际隔离。
3. 原生归属、次序、窗口集合、前台收件人及所有旁窗必须在每个阶段与基线相符。原所有者归还目标后双读几何、身份、焦点和资源，核对零遗留租约。
4. 单窗实机资格只开启隔离的整组验收。单次、10 次、50 次、生命周期及同机性能依次出具独立收据。通用生产能力以完整产品合同为准。

连续点选时，在准备回执后、可见性操作已发出后及活动组写盘前分别插入下一次侧栏选择。确认旧请求停止派发，只在同一所有者完成窗口、旁窗、焦点和几何的独立读回后交接已确认的效果。改变一个成员的租约、旁窗几何或焦点所在显示器，须保留待核实责任。分别记录最后一个有效选择的键盘收件窗口、原组还原的布局，以及活动组实际写入的时刻。[事务与内核收据](../verification/window-engine/stage-switch-admission-26A428/result.json)

[权威产品状态](STATUS.md) · [技术裁决](../research/NEARPANE-WINDOW-VISIBILITY-FINAL-ARCHITECTURE.md) · [归档的原生 Spaces / Mission Control 专项合同](https://github.com/haohongfei2001-png/nearpane/blob/7d099c7/engineering/native-spaces/ACCEPTANCE.md)

正式 Host 支持 `guardian-survival` 只读诊断。监督器以 `--desktop-receipt` 接受新鲜的普通桌面、原焦点及 HID 观察。它在同一 Host 的挑战应答前向内核登记 NOTE_EXIT 和 NOTE_EXITSTATUS，要求原进程代际消失且退出码为 0。Guardian 保留签名夹具的原 AX 引用，在 Host 退出后双读同一窗口、几何和原生归属，以原子重命名交付只读 JSON。监督器独立核对收据、夹具与 Guardian 退出以及日常 Host 和配置。明确的退出后权限拒绝、采样错误或已证实的几何变化为 FAIL，读数矛盾或不全为 UNKNOWN。此单项 PASS 只表示跨进程退出的读取能力。恢复租约、真实停放、输入隔离和还原分别验收。

## 历史隔离实验合同

使用两个签名且已注册的普通 App。一个 App 提供两扇分别归入不同组的文档窗，另一个提供第三组、独立旁窗、用户预先最小化的窗及辅助面板。系统 Stage Manager 全程关闭。独立记录每扇窗的进程出生代、CGWindowID、AX 身份、AX/CG/AppKit 矩形和可见性、前台焦点、真实输入唯一接收者、Dock 窗口图块及退出清理。实机证据只采集隔离测试窗口。含私人窗口的屏幕仅记录必要的数值身份与布局，图像证据仅取测试窗口。

- 一次 A→B→C→A 全部通过后再做 10 次和 50 次。正式 Host 的核心成绩还需要通过生产侧栏，包含双窗组合往返、精确键盘输入、原生桌面隔离及干净还原。
- 最小化须观察 Dock 的基线、每组切换和清理后计数。用户已经最小化的窗保持原样。角落停放须记录系统限位后的残条、遮罩实际覆盖和真实鼠标接收窗。即使画面被遮住，收到点击或窃取键盘焦点仍为 FAIL。
- 墙纸测试使用现有 Apple 设置点击两次。独立确认窗口移开、期间调度暂停、窗口原几何以及恢复后的可派发状态。找不到实际系统桌面或未见原生动作时如实记录。
- 桌面文件与图标单独验收。在托管隔离桌面使用生产设置适配器选择「点击空白墙纸时显示」，用同一份测试文件的像素验证普通窗内点击后隐藏、空白墙纸点击后显示、返回应用后再次隐藏。可见图标应从空白命中中排除。结束时还原「在桌面上」原值并移除测试文件，记录实际回读。正式安装版与托管夹具分别报告。
- 原始证据分别列出夹具、生产模块与正式安装 Host。出现单次失败或可能已写但结果未知时留存原始输入输出，冻结扩大测试。 [可下载的原始矩形、输入、收据与录屏](../verification/stage-groups/5.22-90/isolation/RESULTS.md)

## 正式产品合同

验收主体为标准安装路径中的签名 Nearpane。观察器记录隔离夹具、物理输入与独立读回。每项记录候选 SHA/CDHash、OS build、屏幕 UUID/缩放、已有权限、执行者、单调时间、原生 Space 只读指纹、动作和清理。输入验证使用隔离文档。

| 合同 | 通过条件 |
| --- | --- |
| SG0 每屏目录 | 同一原生桌面内至少两个组，一组含两款 App；每窗只属一个组。正式 Host 重开恢复目录、相对布局、活动引用。窗号复用不得误绑；物理双屏列表、断开/重连独立核对。 |
| SG1 完整切组 | 从生产侧栏执行 A→B→C→A。每次核对 AX、CG、测试 App 收件、旁窗和原生归属。原组保留文档，目标成员全部显示，唯一输入进入指定窗。末次回到 A 时再次核对完整布局、焦点和文档。另验撤销、超时、手动改变、崩溃重开和退出。 |
| SG2 组内精确选窗、组合 | 同 App 两窗 10 次唯一输入，AXFocusedWindow、CGWindowID 与两份测试文档对应；可跨 App 双向本屏拖放，两窗始终同一组；切组往返核对布局。旧候选作为回归参照。 |
| SG3 组预览 | 一组一张卡，两扇动态窗分别有可归属的画面，图像、前后关系、几何与落点正确。测首帧与同步，分开列实时、历史、缺图、丢帧。 |
| SG4 系统互操作 | Apple 手势、Mission Control、App Exposé、Spaces 增删排序与切换均由系统完成。独立观察 Nearpane 原生写为零，无全局设置变化。原生全屏/Split View 只核对适配；系统台前调度开启时 Nearpane 退出窗口调度。覆盖单/多屏、共享 Spaces 与生命周期。 |
| SG5 工具 | 已有授权隔离会话中验证截图到真实草稿、零发送；翻译气泡与词本重开，语音首尾/最终稿，隐藏预算及恢复。 |
| SG6 分发、速度 | 相同负载下与原生 Stage Manager 对照切组及可输入时间、退场、长帧、内存和隐藏能耗。签名、公证、Gatekeeper、干净首启、更新与回退分别对同一包验证。 |

**PASS** 仅适用于注明的主体和场景。**FAIL** 为已证实违反合同。**UNKNOWN** 为可能已投递或读回不足。**BLOCKED** 为先决条件缺失。**NOT_RUN** 为未执行。对可能发生的写入先核对持久状态；不重复投递。单元测试、托管 WindowServer 及干净包静态验签分别计账。
