# Nearpane 的调度组产品定义

Nearpane 为 Apple 台前调度提供 R4 交互界面。用户通过透明框架内的平面卡片选择、组合和恢复原生工作集合。Apple 管理真实窗口的进出、布局、焦点及最小化。Saytile 语音输入、Riftlet 截图暂存和真实窗口预览继续共用 R4 侧栏。验收以真实窗口的显示、输入接收者及恢复结果为准。

本文件确定产品责任。技术条款按以下顺序解释，执行进展统一记入[工程状态](../native-spaces/STATUS.md)。

1. 本产品定义。
2. [窗口可见性最终架构](NEARPANE-WINDOW-VISIBILITY-FINAL-ARCHITECTURE.md)。
3. [Rust 复用裁决](NEARPANE-STAGE-MANAGER-REUSE-DECISION.md)。
4. [实施与晋级顺序](NEARPANE-STAGE-MANAGER-CODEX-INTEGRATION-PLAN.md)。

## 5.22 窗口隔离合同

每块物理屏在当前普通桌面上按系统实际成员显示集合，一组一张卡。新窗加入已有集合或独立成组时，R4 跟随系统结果与用户的多窗口设置。Sheet、Popover 和辅助面板随所属窗口处理。启用前已经最小化至 Dock 的窗口保留原状。切组结束时仅目标组成员留在工作区，原组布局与文档状态可恢复。非活动窗收到输入、旁窗被改变或 Dock 随后台组数增加窗口图块，均判为失败。

同屏精确选窗和已验证的同屏分屏继续可用。正式侧栏的整组隔离尚未取得准入。系统的“始终允许点击墙纸显示桌面”由「桌面与程序坞」管理。Nearpane 在窗口移开期间让渡布局，并在恢复后重新核实窗口。桌面项目可见性单独由 macOS 设置。 [隔离对照与原始结果](../verification/stage-groups/5.22-90/isolation/RESULTS.md) · [Apple 桌面设置](https://support.apple.com/en-gb/guide/mac-help/mchlp1119/mac)

「Nearpane 设置 → 本屏窗口 → 桌面文件和图标」提供「点击空白墙纸时显示」和「始终显示」。用户主动选择后，Nearpane 打开系统的「显示项目」并核实「在桌面上」复选框；macOS 为当前账户保存选择并响应桌面点击。文件、图标、部件及其位置均由系统维护。「点击墙纸移开窗口」保留独立的系统设置。 [Apple 桌面项目显示说明](https://support.apple.com/en-ie/guide/mac-help/mchl534ba392/27/mac/27)

本裁决适用于 PR #15 的原生 5.22（90）工程。R4 是用户组织和选择工作集合的统一入口。优先复用已启用的 Apple 台前调度，由系统实际切换窗口集合。用户在一块物理屏上安排几个工作集合，每个集合可以容纳不同应用的窗口。固定的 R4 卡片、原生材质、托盘与语音设计继续沿用。

## 三个对象

| 对象 | 用户看到的行为 | 身份与边界 |
| --- | --- | --- |
| Display | 内屏和每块外屏各有组列表、上次确认的活动组及布局 | 使用物理显示器 UUID。位置、主屏次序或缩放改变时重新计算本屏工作区。镜像或身份不明时暂停写入。 |
| StageGroup | 一个集合一张卡。单窗使用窗口画面，多窗按真实矩形与前后顺序合成一张卡 | Nearpane 为持久化用户分组分配 UUID。Apple 路线根据当前屏的系统成员读数呈现集合；卡片次序与系统 Space UUID 都不能充当组身份。每个活窗在本屏只有一个当前集合。 |
| Window | 同一应用的两个文档可分属不同组；可精确选到组内一扇窗 | 关联具体的进程代际、CG 窗号和窗口存活见证。逐窗绑定 PID、进程出生代、CGWindowID、原 AX 对象和实时存活见证。输入标记由目标文档独立确认。 |

## 系统责任

| Nearpane 的侧栏与工作集合 | macOS 的系统操作 |
| --- | --- |
| 在本屏呈现工作集合，登记用户选择和布局。优先从 R4 精确激活系统组内目标，再核对整组。组编辑、并排和布局恢复依照各自取得的资格开放。 | 三指向上 Mission Control、向下 App Exposé、左右切 Spaces、系统快捷键和触发角；原生桌面的创建、删除、选择和排序；系统全屏、原生 Split View 和系统桌面动画。 |
| 在允许的当前普通桌面显示可执行的调度组。已有原图可以作为有明确状态的历史预览。 | 用户切换桌面后系统发出通知。Nearpane 只重读当前显示器、窗口归属和布局，撤销旧点击与拖动。 |
| 系统台前调度已开启时，R4 优先跟随当前显示器的真实台前调度集合。系统负责成员退场与还原，Nearpane 收集切换前后证据。语音、截图等独立模块继续工作。 | 台前调度开关、Dock 和 WindowManager 全局设置均由系统及用户管理。 |

Apple 说明台前调度支持跨应用编组、组内摆放与重叠，切回组时成员共同显示，并说明“显示器具有单独的空间”与系统台前调度可用性相关。官方资料没有给出可供第三方持久化的系统组身份或组与 Space 的一一映射。用户可见原生桌面的数量、次序和当前桌面全部由 Apple 管理。技术路线 B 只允许在独立验证后使用 Nearpane 自有隐藏私有 Space，条件见[窗口可见性架构](NEARPANE-WINDOW-VISIBILITY-FINAL-ARCHITECTURE.md)。原生桌面变化使原操作失效，已有组 UUID 和用户布局继续保存在显示器目录。Nearpane 以自己的成员记录保存用户意图，以新鲜的系统读数决定该刻能作用于哪些真实窗。手势、全屏、原生分屏保持原来的系统入口。 [Apple 台前调度指南](https://support.apple.com/en-ie/guide/mac-help/mchl534ba392/27/mac/27) · [AppKit 显示器 Spaces 设置](https://developer.apple.com/documentation/appkit/nsscreen/screenshaveseparatespaces)

## 最小化和系统边缘

产品要求黄色按钮、⌘M、菜单、配置为最小化的标题栏双击以及应用自身的普通单窗最小化，最终都在 R4 呈现可恢复的 Stage 卡片。Apple 路线由 macOS 执行窗口动作，逐窗 AX 通知触发侧栏核对实际 Stage 成员。验收须从卡片恢复同一扇窗并核对旁窗及 Dock。Option 批量最小化、⌘H、⌘Q、关闭窗口和启用前的 Dock 窗口分别保持各自的系统行为。关闭「显示最近使用的 App」后，移到屏幕左边缘仍可临时呼出最近 App。R4 需要实测原生栏隐藏与临时出现时的操作命中。[Apple 台前调度指南](https://support.apple.com/en-ie/guide/mac-help/mchl534ba392/27/mac/27)

## 用户操作及结果

1. 首次观察到本屏当前普通桌面的合格单窗时可以显示一张单窗卡。空桌面留白，单纯发现一个原生 Space 不产生卡片。
2. 点击一个组时恢复该组可执行的真实成员、布局和首选焦点；保留上一组的窗口、文档和用户原有最小化状态。只有整个可见集合、焦点和旁窗均得到验证后，才确认新的活动组。
3. 用户选择组内某窗时，沿用同屏精确选窗。点击组合画面的空白处代表选择整组。组合内成员可单独选择、加入另一组或移出为单窗组。
4. 自定义分屏把两个普通窗口放入同一组，按本屏工作区并排，保存比例及次序。再次选择该组可恢复组合。苹果原生 Split View 的两窗几何仅以系统提供的布局展示。
5. 组中任何必需成员在其他原生 Space、显示器断开、全屏、身份待定或权限不可用时，保留组定义，暂停整组操作。在用户通过系统入口返回且重新核验后恢复资格。另屏、未纳管窗口和同应用的兄弟窗都应保留原状。
6. 退出、锁定、睡眠、系统接管、手动移动/最小化、关闭文档或应用重启时，撤销过期意图。恢复只针对 Nearpane 自己已记录、能再次唯一确认且仍处于预期状态的改变。

发布证明采用正式安装的 Host、隔离测试资料及独立系统读回。单张缩略图变化、应用前台 PID、单窗最小化或旧候选的成功次数均不能代替新版本的完整切组。 [架构与差异审查](NEARPANE-STAGE-GROUP-ARCHITECTURE.md) · [当前实施计划](NEARPANE-STAGE-MANAGER-CODEX-INTEGRATION-PLAN.md)
