# 调度组实施顺序与回滚

5.22（90）沿 PR #15 增量开发。文档、代码、实机结果按阶段提交；R4 设计、Riftlet/Saytile 资料和已登记的签名回退包继续沿用。所有阶段区分源码实现、隔离 WindowServer、正式安装版和设备覆盖。

| 阶段 | 实施范围 | 真实系统验收 | 回滚 |
| --- | --- | --- | --- |
| P0 目录与归属 | 先撤销旧 Space 写入口。NearpaneCore 定义每屏目录、组/成员 UUID、布局和版本化文件；NearpaneUI 将当前普通窗与目录绑定，使用活动资料代单写者。 | 在同一普通 Space 建立两个组，其中一个跨应用，实际窗口身份与显示器 UUID 可读回；Host 重启后组顺序、成员槽位和布局保留，旧活体授权失效。物理双屏独立，断开保留，重连核验。 | 停止目录写入，上一版可忽略该文件；保留原文件、副本与版本。 |
| P1 成员与切换 | 每次只转移选中的成员；接入每屏操作队列、写前日志、公开单窗可见性适配器、失败补偿与恢复。先做单次受控显示/退场/还原，再扩至多组。 | 两款 App，至少三扇窗与一个非参与窗，含同应用兄弟跨组。A→B→A 两次读回整组可见集合、旁窗、原焦点、实际输入及 Native Membership。中途退出、强退两处、手动最小化和切走桌面均须能恢复或留存未知，不重放。 | 先偿还已确认的停放，保留未决日志；停止新切组，可继续逐窗查看和精确选窗。 |
| P2 焦点与自定义分屏 | 复用 `DesktopWindowSelection` 和 `DesktopAutomaticTiling`。对两窗执行同屏拖入、双向排布，真实双窗几何确认后提交一个组与相对布局。 | 复用旧包 10/10 的验收器，在新包上做同应用交替输入；跨应用拖入后只有一张组合卡。切走再返回，两个真实窗在正确槽位，键入唯一标记。 | 只撤销事务拥有的改动，保留原同屏选窗和旧版已验收收据。 |
| P3 组合预览 | 沿用 gallery 的逐窗取像、权限、代际和历史淘汰。按实际几何、遮挡和顺序合成组预览。 | 两个同时变化的有色测试窗在同一张卡逐窗读像素。分别记录首帧、历史片、缺图、退场和权限撤回，异屏/异代旧图不可显示。 | 停止对应的流、清空瞬时缓存，保留逻辑组及原图资格记录。 |
| P4 被动系统适配 | 监听当前原生 Space、台前调度、Mission Control、全屏/Split View、拓扑与睡眠通知；能力不明时让渡。 | 外部在隔离会话使用 Apple 入口，Nearpane 零原生写、零手势投递。全屏/原生分屏、共享/独立 Spaces、另一物理屏、锁屏唤醒和系统台前调度开关分别验收。 | 撤销旧选择、停写、重采样。禁止设置 Dock 或 WindowManager。 |
| P5 工具与生命周期 | 复用 Riftlet 附件链路、Saytile 音频和最终稿、翻译/单词本、资料/import/退出。 | 正式安装版本、隔离资料、已有授权浏览器真实草稿、零发送；冷启动首句、实际最终稿、重启恢复和隐藏预算分别留收据。 | 按模块停止，保留原资料、权限和写锁。 |
| P6 性能与交付 | 比较同屏 Stage Manager 组切换的输入、首帧、所有成员恢复、帧间隔、资源消耗。完成正式签名、公证、干净安装、升级和回退。 | 同机同屏同组负载，列样本分布和缺项。安装包、签名与票据对同一摘要验收，真实启动与回退保持资料可读。 | PR 保持 Draft；只提供有签名来源的内部候选，使用已验签旧包及资料代恢复。 |

P0/P1 的命名只在这份新路线中使用。旧 Dock 手势、原生迁窗和原生选择菜单为 OUT_OF_SCOPE。先交付无原生写的路径与独立目录，P1 从旧停车失败中提取旁窗保护用例。只有完成目标系统版本的真实窗口资格验证，才能向该环境开放物理切组。各阶段的正式判定见[验收合同](../native-spaces/ACCEPTANCE.md)，代码归属见[模块路径图](IMPLEMENTATION-PATH-MAP.md)。
