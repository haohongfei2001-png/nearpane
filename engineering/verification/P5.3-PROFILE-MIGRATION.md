# P5.3 Alpha 资料版本、选择性导入与回退

P5.3 从空白资料启动。用户在 Settings 中选择旧版，预览文字、截图或设置，确认后切换到新建的资料代际。勾选的类别整体替换，其他类别取自切换前的当前资料。P5.2 的基线为 `42ed7b1c7a29e9ce94bb424231f8a911cd10817c`。领域投射与附件保护提交为 `4107ea2a832c1ee8eff5d443998a1d8aafd49343`，选择、排他所有权与恢复提交为 `6beb1b207b5b196ff364b36ba53bf017268d8274`。[Settings 入口](../../Sources/NearpaneHost/ProfileImportSettings.swift) · [成品交付](P5.3-ALPHA-DELIVERY.md)

## 身份和版本

| 对象 | 当前契约 |
|---|---|
| 可执行身份 | 新普通 Alpha 的 Bundle ID 和本机构建的签名标识为 `com.holdsnow.nearpane.alpha`。使用 ad hoc 开发签名。旧版按各自的版本化身份启动和读写资料。 |
| 资料容器 | 新版使用 `~/Library/Application Support/Nearpane Alpha Profiles`。首次生成空代际，再一次性发布容器。每次运行先取得 `writer.lock`，核对 `profile-index.json` 中的 `format: 1` 和活动 UUID，再打开 `generations/<UUID>`。代际标记为 `Nearpane P5.3\n`。资料契约版本与 App 版本分别判断。 |
| 旧版来源 | Settings 明列 P4.8、P4.8.1、P4.9、P5.0、P5.1、P5.2。用户选定版本后才检查对应旧 App 是否已退出。其 Bundle ID 后缀分别为 `p48`、`p481`、`p49`、`p50`、`p51`、`p52`。助手核对同级的 `Nearpane Alpha P…` 目录名及其 `profile.version`，路径或版本不符即拒绝。 |
| SQLite | Saytile 的 `Nearpane/Voice/Saytile.sqlite` 要求 `user_version=5`，Riftlet 的 `Riftlet/queue.sqlite` 要求 `user_version=4`。导入还分别比对固定领域的表、索引与约束指纹，运行完整性及外键检查。未知或更新的 schema 需由能理解该结构的版本处理。 |
| 权限主体 | 新 App 和旧 App 的权限需分别核对。当前 ad hoc 签名不保证后续构建延续相同系统授权。TCC、Keychain、目录安全书签不授予新代际能力。新版本按正常权限流程启用所需功能。 |

当前导入使用的两个 schema 的 SHA-256 分别为 `034c18279d1b3aaffc7580f07c568baf34809cceba5fc4f95469d96ccd4b76e9` 和 `04b043caf5f2b592719c1a5a7ef57e876ea2bb874462b01c6254a493d739f096`。对 SQLite 的导入检查只在副本运行。助手将数据库和 WAL 一起复制，然后在私有副本上核对 WAL 帧数和完成的 checkpoint。残缺 WAL、未收口的回滚日志和存在歧义的文件链接都会阻止切换。[Host 初始化](../../Sources/NearpaneHost/CandidateProfile.swift) · [整份资料的写锁](../../Sources/NearpaneCore/ProfileGeneration.swift) · [schema 检查与领域规则](../../scripts/profile_domains.py) · [候选签名](../../scripts/build-candidate.sh)

## 用户选中的内容

| 类别 | 新代际使用的数据 | 保留在原版或需重新确认的项目 |
|---|---|---|
| 旧版 Saytile | 录音记录的文字部分、修订 UUID、用户首选修订、编辑草稿及冻结修订。先校验首选修订确属该条记录。 | 外部旧版本的原音、识别运行历史及云端授权仍可在旧版取得。新代际清除活动录音和 attempt，排队或执行中的识别改为取消。 |
| 本版 Saytile | 用户未勾选文字或从本版备份回退时，保留本代原音、块索引、文字及可核对的本地历史。复制后按文件核验原音 SHA-256。 | 正在录音、活动识别或待完成擦除时，要求先处理。恢复后撤销云端授权、外部绑定及旧输入范围，未确认的派发保留为待核对，已有失败或排队的识别不得自动重试。 |
| 截图与附件 | 逐张核对 UUID、媒体名、字节数、SHA-256、收录日志和关联操作，保留顺序、状态、操作、补偿及 START 历史。UNKNOWN 和 FAILED 继续保有原状态。 | 出现进行中的附件操作、待导入媒体或不一致记录时拒绝。旧目标只保留为历史字段；新代际的已尝试资产 UUID 受禁止重放标记保护。切换前本代积累的禁止标记一并延续，原草稿和旧 claim 不能触发新输入。 |
| 显示和模块 | 保留首选显示器 UUID、每屏 Docked/Floating、已存尺寸和位置、手动隐藏、模块启停和固定设置、可识别的截图模式与动效。现有 Host 配置解码器校验并重新编码新配置。 | 临时展开状态随启动重新计算。遇到旧显示器离线，保留该 UUID 的设置，按已确认的当前拓扑决定显示位置。 |
| 窗口管理 | 保留应用排除项、新窗和溢出策略、已保存的双窗比例及互换偏好。 | 新代际管理状态为关闭，旧 PID、窗口号、票据和窗口排除身份均不用于接管。仍在管理、待停止、全屏挂起、阻塞原因或未完成 journal 时先在来源版本处理。 |

已验证的文件夹外部访问、Chrome 权限及草稿绑定需要新版本自己的授权。升级程序不会打开 Chrome、申请麦克风、操作系统窗口或调用上传适配器。导入检查使用普通文件和合成 SQLite 资料，本轮没有访问个人资料。[导入后的资产限制](../../Sources/NearpaneTray/ProductDraftBinding.swift) · [领域回归](../../scripts/test-profile-domains.py)

## 事务与回退

1. 预览要求来源版本已退出，取得既有 Voice、Riftlet 及存在的 WorkRect 写锁。只读复制来源树并比对指纹。预览 token 绑定来源路径与目录身份、完整内容摘要、选择范围和当前代际索引。
2. 用户确认后，Host 停止模块并等待领域和窗口助手排空，再移交整容器的独占租约。助手持锁重新验证来源、当前代际和 token，创建 `transactions/<UUID>/source-backup` 和 `previous-backup`。备份覆盖相对路径、空目录和普通文件的数据字节，包括已存在的 SQLite 附属文件。ACL、扩展属性、时间戳和系统凭据不在这份指纹的覆盖范围内。
3. 在私有暂存区构造完整新代际，调用同包 Host 解码并规范化设置。核验目标库和媒体，再次核对来源和当前代际指纹。事务收据包含一次性事务身份、前后代际及备份和输出摘要。文件与目录同步后晋升代际目录，最后原子替换 `profile-index.json`。同一来源及范围已在当前活动代际导入时返回已有结果。
4. 启动时发现 `transaction.json` 则先取得独占锁恢复。索引仍指向原代际时，验证归属后丢弃未发布副本；索引已指向新代际时，验证代际、收据与备份后结束事务。若归属或指纹矛盾，保留现场并阻止开库。不能通过删除日志来“清除”恢复要求。
5. Settings 的“恢复上一份资料”从核验过的本版备份重建安全代际，保留当前资料以备反向恢复。它恢复文字、截图、设置和可安全恢复的状态，并按领域契约撤销过期的外部权限。需要回到旧 App 时，退出 P5.3 后直接打开原安装包；旧版继续使用自己的原目录。

更换后的资料在重新打开 Nearpane 时生效。副本为本机同一用户的私有文件，含真实历史时应按个人资料对待。备份、旧代际和构造过程中的临时副本会占用额外磁盘空间，当前没有自动清理历史的机制。Settings 只提供上次切换的回退入口。掉电、持久介质失效及两个不同设备之间的迁移均未现场验证。[事务实现](../../scripts/profile-migration.py) · [Host 停机与资料交接](../../Sources/NearpaneHost/NearpaneApp.swift) · [故障和回退验收](P5.3-UPGRADE-ROLLBACK-ACCEPTANCE.md)

后续 Alpha 可沿用 `com.holdsnow.nearpane.alpha`、既有容器和格式 1 的独占规则。只有通过当前资料标记、schema 与完整性判断的版本才能复用契约。未来若引入不兼容 schema，应另定义读写版本并在新代际转换，同时保留旧应用可打开的原代际或独立资料。采用 Developer ID 或公证时还需单独验证签名要求、TCC 和 Keychain 访问组的连续性。本轮只使用本地开发签名。
