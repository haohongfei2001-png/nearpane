# P4.2.2 Virtual 技术裁决及 Native 下一步

**Virtual 真实停放继续 BLOCKED；本机停止试验该机制。** 结果属于分支 C：普通 Dock 应用已经成立，但在不激活、只操作副屏的条件下，AppKit 自身没有完成合格的单窗最小化。实际观察还发现了同 App 兄弟窗的呈现变化。不能裁定外部 AX 不支持普通 Dock 应用，也不能推荐任何停放机制用于用户窗口。

| 路径 | 已证实 | 裁决 |
| --- | --- | --- |
| 屏外 frame | P4.2/P4.2.1 曾独立读回部分可见 | 本轮零写入，不继续尝试坐标 |
| AppKit 自身单窗最小化 | 真实 regular Dock App、原位稳定，两窗均可最小化；只向 W1 请求，W2 也改变呈现；两窗未读到 minimized=true | 正向基准失败；详见[原始数据摘要](P4.2.2-REGULAR-APP-PARKING.md) |
| 外部 AX | 本轮只读，两窗属性可写；该属性可写不等于能停放。上轮 accessory 应用曾返回 success 但未确认 | 当前 Dock 应用 AX 实验 NOT RUN，没有可报告的 setter 返回码 |
| 真实 Virtual 切换、恢复与两次强退 | 前置条件失败，未执行 | 没有真实成员切换、原位恢复、幂等零写入或保留用户意图的新实机收据。既有屏内位移强退收据不代替 Virtual |
| 替代机制 | 整个应用 Hide 无法隔离同 App 的 W1/W2；AppKit 自身排序不能用作第三方通用写接口 | 没有已验证的公开替代机制。生产 Virtual 仍不授予物理动作 |

不需要用户更改当前桌面，也不要求补做手动测试。只有将来具备**隔离的登录会话，允许普通测试应用成为前台，且能独立验证两扇普通窗正常并存和恢复**时，才有理由重新开启受控对照；本轮不再推进 Virtual 实机切换。焦点安全本次只覆盖被动启动、登记、AppKit 请求和否决，未覆盖未执行的反最小化和强退。

## P4.3：能继续的工作

新增[两次采样的来源检查](../../Sources/NearpaneCore/NativeOriginCheck.swift)，接到[专用夹具的只读准入记录](../window-lab/Sources/NearpaneFixtureWindows/ReadOnlyGate.swift)。它只回答“同一扇已登记测试窗是否两次见证了同一来源”，无写接口。要求同会话、build、双屏拓扑和 scope、递增 revision、互不重叠的新鲜采样、独立显示器 Spaces、单个已登记窗的唯一 membership、普通窗的 AX/CG 身份和 ownedWindow 锚点。不把读者进程局部的 AX 标记当成可跨进程持久身份。现有一次性 Reader 重新启动可能产生新标记；这种情况拒绝，不能退化为仅比较 PID/CG 编号。两次读取在夹具内的联接通过编译；本轮没有给它签发真实的正向来源证明。

本轮交付的 Release Reader 用**空窗口白名单**做了两次真实只读测量（同会话，revision 1、2）。结果均 fresh、26A428、separateSpaces=true，主屏 scope 3 条内部记录、副屏 1 条，窗口数 0，已见证用户空间行数 0，切换和激活能力均 false。没有读取私人窗口清单或像素。原始文件 `build/verification/p422/gate-{1,2}.json`。此处的 3+1 不能作为四个用户桌面或目标 B 的依据。

下一步是先使隔离观察器能用同一仍存活的 AX 元素见证两个新鲜 revision，在指定会话、副屏分别冻结可验证的 A/B 及回到 A 的路径，并记录主屏不变条件。真实切换需要另行授权；创建、删除、跨空间移窗仍未开放。未取得回程和目标身份时不输入、不猜落点、不自动重试。
