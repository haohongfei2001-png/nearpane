# P4.2 Virtual 停放与强退恢复

**屏外停放 FAIL，首窗原位恢复 FAIL。屏外 Virtual A/B 切换及其 SIGKILL 恢复未执行。** 同一台 Mac 的另一次副屏内实验取得了独立的实机证据，证明一个新控制进程能在 AX 写入与确认日志之间发生强退后，将仍可访问的普通窗口恢复原位。

## 第一扇窗的真实失败

macOS 27.0（26A428），副屏位于主屏左侧，可见横向区间为 [−800, 0)。两扇新建夹具窗口都已经从平铺还原至原始 frame。监督器先登记 W1 的 PID/启动代际、CG 编号、AX 标记、副屏 UUID、逻辑工作区、frame 及恢复点，再批准一次沿副屏外侧的水平移动。

| 检查点 | W1 的真实数据 |
| --- | --- |
| 写前原位 | (−681, 1034, 240, 160)，AX 和 CG 一致 |
| 持久化的请求 | (−1042, 1034, 240, 160)，整个窗口预计位于两个显示器外侧 |
| AX 返回 | `AXUIElementSetAttributeValue` 返回 0，即 `success` |
| 最终读回 | AX 和 CG 均为 (−881, 1034, 240, 160)，CG 仍报告在屏，约 159 点宽留在副屏 |
| 恢复决定 | 实际位置既非原位、已确认位置，也非已登记的飞行中目标。新控制进程拒绝写入，保留 `recovering` 日志，W2 未被选作替代 |
| 清理 | 夹具正常退出。事后按原进程启动代际及该会话六个已登记 CG 编号复查，原进程已退出，残留窗口为零 |

该样本观察到了窗口边缘限位；仅凭一次回读无法区分 AppKit 与 WindowServer 的具体限位责任。会话 `device-se3vv30i` 保留原始 `journal.json`、`unconfirmed-readback.json`、写尝试和退出事件。整轮所有留存会话中，离开副屏边界的请求只有这一次。没有执行第二次停放、最小化替代、屏外强退或对另一个应用的操作。夹具关闭属于清理，原位恢复判定保留 FAIL。[恢复路径](../window-lab/Sources/NearpaneFrameController/FrameJournal.swift) · [实际写入](../window-lab/Sources/NearpaneFrameController/FixtureAdapter.swift)

## 经实机证明的崩溃边界

会话 `device-ew459kjc` 的普通窗位于副屏内部。签名夹具与监督器保持运行，只有负责这一笔写入的外部控制子进程收到 SIGKILL。

1. 控制器以排他锁占有日志。每次危险操作前写入事务、同一会话和窗口身份、原始几何、最后确认值及下一步目标，先同步文件，再原子替换并同步目录。
2. AX 将窗口从 (−681, 1034, 240, 160) 移到 (−667, 1043, 240, 160)。控制器在 AX/CG 回读成功、`confirmed` 尚为原位时留下见证。另一个独立进程再次观测到同一位置；竞争恢复者因现有锁被拒绝，外部写入为零。
3. 监督器向其持有的确切子进程发送 SIGKILL，并等待取得信号退出状态。新进程重新核验原夹具的运行代码、内核代际、登记版本、窗口标记及 AX/CG。一次 AX 写入后实际回到原 frame，CG 显示可访问。再次启动恢复时重新读回相同原位，写入次数为零。
4. 在独立负例中，试验注入授权丢失，真实 TCC 设置保持原值。恢复者在动窗口或修改恢复日志前拒绝。把早先的真实恢复记录回放到后来已调整的几何，也得到拒绝，新的窗口位置得以保留。同名窗重建、所有者退出并以新 PID/代际启动均未复用旧目标。

经合成后端证明的跨组切换、历史恢复及空源清理继续通过原有回归。此次设备 SIGKILL 证明的是副屏内真实第三方 AX 写入的进程崩溃恢复。断电耐久性、第三方管理器在 AX 最终检查与系统调用之间竞争、完全屏外窗口的可访问性仍未验证。[原 Virtual 回归](../../Tests/NearpaneCoreTests/VirtualRecoveryTests.swift) · [设备监督与进程等待](../../scripts/acceptance/verify-window-management.py)

## 停止条件与下一步

本机这个屏外坐标策略仍阻塞 Virtual 真接管。下一次停放前，需要审查能证明实际落点归属并安全撤销的策略，或验证具备可恢复性且不会影响另一块显示器的隔离环境。后续先验证第一扇窗的完整停放和恢复，再验证两个逻辑组和屏外强退。在此之前，生产 Host 的 Virtual 写入能力保持关闭。

`device-93pthhkh` 在补测首次登记几何与当前观测的绑定后，通过了零写入拒绝和单窗原位恢复。随后焦点守卫触发，当前会话在第二个强退场景前终止。其旧版证据记录 `keyOrMain=true`、激活通知数 0，无法区分前台应用变化、应用当前激活值或某个自有窗口的 key/main 状态。夹具退出后按旧代际再查，剩余测试窗口为零。交付源码将这些信号分别记录；该诊断变更仅经编译和离线检查。本轮可见测试到此结束。
