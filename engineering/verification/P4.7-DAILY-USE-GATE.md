# P4.7 个人日常窗口管理准入

**普通日常应用：不开放自动管理。** TextEdit 实机时段暂缓；Calculator 和 Preview 未授权。没有普通应用的 AX 写入、焦点或恢复收据。可以保留个人 Alpha；主动启用管理的范围仍仅为随包登记的副屏兼容应用。系统弹窗、菜单、权限对话框、模态窗口、未知代际、最小尺寸不明及其他未登记窗口均不在范围。Native Space 切换、跨 Space 移窗和 Virtual 停放继续关闭。

## 实际修复与恢复语义

| 缺陷及复现 | 改动 | 本轮验证 |
| --- | --- | --- |
| 两次去抖快照均观察到代际 1，基线管理服务在交给控制器时却选择了新代际 2 | [管理服务](../../scripts/window-management.py)在发票据前重读并核对整个已批准快照；成员、布局或编辑状态发生变化就重新等待稳定 | 用基线服务与合成快照复现；修复后新代际不生成票据、零控制器调用 |
| 明确退出时恢复失败，基线服务重启后回到 active 且未阻塞 | 在做恢复前将停止意图持久化；未完成的停止操作在重启时阻止自动管理，保留「重新核对并恢复」。重试退出恢复成功后进入暂停，需显式继续 | 临时资料目录中的失败、重开、拒绝自动接管和显式重试均通过。未对普通应用发送 SIGKILL |
| 仅凭当前 frame 等于日志中的位置，无法区分用户是否曾拖动后移回 | [兼容窗口所属应用](../../engineering/window-lab/Sources/NearpaneFixtureWindows/main.swift)记录每窗手动编辑代际；[动作票据](../../engineering/window-lab/Sources/NearpaneFrameController/FixtureAdapter.swift)与[恢复日志](../../engineering/window-lab/Sources/NearpaneFrameController/FrameJournal.swift)比对代际、精确身份和实际几何 | 同一几何但编辑代际变化或缺失时拒绝，匹配才允许恢复；保留未决记录。仅覆盖能提供这些事件的兼容应用 |

原始[基线复现](../../build/verification/p47/before.log)、[管理服务回归](../../scripts/test-window-management.py)、[恢复策略回归](../../engineering/window-lab/Tests/FramePolicyTests/FramePolicyTests.swift)。同一资料目录的写者租约和遇到冲突即停止的回归保留；不能由此声称与任意第三方窗口管理器存在系统级互斥。

隐藏面板保留管理；暂停保留当前布局并停止新自动写入。「停止并恢复」完成后撤销管理。正常退出恢复临时布局，保留已保存的布局意图；未完成的明确退出与意外终止按不同路径处理。意外终止依赖持久窗口动作日志，身份或用户编辑证据不符的记录不能重放。对仍存活的随包应用，实际 SIGKILL、AX/CG 回读和恢复证据来自 [P4.6 原生验收](P4.6-NATIVE-ACCEPTANCE.md)，不是 P4.7 对普通应用的实测。
