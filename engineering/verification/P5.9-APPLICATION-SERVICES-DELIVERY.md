## 产品入口和数据

「设置 → 应用」提供 Nearpane 反馈与更新。菜单栏另有检查更新入口，后台发现新版本时显示圆点及版本提示，点击后才打开更新界面。侧栏沿用已有结构。

反馈使用 Nearpane 独立草稿、回执、稳定资料目录及 Keychain namespace。发送前展示完整预览，用户确认才入队，编辑后旧预览失效。同一私有反馈仓库通过 `product=Nearpane` 和模块字段区分产品，原服务的 Issue 标题前缀仍为 Riftlet。现有接收器严格使用 schema 1，本轮保留其正式协议，未修改远端服务。截图、录音、资料正文和日志不自动进入反馈。真实反馈创建和删除未在本轮执行。[反馈范围与接口](P5.9-FEEDBACK-INTEGRATION.md)

本轮发现并修复反馈退出竞态。退出在第一次等待前冻结编辑，等待已接纳保存后刷盘，再停止引擎并等待在途回执。写入失败保留错误及重试退出入口。系统版本变化时递增未发送草稿的修订，保留用户原文。Host 在反馈准许退出后才停止其余领域，重复退出使用同一个排空任务。

## 应用内更新的实际准入

复用 Riftlet 使用的 Sparkle 2.10.1，独立锁定 Nearpane 通道。自动检查默认关闭，用户可保存每日检查偏好，周期为 86400 秒。安装逐次确认，禁止自动下载与静默安装，关闭系统统计和更新说明脚本。包内包含完整框架、许可证和嵌套助手，运行不需要外部开发工具。

Nearpane 必须有独立 Ed25519 公钥、签名 appcast 和签名归档。更新清单签名失败不允许超时放行，归档解压前验签，版本与 build 均须递增。用户已经接受下载、安装或延后安装时，资料切换保持阻塞。资料切换开始后，新的更新检查拒绝进入。定时发现更新不取得前台焦点。[运行策略](../../Sources/NearpaneCore/ApplicationUpdatePolicy.swift) · [Host 接线](../../Sources/NearpaneHost/ApplicationUpdater.swift)

截至本次交付，Nearpane GitHub 没有正式 Release 和签名更新源，尚未配置独立公钥。当前包明确显示通道未就绪并关闭实际检查，保存的每日检查选择可供后续正式通道使用。没有执行真实在线下载、替换与重启，线上自动更新尚未开放。首个带公钥的签封版本及签名 feed 发布后，需要完成隔离资料的真实更新验收。[发布条件与流程](../../docs/APPLICATION-UPDATES.md)
