| separate Spaces | 完成 AppKit 初始化后的设备控制进程和隔离 Reader 均读到 `NSScreen.screensHaveSeparateSpaces == true`；只读的 `com.apple.spaces spans-displays` 为 0。早期未初始化完整的独立探针曾读到 false，历史 P1 也曾在 false 时取得 3+1。实际联动须靠获准切换来测量 |

| 来源 A | 在 `device-3omqyh5s` 中，受控的普通 W1 属于当前活动空间，完整位于副屏，未最小化、未全屏、未配置为驻留所有 Space。夹具在独立 Reader 返回前后都核对 W1。连续两个 revision 各有一个 corroborated 窗口、一个单值 membership 和一行当前副屏记录；两次的 scope、record 和窗口身份相同 |
| 目标 B | 本轮副屏范围没有第二个已见证用户可见目标。主屏的其他内部记录也没有资格充当副屏 B。A、B 测试标签只在具体登录会话和新鲜见证中有效 |
| 能力与权限 | 版本约束的 P1/P4.0 SkyLight getter 在独立进程读取。两次 Reader 快照的 `spaceSwitching` 与 `windowActivation` 均为 false。无麦克风、浏览器、录屏或新 TCC 授权要求 |

## 下一次设备授权与处置矩阵

| 步骤 | 最小条件、证据与停止边界 |
| --- | --- |
| 固定范围 | 指定测试设备或独立登录会话、唯一副屏、两个已存在的普通测试 Space、每个目标一扇新建标记窗口。重新记录两屏 UUID、原活动空间、原焦点令牌和原设置。B 的建立如涉及新增 Space，单独列入授权 |
| 动作路径 | 可评估 macOS 自带的左右切换或 Mission Control 中选中已确证的测试目标。方向输入依赖当前顺序、焦点和设置。用当前 A、可独立辨识的 B 及返回 A 的证据限定单次动作。读取到内部 ID 本身不授予按 ID 切换的能力 |
| A → B | 动作前冻结 OS build、登录会话、显示器布局、source/target、两个自有窗口代际和前台状态；保存 A 的回程证据。单次动作后读取活动 Space 通知、两屏 current、两个窗口的实际 membership/活动状态和焦点。过渡中等待稳定双采样 |
| B → A | 仅在 B 身份确定且返回路径仍然有效时执行一次返回。在同一登录会话重新核对 A、两个测试窗口的可访问性、主屏以及初始状态。焦点恢复只限另行授权的专用测试窗 |
| 失败和部分完成 | 动作后身份模糊、显示器/用户会话变化、主屏被带动、焦点进入用户程序、目标或退路消失时停止后续输入。以新读回确定实际落点，保留日志。若连当前状态都无法证明，不发送猜测性的反向快捷键 |
| 关闭的能力 | 创建、删除、跨 Space 移窗、修改 Mission Control 或快捷键均有各自授权与恢复门槛。A、B 尚不能同时证明或不能保护主屏时，转专用登录或设备。尚未获得公开、可据指定内部 ID 定向写入的生产实现证据 |

Apple 记录了桌面切换的用户操作与活动 Space 变化通知。通知可作为观察时间点，成功判定仍需同一目标的窗口和 membership 回读。[Apple 的多空间操作说明](https://support.apple.com/en-euro/guide/mac-help/mh14112/27/mac/27) · [活动空间变更通知](https://developer.apple.com/documentation/appkit/nsworkspace/activespacedidchangenotification) · [独立空间设置](https://developer.apple.com/documentation/appkit/nsscreen/screenshaveseparatespaces)
