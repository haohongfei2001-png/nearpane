## 焦点、重启与证据保管

- 静置、按钮、文字编辑、隐藏和恢复各有 start/end 检查点与独立结果。静置默认连续 60 分钟。按钮须出现实际按钮事件。只有显式点击原生编辑器后才允许编辑场景取得键盘焦点，并须观察到真实编辑事件。隐藏/恢复分别核对可见性变化和原前台进程。记录限于测试进程自身的鼠标事件及前台 PID。[原生探针](../../Sources/NearpaneHost/NativeAcceptance.swift) · [五种判定](../../scripts/acceptance/session_evidence.py)
- 启动器持有会话锁，通过操作系统 wait 取得实际 PID 的退出状态与时间。比较退出前、退出后、下一次启动前和打开后的资料摘要。包括 Voice 录音/修订与编辑草稿、实际媒体字节、资产顺序、未决操作、原始调用次数、START 与唯一输入记录。完整恢复正例要求有实际资料，初始收音暂停、托盘未连接、外部附加许可与目录收录关闭，并核对麦克风及语音权限读数。一个空库或仅有 drained/opened 不足以通过。合成测试确实等待两次无 GUI 子进程退出，覆盖原未决操作和恢复后授权/数据变化。
- Schema 2 会话在忽略目录记录成品 SHA-256、全包资源指纹、依赖锁、验收脚本版本、各可执行主体的标识、签名/CDHash、版本、运行事件、检查点、错误及最终判定。浏览器代码身份和内核进程身份仅在获准的 browser-before 建立。TCC 由 macOS 按实际责任主体判定，隔离资料目录不会产生独立的系统授权。测试运行的原文、录音、网页、图片及原始事件只留本机；语音检查点使用会话密钥生成文字摘要。仓库只跟踪工程与去内容化收据。

## 授权后的现场步骤

以下由执行代理完成。开启相应步骤前需取得单独授权。

1. 显示隔离 Nearpane、观察指定测试窗口，允许在面板内点击、输入合成文字、隐藏、恢复、正常退出与重启。代理执行五组 `focus-start/end --scene idle|button|edit|hide|restore`。若所选交互工具需要辅助功能权限，须指明实际工具和签名主体。静置期间须保持约定测试环境。
2. 仅允许隔离 Host 使用指定麦克风和本机已安装的语音资源处理短测试话语。若使用合成音源播放，也要明确获准。先回到待命，再执行 `speech-before`，让 `speech-during` 在后台等待原录音和识别尝试，待域内识别结束后执行 `speech-after`。另做一次明确的用户暂停。云端识别和付费服务不在范围内。
3. 允许 Host 在只含合成内容的指定窗口内截图，并允许本会话的 capture-panel 助手截取隔离侧栏的单个窗口。屏幕捕获分别按实际 Host、帮助程序及系统责任进程授权；若选择系统截图入口，还要明确允许启动系统截图选择器。目录监听需要另外列出获准目录。代理检验托盘入库、模块互不干扰及异常断开恢复。
4. 明确允许专用 Chrome 配置、单一已运行的目标进程、窗口/标签及确切已有测试会话。向该草稿写入唯一测试标记并上传已指定 UUID 与 SHA-256 的一张测试图片。先在 Host 完成显式附加授权，再让指定 Chrome 草稿处于前台。Host 和 observe-draft 助手分别需要向同一 Chrome 发 Apple Events 的权限。Chrome 的 JavaScript from Apple Events 设置如需更改，需事先单独授权。browser-before 仅在原编辑器上安装本会话的临时监听。绑定有效期为 15 分钟。授权阶段只点一次缩略图，之后只观察，持续保留未发送草稿。
5. 在工作稳定时运行 `before-exit`，由启动器等到实际退出，再启动同一成品与测试会话，等待新的 startup 检查点后才继续操作。执行 `report` 记录各项目状态。全程不执行 Spaces 切换、用户窗口搬移或生产资料库操作。

代理从 `scripts/native-acceptance.py` 调用上述动作，每次传递同一 `--session` 和 `--app`。browser-before 另需 `--url`、`--browser-pid`、`--browser-window`、`--browser-tab`、`--asset-id`、`--asset-sha256`。browser-after 复用 URL、PID 和会话文件里的固定目标。浏览器、设备和 macOS 对这套实际装配的行为仍待授权后取证。
