# P5.9 Nearpane 独立反馈入口

## 产品与来源

Nearpane 在设置的应用页提供反馈入口，使用自己的草稿、历史和每条反馈密钥。反馈存储位于稳定资料根的 `Feedback` 目录，独立于文字、截图、附件队列和资料代际。`KeychainFeedbackSecrets` 使用 Nearpane 专属 namespace `com.holdsnow.nearpane.alpha`，客户端没有 GitHub token。隔离验收使用停用网络的 transport 和内存密钥。

沿用 Riftlet 固定提交 `44f745a15ecb3682a9da0bda17f17a5d9fc1f07e` 的六个反馈库文件，复用原来的 SQLite 事务、重试、凭据、回执与删除策略。GitHub tree 的 blob 与公开归档内容分别核验，锁定的 Riftlet 文件数由 81 增为 87，tree SHA-256 为 `67ee240827accc16f956ecf8f3c8c035e34581a830840773a7758fb37463e2db`。含 Saytile 的全部固定文件数为 184。

共享接收器为 `https://riftlet-feedback-receiver.haohongfei2001.workers.dev/v1/feedback`，后端继续使用 `haohongfei2001-png/Riftlet-Feedback`。本轮只读 GitHub 元数据确认仓库仍为 private、启用 Issues、未归档。[实际元数据](../../build/verification/p59/feedback/repository-status.json)

接收器的严格 schema 1 当前没有独立 product 字段。Nearpane 在用户预览的正文首行固定 `product=Nearpane`，第二行固定所选 `component`，在共用私有仓库中可据此筛选。远端现有 Issue 标题仍采用 Riftlet 命名，标题与标签的服务端产品化需要后续接收器兼容更新。本轮没有改生产 Workers、D1、远端仓库配置或提交真实反馈。

## 用户操作与隐私

用户选择问题或建议、相关模块并填写文字。macOS 版本默认不附加。预览显示将发送的正文和 Nearpane 版本，确认发送后冻结原报告编号、内容及密钥。修改草稿使原预览失效。打开、编辑、预览和关闭反馈界面均不建立发送授权。

上游固定协议还包含随机反馈编号、类型和创建时间。Nearpane 不自动采集截图、录音、文字流、浏览器内容、文件路径、窗口身份或原始日志。用户可在自己的记录中查看已预览内容、刷新回执、取消未投递内容或申请删除。只有已取消或服务确认已删除的记录可从本机移除。

HTTP 未取得正确编号及 durable 回执时保留待处理状态。后台重试始终使用同一编号、内容和密钥。服务接收、进入私有中心和删除完成分别显示。远端副本删除可能需要维护者处理，界面不会将已申请删除显示成已删除。

退出先冻结交互，等待已接纳的草稿写入，再保存最终版本、停止新请求并等待原在途回执落库。草稿保存失败恢复编辑。停止后的 clean 标记写入失败保持反馈阻塞，用户可以再次退出重试。资料导入与回退不会复制该独立待投递记录，也不会复制 Keychain 密钥。
