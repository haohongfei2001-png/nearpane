# P4.2.1 单窗口停放裁决

**Virtual 真实接管 BLOCKED。** macOS 27.0（26A428），左侧 800 × 1280、旋转 90° 的副屏，主屏 1920 × 1080。基线为 `242e2907825b30247004d35f81d69b043b53d1f3`，开工时本地与 GitHub 同分支一致，工作区干净。

| 候选 | 现场结果 | 产品裁决 |
| --- | --- | --- |
| A 屏外 frame | 原试验中 AX setter 返回 0，AX/CG 同时读回部分可见位置，首窗恢复被拒绝。本轮复算坐标并调用未显示窗口的 AppKit 约束方法 | 这条横向停放路径不可用 |
| B AX 单窗口最小化 | 本轮独立控制器只向 W1 发出一次 AXMinimized=true。属性可写，返回 0，但自建窗口没有确认最小化，恢复者也未取得一致几何 | 当前夹具、Dock 与系统版本组合无法验收 |
| C 其他机制 | NSRunningApplication.hide 的对象是整个应用。自有 NSWindow 的 orderOut 需要目标应用协作。当前没有提供精确第三方单窗控制及独立恢复证据的第三条路径 | 不选择。未使用真实 Space 或私有写接口代替逻辑工作区 |

### A 的最窄可证原因

W1 原位 (−681, 1034, 240, 160)。屏幕外侧边界 −800，目标左边缘为 −800 − 240 − 2 = −1042。这里的 AXPosition 和 CG 边界都使用全局左上逻辑点；本次操作保持 y、宽、高。实际回读 x=−881，右边缘 −641，与副屏相交 159 点。P4.2 真实平铺及本轮副屏内回读也支持这个坐标系。[实际写入与轮询](../../engineering/window-lab/Sources/NearpaneFrameController/FixtureAdapter.swift) · [原停放失败收据](P4.2-VIRTUAL-CRASH-RECOVERY.md)

在同一拓扑将原提议转换为 AppKit 坐标，y=−114。窗口未显示，最小尺寸 144 × 96。调用 constrainFrameRect 时，普通标题窗对宽 240 和 320 的请求分别从 −1042、−1122 调整至 −681；无边框窗分别保留 −1042、−1122。两个宽度是纯函数输入。没有向系统发出第二个更远的 AX 请求。[可复核的夹具](../../scripts/acceptance/measure-appkit-constraint.swift) · [AppKit 窗口约束契约](https://developer.apple.com/documentation/appkit/nswindow/constrainframerect%28_%3Ato%3A%29)

该结果证明样式及目标显示器参与 AppKit 的约束计算，但 −681 与实际 −881 不同。现有数据只支持“写入获接纳，最终几何未到达”。旧轮询保留末次测量，未保存逐样本时间线；短暂停在目标后被异步覆盖、具体责任在应用还是 WindowServer、其他多屏排列、真实无边框窗外部写入行为仍未判定。

### B 的实机记录

两扇同进程的已登记普通 NSWindow，均为 240 × 160，CG 编号、AX 标记及 PID/启动代际各自绑定。两窗起初在屏、未最小化，AX 属性均可写。Dock 配置为左侧、自动隐藏、最小化到应用。控制器只读 Dock 的 AXList 边界 (−850, 59, 50, 1191)，位于副屏外侧，未读取 Dock 条目内容。

在同一排他 writer lease 下先持久化原状及下一步目标；W1 写入时刻为系统 uptime 1595522.352456，AX 返回 success。随后的 20 个目标应用样本中 W1/W2 的 isMiniaturized 始终为 false。W2 没有收到 setter。控制器在 1.8 秒内未取得 AX 已最小化且 CG 已不占用工作区的联合确认。恢复进程报 AX 与 CG 几何不一致，在写入前拒绝。末次持久化的夹具 frame 仍为原始值。失败轮询未留存每次 AX/CG 数值，不能定位是哪次系统更新造成差异，也不能证明兄弟窗在每个瞬间都没有变化。[独立读回及恢复](../window-lab/Sources/NearpaneFrameController/MinimizeStudy.swift) · [Apple 的窗口最小化状态](https://developer.apple.com/documentation/appkit/nswindow/isminiaturized)

首窗未能证明安全恢复，实验立即停止。夹具正常退出，按两枚 CG 编号检查原所有者残留为零。真实 A/B 切换、三个成员的隔离、不可最小化窗、停放及恢复确认前的两处强退、正常退出时保留显式布局，均未进行新机制的实机认证。不能把本结果外推到所有常规 Dock 应用。生产 Virtual provider 对物理动作返回 unavailable；交付控制器及监督器在新停放前使用同一能力报告。合成事务仍可独立验证，真实新机制未被接入生产事务。[能力报告](../../Sources/NearpaneCore/WorkspaceActions.swift) · [既有 Virtual 事务](../../Sources/NearpaneCore/VirtualWorkspaceExperiment.swift)

最低下一步是在专用登录环境中，用有常规 Dock 身份的独立应用记录第一窗 setter 后带时间的原始 AXMinimized、两份 frame、WindowServer 可见性和 Dock 状态，且在同一代际恢复原位。成功后才有依据扩大到多组与异常退出。当前版本保留只读、WorkRect 既有验证与显式拒绝。
