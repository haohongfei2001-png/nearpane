# P4.9｜在授权之前预览窗口管理范围

入口：在 Nearpane 的设置中打开「窗口管理 → 预览管理范围…」。选择一个应用，再按加入顺序选择具体窗口，点「核对所选窗口」。查看所选窗口现在的位置、预计布局、退出时能否恢复，以及限制原因。切换「驻留试算」「浮动试算」或双窗比例仅改变本页；要查看新结果须再次核对。预演没有授权按钮，也不会开启自动管理。

| 设置里的判定 | 含义 |
| --- | --- |
| 可以进入进一步授权 | 最近一次双采样中，每扇窗口的身份、编辑代际、几何、最小尺寸、排除规则、显示器及恢复条件均有依据。结果只在短时内有效，不是写入授权，也不是已经完成平铺。 |
| 当前条件不足 | 例如缺少读权限、跨采样存在变化、Stage Manager 下 AX/CG 呈现不一致、无独立的编辑或恢复见证。当下不会为此窗口签发动作票据。 |
| 明确不可管理 | 已排除、非普通窗口、明确不可调整，或预计槽位小于已知最小尺寸。 |
| 仅供布局试算 | 用户替换了实际 Docked/Floating 情景或比例；即使预演可排下，也不代表实际配置可管理。 |

**观察范围。** 打开预演后先列出本地进程的应用标签，选择应用后才列其窗口；选择具体窗口后才采集资格数据。展示的名称仅供用户辨认。进程按 PID/启动时间/Bundle ID 核对；可用时从 AX 对象读取窗口号，随后按指定号码和 owner PID 读取 CG 元数据。只读子进程单独校验 SHA-256，带请求 nonce 与超时，受限 getter 仅在核实过的系统构建使用。没有按标题、窗口排序、相似位置或最近窗口回退。没有读取文档正文、网页内容、图像或剪贴板。

**从身份到恢复。** AX 窗口和 CG 号码吻合仍不足够：两次采样须稳定，AX/CG frame 及可见性必须符合 P4.8 规则，窗口不能跨入未确认的显示器区域。真实最低尺寸未知不可用猜测值代替。普通应用没有随包夹具的窗口代际、编辑与恢复协议，可能提供一些当前数据，但没有执行器或授权延续；同名重建窗口不能接管。归档的窗口 179888（AX 562×422、CG 49×76）仍拒绝；未把微型矩形判成已证实的缩略图。

**布局。** 当前与替代方案复用 `DesktopWorkArea`、`ManagedWindowTiler` 及每屏实际配置。两窗可试算比例与槽位，第三窗用标准分区；保存的历史只有在成员、旧基线、编辑代际和日志得到确认后方可预测退出。预计值与当前值分列。八窗为分流阈值，不能创建真实 Space 时只试算现有区域的分割，并保留最小尺寸门槛。预演不保存临时比例，不改变持久预留宽度。

**设置、暂停与异常。** 启用、暂停、停止并恢复属于原有随包窗口管理服务，与预演隔离。隐藏侧栏及图标级收纳不撤销管理状态。暂停停止新布局写入；正常停止按真实窗口及用户意图恢复；异常由持久事务和原身份复核。P4.9 修复了一个实际缺口：原来部分拒绝原因只在管理进程内存中，进程替换后可能自动再试。现在先落盘拒绝原因，再撤销写入资格；未解决的旧会话不能在重新创建窗口时被悄悄退役。可以在设置里看到原因，明确重新核对或停止并恢复。旧日志不匹配窗口/编辑代际时不覆盖新的用户布局。
