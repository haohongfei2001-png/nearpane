# P4.8 台前调度兼容性与窗口管理安全收口

**裁决：同一窗口号不足以证明 CG 矩形可用于布局。** 本轮修复了动作票据可早于独立几何核验生成的缺口。在屏、身份、几何和授权都得到确认的兼容窗口，仍可进入原有 WorkRect 管理路径。TextEdit 和其他个人应用继续处于未开放状态。

分支 `implementation/host-foundation-20261109`，起始工作区干净。P4.7.3 基线为 `2fb07e00acaae84bebb555853cca77264a4a93c1`，P4.8 实现和测试提交为 `bf94290f2fc2fe79f4c9f36633078dc37342bd10`。

## 现场事实与归因边界

P4.7.2 的独立空白文档见证得到窗口号 **179888**。对同一 AX 对象和定向查询的 CG 记录，在约 325 ms 内三次得到相同读数。AX 为 **(−681, 64, 562, 422)**，CG 为 **(−64, 602, 49, 76)**，CG 记录属于同一 PID、普通层且在屏。两处直接读取逻辑点，宽、高分别缩为原值的约 8.7% 和 18.0%。这个差异不能由原点、旋转或单一比例换算解释。退出前的系统偏好记录显示台前调度开启。原始三次采样文件 SHA-256 为 `5595726f4d2e234264e98cd8432983322f52d8ed1f9e46a35d3e2ef77946e256`。[上轮诊断与原始读数](P4.7.3-AX-CG-IDENTITY-DIAGNOSIS.md)

Apple 记录了台前调度会将最近使用的应用排列在侧边。macOS 27 的另一份现场报告记录过捕获到侧边缩略呈现的情况。本机样本没有该表面的类型标记，也没有开关对照，因此 **CG 报告了异于 AX 普通窗口的屏上几何** 是最窄可证解释。工程判断只采用实际读数，不依据屏幕边缘、尺寸阈值或偏好开关猜测缩略图身份。[Apple macOS 27 使用手册](https://support.apple.com/en-ie/guide/mac-help/mchl534ba392/27/mac/27) · [macOS 27 独立现场报告](https://github.com/openai/codex/issues/38348)

本轮在 macOS 27.0（26A428）用最终 Release 观察器执行限定的空窗口清单读取。快照为 `fresh`，`stageManagerEnabled=true`，返回 0 个窗口、0 个 Space scope，实验 Spaces 读取关闭。本次系统取证只验证偏好采集与序列化。TextEdit 启动、真实 AX 写入、台前分组切换及台前调度开关操作均为零。[本机只读收据](../../build/verification/p48/empty-scope-reader.json)

## 资格与产品行为

| 观测结果 | 处理 |
| --- | --- |
| 台前调度开启、关闭或偏好未知，指定窗口稳定在屏，身份、AX、CG 和已登记的应用窗口 frame 完全相符 | 在既有签名、用户授权、副屏工作区和最小尺寸检查通过后，可生成动作票据 |
| 窗口号已知，AX 与 CG 有任一分量不同 | 可保留独立读数，不能颁发管理票据、写入或采用为恢复基线。身份匹配器的 2 点候选容差不适用于写入 |
| 公共观察器无法对应 AX，或缺少在屏证据 | 保留可核对的只读信息，不借同 PID 的另一个 AX 窗口补全证据。旧元数据缺失在屏字段亦按未知处理 |
| 两次呈现采样、窗口代际、登记 frame 或编辑记录变化，或采样过期 | 该次事务拒绝。设置中显示原因，管理循环停止周期重试。用户明确重新核对后须重新采样 |
| 已知最小尺寸大于呈现矩形，或目标超出已授权区域 | 拒绝该窗口，即使单次读数表面一致。没有按通用像素阈值排除所有小窗口 |
| 崩溃恢复同时涉及可核对与不可核对的窗口 | 只对通过新核验的成员生成恢复票据。身份、编辑代际和事务边界仍须匹配，其他成员继续待处理 |

**观察与设置。** 读取器在采样两端读取台前调度布尔偏好，并保留 CG 在屏证据。窗口的身份可信度和呈现状态独立保存。公共匹配器无法建立 AX 对应时保留“未确认”；已有独立读数时可以表明“两者不同”。不一致窗口仍可作为只读轮廓和遮挡物，不能成为可操作命中目标，也不会使同屏已确认的其他窗口失效。「设置 → 窗口规则」显示采样时的开关状态、未确认窗口数量或快照过渡状态。[观察器](../../Sources/NearpaneDesktopReader/Reader.swift) · [证据模型](../../Sources/NearpaneCore/DesktopReadEvidence.swift) · [呈现判定与目标解析](../../Sources/WindowGeometryCore/WindowIdentity.swift) · [只读预览](../../Sources/NearpaneCore/DesktopPreview.swift) · [设置](../../Sources/NearpaneUI/WorkspacePolicySettings.swift)

**动作票据签发、写入与恢复。** P4.7.2 的真实写入已被拒绝。此次确认的代码缺口在更早的位置：管理器此前可以仅凭应用上报的 frame 生成 `ticket.json`；公开观察侧也可能把在匹配容差内的差异当作可命中目标。现在管理器先提交只读请求。独立控制器按已登记身份做两次 AX/CG 采样，中间至少 80 ms。管理器核对会话、revision、成员、frame、编辑代际和 3 秒时限后才生成票据。只读请求不能调用 setter。实际写入及恢复继续核对当前身份和实际 frame，恢复时另外核对持久日志与用户编辑标记。呈现回执与 `layout.json`、`journal.json` 分开存储。[管理器 issue_ticket、apply、recover](../../scripts/window-management.py) · [双采样](../../engineering/window-lab/Sources/NearpaneFrameController/ProductManagement.swift) · [写入前核验](../../engineering/window-lab/Sources/NearpaneFrameController/FixtureAdapter.swift) · [恢复](../../engineering/window-lab/Sources/NearpaneFrameController/FrameJournal.swift)

## 实机验收边界

修复已通过归档样本及离线产品路径回归，本轮没有重新证明日常应用的实时平铺、焦点或恢复兼容性。普通个人应用自动接管继续关闭。

下一次若只验证呈现状态转换，最小条件是单独授权一个不干扰日常工作的图形时段、一个登记的合成窗口和可恢复的台前分组。在台前调度开启的情况下，对同一个窗口的普通呈现与侧边呈现做只读双采样，分别核对身份、AX/CG、在屏标记及动作票据是否签发。若还要判定系统开关对差异的因果作用，需要另行授权一次记录原值、切换、复测并恢复原值的对照。本轮未执行这些操作，也未扩大现有应用准入。
