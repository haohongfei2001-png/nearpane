# 5.22（90）分阶段验收

**窗口调度路线已更新。** 当前工程采用[StageGroup 裁决](../../native-spaces/ACCEPTANCE.md)。下文涉及原生桌面切换、跨 Space 迁窗与双模式的历史要求均为 ARCHIVED。

以[操作合同](../../native-spaces/ACCEPTANCE.md)、[冻结实施计划](../../research/NEARPANE-5.22-CODEX-IMPLEMENTATION-PLAN.md)和[版本矩阵](../../research/NEARPANE-5.22-COMPATIBILITY-MATRIX.md)为依据。操作必须从正式签名安装包的生产入口发起，夹具仅负责建立和清理隔离资料、读取真实系统结果。

| 判定 | 必须保留的证据 |
| --- | --- |
| PASS | 指定场景、安装包及 OS 符合条件，独立读回证明目标和受保护状态 |
| FAIL | 实际结果确定违反合同，例如落在错误空间 |
| UNKNOWN | 已可能投递但无法确认结果。停止后续手势，保存时间线和恢复结果 |
| BLOCKED | 前置条件未成立，写明现场缺项以及已投递数量 |
| NOT_RUN | 未执行并说明依赖或设备条件 |

P0 必须依次通过单次相邻往返、10 次交替及 50 次交替。固定显示器及当次目标身份，检查延迟回弹和其他显示器，统计实际持续时间。出现错误或未知即停，P0 通过前关闭依赖它的迁窗集成。P1 的普通窗口往返、兄弟窗保持、取消与归属验证单独记账。P2 的同应用选窗以真实输入落点为准。P3 的附件要在草稿中完成上传且发送次数为零。P4 翻译、面板、单词本重开及语音最终稿各自判定。P5 使用真实拓扑和预热性能样本。P6 核对每层签名、公证票据、干净安装、升级及回滚。任何受支持组合均需有相应平台实测。PR #15 在完整合同通过前保持草稿。

回滚基线为 5.22（90）已签名的 `365fdc4`，其 SHA-256、安装路径和配置收尾见[窗口验证记录](5.22-90-window-roster/RESULTS.md)。系统空间及真实窗口不得由测试移除或关闭，只有当前运行创建且可验证所有权的夹具可以回收。

## 正式安装版相邻普通桌面验收

在已安装签名候选的图形会话执行。编译夹具可在操作前完成。每次运行使用新的收据目录。

```sh
kit="$(scripts/acceptance/native-spaces/p0-build.sh)"
scripts/acceptance/native-spaces/run.sh p0-adjacent "$kit" build/verification/adjacent-run-01
```

为测量操作期间的呈现时序，可在第二条命令前设 `NP_P0_DYNAMIC_MARKER=1`。两扇夹具文档各自在同一色系内交替绘制，显示流仍须读到实际呈现的帧和正确的末端颜色。测试收据同时保留启用条件和屏幕实测结果。

`profile/profile-session.json` 记录实际运行的安装包、隔离目录和日常配置恢复。`actions/results.json` 给出往返、10 次、50 次的各自终态。每次按压均有正式 Host 意图及独立 WindowServer 时间线，10 次阶段单独校验物理显示结果。未达门槛即停。逐次操作结果和临时桌面回收记录可从 [5.22 实机收据](5.22-p0/RESULTS.md) 复核。
