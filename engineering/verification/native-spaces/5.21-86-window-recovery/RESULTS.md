# 5.21（86）逐窗清单、取图与选窗复测

## 修复起点

2026-11-19 在一块显示器、台前调度开启的 macOS 27.0（26A428）上，先向运行中的 build 85 请求带随机编号的授权读数。Host 的屏幕录制和辅助功能均返回 false。独立观察器证实本桌面有 4 扇普通窗口，安装版清单为 0 张。这次读取不请求权限，也不采集私人窗口标题或画面。

## 产品变更

- 读取器将角色查询的 0.8 秒总预算分给本桌面有候选窗口的各应用。已确认在其他桌面的窗口不占用详细角色查询；同应用有一个窗口拒绝提供编号时，其他精确匹配的普通窗口仍然可以入列。两个测试在旧调度逻辑下复现了后续所有者或窗口得不到查询机会的问题。重复编号、最小化和辅助窗口继续排除。
- 权限引导从系统设置返回或手动复查时直接读取当前 Host 的系统授权。后台权限查询与同时发生的点击共享一次助手读数，画面授权独立处理。真实授权发生变化后，用户无需反复打开引导来要求刷新。
- 快速重复点选时，每次新的输入使用独立选窗意图。连续选择 A、B、再选 A 时，旧 A 的延迟回执不能取代最后一次点击。备用路径若只能核实应用与唯一窗口已置前，会提示键盘焦点仍未确认。
- 台前调度把窗口压缩成小的系统呈现区域时，对已经取得的完整画面保留有限期的内存快照。侧栏必须核对同一进程代际、窗口、桌面、生命周期、共享许可与逻辑尺寸，且留有足够空间显示“上次画面”。从未取得完整画面的窗口继续显示轮廓。

## 同一窗口的原生画面复审

在合成普通应用中，独立对照了本次源码对应的真实 SwiftUI 卡片和 WindowServer 状态，同一扇 Board 文档保持 300 × 210 pt。台前调度将其系统呈现缩为 92 × 104 pt 时，卡片保持原比例的橙色画面，并显示“上次画面”。返回 300 × 210 pt 后，卡片显示新绘制的红色，旧标注消失。已逐张审阅三张图。两扇从未取得完整原图的 Notes 窗仍显示轮廓。原前台保持，合成窗口全部关闭。该次视图使用验收进程已有的独立权限。[三态数据与图片指纹](stage-history.json)

第一轮观察到历史画面，但未能验证窗口恢复；第二轮复现了动画中几何短暂不可核实导致旧帧过早清除。修复后，身份仍确切而逻辑尺寸短暂不可读时，允许内存保留至多 3 秒，绘制仍须通过完整核对。窗口代际或桌面变化会使旧图失效。有标记的历史帧自最初取图起最多显示 60 秒。完整三态的原始取证在本机 Git 忽略目录 `build/verification/current-desktop-nm1rurxi/`。
