# P5.0 截图附加到 ChatGPT 草稿

**普通 Alpha 已接通截图托盘的单次附件入口。真实 ChatGPT 服务验收仍为 BLOCKED。** 签名成品在副屏取得实际系统截图，同一张 PNG 在隔离 Chrome 的目标草稿收到一次，Riftlet 记录了上传开始。服务端上传、最终完成回执及已登录 Chrome 的系统自动化寻址均待现场验收。

## 用户入口与适用范围

打开 `~/Applications/Nearpane P5.0/Nearpane P5.0 Alpha.app`。首次在「设置 → Riftlet」选择「选择当前系统截图目录并收录…」，并按需启用「允许附加到当前浏览器草稿…」。此后保持希望使用的 Chrome 草稿在前台，点击已收录截图的缩略图一次。设置中可单独停止收录或关闭草稿附加。用户无需在编辑器输入测试标记。[设置入口](../../Sources/NearpaneUI/SettingsView.swift) · [截图目录授权](../../Sources/NearpaneTray/CaptureFolderConsent.swift)

按下缩略图时冻结签名 Chrome 的进程代际、窗口、活动标签、文档、编辑器、资产 UUID 与 SHA-256。在上传前重新核对选中目标，只有归属得到正向证明的文件输入能收到图片。程序仅接受 `https://chatgpt.com/` 和 `/c/…` 下符合守卫条件的草稿。提交前持久记录一次性操作身份。结果不明时，后续点击只核对原操作。[缩略图点击](../../Sources/NearpaneTray/TrayModule.swift) · [原生目标与一次性提交](../../Sources/NearpaneTray/ProductDraftBinding.swift) · [文件输入守卫](../../Resources/AcceptanceTargetGuard.js) · [回执状态提示](../../Sources/NearpaneTray/TrayAttachmentFeedback.swift)
