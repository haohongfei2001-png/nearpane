## 从已安装候选取得的现场结果

macOS 27.0（26A428），独立 800×1280 副屏。真实应用控件在不激活的副屏 Settings 中运行。仅使用本轮创建的签名兼容应用和空资料；没有枚举个人窗口来验证选择器。测试经现有的无网络执行入口运行，未申请新 TCC 权限。

| 场景 | 实际观察 |
| --- | --- |
| 单窗、双窗、三窗 | Settings 取得窗口号 182664, 182665, 182666，按加入顺序逐次核对。实测三个窗口均为 240×160 pt，最小 144×96；分别获得「可以进入进一步授权」。驻留预留 120 pt，WorkRect 680×1280。单窗预计占满，两窗 340/340；三窗中旧两窗在右侧各 340×640，新窗在左侧 340×1280。这些是**预计**位置；原窗口没有移动。 |
| 浮动、自定义与恢复 | 浮动试算恢复 800×1280 的整块可用区域。双窗 60/40 试算将第一窗宽度从 340 变为 408 pt；如果用户明确保存该比例，退出时第一窗在完整区域预计宽 480 pt。普通未自定义时显示原 frame。试算没有写入全局设置或执行恢复。 |
| 排除、重建 | 按确切窗口排除，三窗组即显示「明确不可管理」；撤销排除并再次核对才得到新的预演。关闭末窗，创建同一应用的新窗后，旧选择显示「当前条件不足」，未自动换目标。 |
| 持久恢复门槛 | 在全新、管理关闭的会话临时注入本轮专用的 `prepared` 日志样本；真实 Settings 因恢复记录拒绝，未产生授权或恢复回写。核对输入文件哈希后清理。不是实机崩溃实验。 |
| 最小尺寸冲突 | 独立新会话把驻留预留设为 760 pt，剩余 40 pt 小于选定窗口的实测最小宽度 144 pt；真实 Settings 显示「明确不可管理」。同一扇窗口改用浮动试算可排下，实际 frame 不变。 |
| 图标、退出与焦点 | 真实侧栏 20×20 pt；展开、收起、再次核对所选窗口后，仍为未启用管理，结果保持一致。Host/夹具未成为前台工作应用，比较首尾前台 PID 相同；未采集其他窗口内容。两次试验均 waitpid 退出 0、fixture 原 PID 已终止、领域数据前后摘要相同。已启用管理时的图标收起行为继承 [P4.8.1 实机收据](P4.8.1-RESPONSIVE-ALPHA.md)，本轮不为验证预演而重新开启写入。 |

**零写入证据。** [现场驱动](../../scripts/acceptance/verify-window-admission.py) 仅对本包已核对且位于副屏的控件执行 AXPress，不设置任何窗口属性；管理服务始终 off。每个检查点独立核对 fixture 的进程、成员代际与原 frame，主管理器未发放写入 grant、ticket 或 setter 前持久 attempt。测试注入日志与真实 writer 日志分开核对。打包检查还验证读取器 Mach-O 不导入 AX setter、AX action 或 CG 事件投递入口。这里的「零」指 **Nearpane 对测试窗口的 AX 管理写入**，并非声称监控整个系统。

## 失败与证据边界

初次专用设置入口依赖旧桌面夹具标志，未创建 Settings，已改为单独校验副屏会话标记。随后 macOS 排序后将 690 pt 测试面板移到 x=−681，右缘超过副屏 9 pt；边界守卫及时终止，key/main 均为 false，未创建测试窗口、未截图。最终验收面板在两边留出安全边距并持续核对，不能把先前失败算入 PASS。实际截图还揭示「管理窗口」勾选文案易被理解为已接管，已改成「允许纳入管理范围」。

无权限、过期、编辑代际/身份丢失、写者竞争、归档的 Stage Manager 微型 CG 矩形、已保存布局与恢复日志不一致均在隔离数据回归中拒绝。未撤销实际权限，未变更台前调度以制造反例；未证明 TextEdit 或任意普通应用可管理，未尝试真实 Native Spaces、Virtual 停放、语音或附件上传。随包兼容应用仍保留既有的独立授权与写入流程。
