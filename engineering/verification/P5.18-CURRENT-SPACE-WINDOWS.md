# 当前桌面逐窗预览 · Nearpane 5.18（70）

产品源码为 `7decdcac2108351c147b9629826e0ee44601e3bb`。本机为 arm64、macOS 27.0（26A428），一块显示器，台前调度开启。

## 用户现场与修复

5.17 在全量系统清单里只读取在屏窗口，又用 AppKit 当前可见窗口过滤了一次。切换前台应用会清空桌面快照。第一次取图还有固定等待，某些后台窗口即使在同一桌面也没有自己的卡。现场一次只读采样中当前桌面有四条窗口记录，只有两条进入 AppKit 可见清单。复核只保存统计量。

5.18 单独读取逐窗清单。读取器核对进程启动时间、窗口号、显示器以及相邻两次系统读回的当前普通桌面与逐窗归属。当前台应用改变时，它重新取样并保留同桌面的其他窗口。系统支持范围外沿用公开可见窗口证据。清单独立于 AX 平铺和真实 Space 动作。侧栏每扇窗口占一张卡，能区分同应用兄弟窗，随数量和宽度排成一或两列，可滚动。[读取器](../../Sources/NearpaneDesktopReader/CurrentSpaceWindows.swift) · [事件与更新](../../Sources/NearpaneUI/CurrentDesktopWindows.swift) · [侧栏](../../Sources/NearpaneUI/DesktopSurface.swift)

冷启动后台窗暴露了第二处缺陷。原来的相对窗口查询没有返回该窗的几何和共享属性，尽管单窗共享源与当前桌面归属都存在。改为对明确的窗口号使用公开的 Core Graphics 描述接口，核对 PID、layer、共享属性、frame，再读 ScreenCaptureKit 的单窗画面。捕获前后核对身份。系统禁录或缺少可核实的共享源时保留窗口卡。画面只驻留内存，未采集声音。[单窗记录](../../Sources/NearpaneCore/WindowSurfaceRecord.swift) · [画面与缓存](../../Sources/NearpaneUI/DesktopWindowGallery.swift)
