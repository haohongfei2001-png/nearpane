# P5.4 普通 macOS 窗口逐窗管理

基线为 P5.3 的 `cc36d147904fde58373fbb868d270502c69af31e`。P5.4 在「设置 → 窗口管理 → 预览管理范围…」接入普通窗口的逐窗授权、平铺与有条件恢复。可写范围限于副屏、同一显示器上的明确选择。本报告说明产品如何决定是否写入。实际发生过的 AX 操作、成功或拒绝的场景、独立读回、成品指纹及交付提交见[原生验收收据](P5.4-REAL-AX-ACCEPTANCE.md)。

## 用户操作

1. 选择正在运行的普通应用，再勾选窗口。选择「此屏设置」并预演后，可以查看本轮涉及的全部窗口号和预计位置。已有授权成员也在此次布局中列出。改变选择、关闭预演或改变相关设置会撤销旧预演。选择「驻留试算」或「浮动试算」只比较布局。
2. 满足条件时出现「授权所列窗口并应用布局」。确认有效期为 45 秒，确认时重读窗体并核对显示器和实际工作区域。其他兄弟窗口以及随后新建的窗口均需单独选择。权限、身份、呈现几何或尺寸不足时显示拒绝原因。
3. 双窗布局可调整左侧比例，范围为 20% 至 80%。加入第三窗时新窗占左半，原两窗在右半上下分布。移除第三窗后，原两窗仍是同一组时可恢复本次会话保存的比例和槽位。布局复用现有 `ManagedWindowTiler`。Docked 和 Floating 按既有显示器角色及已提交设置计算 WorkRect。管理器比较提交后的实际工作区，面板临时显隐、收起和展开本身不会触发布局写入。[Settings 入口](../../Sources/NearpaneUI/WindowAdmissionSettings.swift) · [管理状态和按钮](../../Sources/NearpaneUI/OrdinaryManagementStatus.swift) · [工作区域](../../Sources/NearpaneCore/DesktopWorkArea.swift) · [平铺算法](../../Sources/NearpaneCore/ManagedWindowTiler.swift)

| 入口 | 对已授权窗口的含义 |
|---|---|
| 暂停／继续 | 暂停保留当前位置、身份观察及恢复记录。继续时重新核验每扇窗与最新工作区。 |
| 排除并停止管理 | 立即释放这扇窗的授权，保留其当前位置，活动会话重排其余成员。会话内按进程代际和窗口号拦截重新纳入。已有应用和窗口排除规则在每次操作前另外核对。待解决的故障必须通过恢复入口处理。 |
| 停止并尝试恢复原位置 | 对仍有连续证据的原窗口逐一恢复接管前的 frame。一扇窗失去证据时保留其记录，其他仍可验证的窗口可独立恢复。正常退出也会等待在途工作并尝试此流程。 |
| 保留当前位置并结束本次恢复 | 需要明确确认。只归档未完成记录，释放授权，几何写入数为零。之后重新管理需重新选择。 |

后台轮询正在读取窗口时，Settings 可接纳一次明确点击，等本次读取结束再核对条件。重复点击、期间失效的意图和关停时的动作均被拒绝。已经开始的布局写入需要先完成才能接受新的操作。[点击与轮询交错回归](../../build/verification/p54/manager-explicit-intent.log)

## 身份、系统事件与回执

普通应用不需要提供专用令牌、编辑代际或插件。Host 核验包内控制助手的 SHA-256，通过匿名管道启动它。助手只绑定一个应用进程，按同用户 UID、PID、启动时间、Bundle ID 和普通应用身份核对归属。从初选起保留 AX 对象，操作前重新枚举，以唯一窗口号、同一 AX 对象和 CG owner PID 再次核对。窗口标题和文档正文不参与身份判断。读取窗口号优先使用系统暴露的属性；已有只读回退仅允许 arm64 系统 build `26A428`。无法取得可靠编号时拒绝写入。[助手通道](../../Sources/NearpaneUI/OrdinaryWindowAX.swift) · [系统证据](../../Sources/NearpaneOrdinaryWindowController/SystemEvidence.swift) · [窗口号只读回退](../../Sources/CReadOnlySpaces/ReadOnlySpaces.c)

两次间隔采样必须确认 AX 与 CG frame 相同、窗口完整位于可用区域、在屏、layer 0、普通非模态且可移动缩放。同时检查全屏、最小化、附属对话框、显示器 UUID 和镜像状态。台前调度开启时，几何一致的窗口仍可受检；出现缩略形态或过渡导致几何分歧即拒绝。若系统不给出可靠 `AXMinSize`，只允许两个维度均不小于初选时已实际达到的尺寸。该尺寸是本次管理的保守下限，应用真正的最小尺寸可能更小。[系统取样](../../Sources/NearpaneOrdinaryWindowController/SystemEvidence.swift) · [预演规则](../../Sources/NearpaneCore/WindowAdmissionPreview.swift)

助手监听此 AX 对象的移动、缩放、销毁事件。写入前后分别核对前台 PID 与 AX focused window。每个位置或尺寸操作须收到预期事件，并从 AX、CG 读回期望 frame；额外事件、窗口重建、超时、父进程消失或几何不符都使该观察失效。监听标识属于 Nearpane 本次观察会话。**macOS 的 AX 通知没有提供实际操作者身份**。本轮能关联 Nearpane 发出的操作、预期事件和几何读回，遇到其他变化时不能可靠区分用户手动调整、应用自行重排和其他管理器。完全同时且表现相同的外部动作也不能单凭通知归因。管理器遇到可观察的冲突会暂停并保留记录。[AX 事件与逐步写入](../../Sources/NearpaneOrdinaryWindowController/WindowMonitor.swift)

## 竞争、中断与资料延续

同一用户的 Nearpane 实例按 PID、启动代际和窗口号竞争系统文件锁；当前资料还持有一把会话锁。它们约束遵循这套锁协议的 Nearpane 实例。其他厂商的管理器不会自动遵守，实际几何和事件仍需核对。Host 同时要求原兼容窗口管理服务已报就绪、处于关闭状态且没有恢复阻塞，并检查锁屏、全屏及显示暂停条件。切换状态导致在途操作失去范围时，Host 会撤销控制助手。[Host 范围判定](../../Sources/NearpaneUI/CandidateWorkRect.swift) · [管理会话](../../Sources/NearpaneUI/OrdinaryWindowManager.swift)

在活动资料代际的 `WorkRect/ordinary/journal.json` 中，先写操作 UUID、会话、精确窗口身份、原 frame、最后确认的位置及本次目标，文件同步、改名并同步目录后才写 AX。确认后的 `action-<UUID>.json` 保存前后两次 AX/CG 取样，以及本次各个 AX 动作的时间、通知和实际读回。成功恢复、排除或明确保留现状时归档记录；归档失败仍会阻止后续管理。异常重启丢失 AX 观察连续性，即使窗口号和 frame 与日志相符，也保留阻塞，等待用户核对、明确保留当前位置。磁盘里的 PID 和窗口号不能重建写权限。[日志和范围锁](../../Sources/NearpaneUI/OrdinaryWindowManagerJournal.swift) · [服务级回归](../../Tests/NearpaneUITests/OrdinaryWindowManagerTests.swift)

P5.4 沿用 P5.3 的 `com.holdsnow.nearpane.alpha`、资料格式 1、活动代际和容器写锁。新增的是当前代际内的窗口日志，SQLite schema 没有变更。P5.3 已会检查 `WorkRect/*/journal.json`，遇到未完成记录会阻止导入或迁移。切回 P5.3 前，可先在 P5.4 停止并恢复，或手动确认保留现状。P5.3 安装包保留，两个版本按容器写锁互斥。工程验收使用隔离资料。该候选没有为普通应用建立整 App 的自动管理白名单；主屏、Native Space 操作和 Virtual 停放继续保持原边界。[资料契约](P5.3-PROFILE-MIGRATION.md) · [迁移检查回归](../../scripts/test-profile-domains.py) · [候选打包](../../scripts/build-candidate.sh)
