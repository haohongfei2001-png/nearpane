# 单屏普通窗口管理实机记录

macOS 27.0（26A428），一块 1470 × 956 pt 显示器，可用区为 `(0,33,1470,923)`。隔离资料在左侧持久预留 160 pt。目标为从 LaunchServices 后台启动的独立、已登记的 regular App，系统提供标准的 NSWindow 与 AX 窗口。测试 App 的读回和外部布局刺激只用于验收，Nearpane 的窗口控制器依靠系统接口独立工作。

| 操作 | 实际结果 |
| --- | --- |
| 选择一扇，授权同一进程接下来的新窗 | 原窗占满 WorkRect，新窗创建后自动加入，宽度各 655 pt。已有未选兄弟始终原位。暂停期间新打开的窗在恢复后也保持未授权。停管归还两扇窗口，合计 5 笔经 AX/CG 确认的事务。[新窗与恢复](../../build/verification/p54/ordinary/0ea34e49-9951-44e7-ab50-069753b911db/new-window-scope.json) |
| 双窗自选 60/40 比例、交换槽位、正常退出 | 管理期间宽度为 786/524 pt。退出后同一组窗口映射到整个可用区，宽度为 882/588 pt，注销了恢复事务，合计 8 笔。[正常退出](../../build/verification/p54/ordinary/7b263dcd-bfe4-435b-b921-f6eacc65a251/pair-quit.json) |
| 三窗加入、关闭和重建 | 第三窗占左半，原双窗在右半分得 462 和 461 pt 高。关闭第三窗后原组回到 60/40。重建的同名窗口在 Settings 仍未选中，操作数为零。11 笔确认，停管后两个原窗归位。[几何与事务](../../build/verification/p54/ordinary/4abe07be-896a-4fc7-b3f8-41fdc1e40f90/manager.json) · [关闭见证](../../build/verification/p54/ordinary/4abe07be-896a-4fc7-b3f8-41fdc1e40f90/membership.json) |

以上五组均由窗口所有者、系统 AX 与 CG 核对。已确认操作的请求及逐步读回误差均为 0 pt。每组的 cleanup.json 记录原前台 PID 和 AX focused window 未变、测试窗口残留为零、Host 正常退出。没有接管个人窗口或改变系统桌面。窗口越界纠正发生在外部几何稳定后；本记录未验证拖动过程中的逐帧阻挡或任意第三方应用。

## 成品与复现

签封试验候选两次迭代。前两项 Host SHA-256 为 `4e469cb7afc8195543dc3299f9b32d0a99ba121d20c36718b3dfe06d551c721f`，后三项为 `a66f84f3e3576e79183b07cbaecec7ec2dbd3a7cd70145f01b3c5df54bc32d30`。开发中保留了新版修复前的[真实 Settings 拒绝记录](../../build/verification/p54/ordinary/e8ae5067-8ab7-4d2e-9bde-e9f9db9bba00/unavailable-control.json)。临时包路径规范化后，正式助手能在同一机器识别测试窗。

在已有 AX 权限、仅一块显示器且无其他 Host 使用中的条件下，先执行 `scripts/acceptance/ordinary-windows/build.sh`。运行 `python3 scripts/acceptance/ordinary-windows/run.py --single-display --mode new-window-scope --candidate "/path/to/Nearpane.app"`。其他独立场景使用 `pair-quit`、`membership`、`boundary`、`physical-boundary`。脚本核验签名、可执行文件、测试资料、进程启动代际、窗口编号和原焦点，使用新建的一次性测试窗。原始记录位于 Git 忽略目录。

## 最终安装包复核

最终 Host SHA-256 为 `a9b7645b36cf0a84080042d2fd377af9a8320343b01ef2604311f80a8a0127a9`。两次通过的试验包和最终包均逐文件核对了同一窗口控制器（SHA-256 `dce659a84cbaee96a632f4e38e8476a46c49bc69b35fdd7d778a16cba9213711`）和桌面读取助手（`94ca62bbc80d99bdbdccdaf63cf56b0fc638b53465fc97d936755fa2a00a8822`）。

最终包复测先因另一个隔离 Host 正执行资料回退检查而让出。随后一次安静期采样通过，实际启动测试窗前无法复核焦点。最后一次在独立观察器读取前台窗口时收到 `AX -25211`，尚未创建目标窗口或启动窗口管理。该现象表明当时的前台焦点读取未获可用结果，不能仅据此推断系统 TCC 设置发生改变。最终包本次的窗口自动管理现场判定为 **未执行**，上表五个场景的实机判定对应各自签封的候选。没有修改系统权限或操作个人应用。
