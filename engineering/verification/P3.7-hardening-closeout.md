## 数据与权限边界

临时会话目录和捕获目录均实测为 0700。进程复用固定的锁文件，专属锁的释放以新持有者实际取得锁证明。系统截图的私有原图和已导入媒体归隔离库所有，均位于 Git 忽略路径内。单个原图与原始导入行可按各自的 SHA-256 复核。

Host 的结构化诊断只导出时间、预定义事件码及内建模块 ID。六个隔离会话分别产生 260、840、146、29、4714、23 条验收事件，合计 6012 条、12 次启动。逐行检查均通过 19 个状态字段的白名单、类型与标识校验。观测使用可见性、焦点、PID、权限枚举、计数和指纹。语音资料快照对文本使用会话密钥 HMAC，媒体、正文和浏览器页面均保留在本机。数据见 `event-data-audit.json`。

六个会话的 12 次原生 Host 均由各自的监护器 wait 到退出码 0，退出前均记录 drained，退出后各隔离资料库均能重新取得独占锁。最终成品另做两次定点挑战。五图会话让真实系统截图子进程保持运行到 Host 退出，内核退出通知早于 drained；历史故障会话通过原 QueueStore 生成 UNKNOWN、FAILED，原生重启前后逐项一致，新增输入意图和 START 为 0。对应原始证据为 `verified-process-exits.json`、`gallery-live-child-2.json` 和 `recovery-phases.json`。

隔离库只隔离内容，TCC 的授权仍取决于进程签名和系统责任链。本机已读到的麦克风状态为 authorized，语音识别为 notDetermined。真实撤销已授予的权限涉及当前责任主体，未改动其系统授权。现场缺少无声虚拟输入及预先指定的登录草稿，相应权限和真实设备结果见 P3.6 现场收据。

## 分发前检查清单

本轮原始编译器签名可通过单个 Mach-O 的 `codesign --verify --strict`。对当前开发 `.app` 的严格验证实际返回 1，原因是尚无完整的包资源签名。原始结果在 `bundle-signing-preflight.json`。开发可执行文件签名和包内资源校验分别记录。

- 在干净的发布暂存目录生成包，确认架构、最低系统版本、bundle ID、版本号，以及包内所有固定资源的指纹和许可证。检查成品的最终权限说明和受保护能力。
- 取得正式发布授权后，使用同一团队的 Developer ID Application、受控时间戳和 Hardened Runtime，由内向外签署实际包含的可执行组件和整个包。仅配置确实需要的 entitlement，在最终产物上执行 `codesign --verify --deep --strict --verbose=2`。[Apple 公证要求](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)
- 用发布身份处理最终分发容器，按选定容器类型提交 `notarytool`。取得 Accepted 后在适合的包或镜像上装订并验证票据，通过 Gatekeeper 和干净设备的隔离下载启动测试。将签署、公证记录和最终 SHA-256 关联。[Apple 分发打包](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution)

本机可用 `notarytool 1.1.3 (42)`、`stapler` 和 `spctl`。本轮使用开发成品，发布凭据和 Apple 公证提交均未使用。
