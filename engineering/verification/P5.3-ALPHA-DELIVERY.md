# P5.3 个人 Alpha 安装与资料延续

在 Finder 双击 [Nearpane P5.3 Alpha.app](</Users/hhf/Applications/Nearpane P5.3/Nearpane P5.3 Alpha.app>)。首次普通启动会在 `~/Library/Application Support/Nearpane Alpha Profiles` 建立空白资料，包括语音文字库、截图托盘和默认设置。这一步只访问新版本自己的资料根。此版本可留空使用，导入入口位于 Nearpane 菜单的「设置… → 模块」。

## 从旧版继续使用

1. 正常退出要用作来源的 Nearpane。展开「从此前 Nearpane 版本导入」，选择 P4.8、P4.8.1、P4.9、P5.0、P5.1 或 P5.2，再勾选「文字与修订」「截图与历史」「设置」中需要的项目。选择器使用已知版本列表。按下「预览导入」才读取所选资料。
2. 预览显示对应的记录、修订、草稿、截图、附件操作和显示器设置数量，并说明哪些内容需要留在原版。确认前可以改选类别并重新预览。导入按类别整体替换，未勾选的资料沿用当前代际。文字导入保留用户选定的修订和编辑草稿，原始录音留在来源。历史附件保留 UNKNOWN / FAILED；旧操作不会被安排再次上传。
3. 按「确认导入所选资料」。Nearpane 结束当前模块工作并释放写锁，通过校验后才切换到新资料。读完结果后按「退出 Nearpane」，再从 Finder 打开 P5.3。来源仍在运行、预览后来源改变、空间不足、数据库格式未知或存在未解决事务等情况会显示拒绝原因。遇到中断时，下一次启动会检查事务结果；无法验证的现场会保留。处理原版本的挂起操作后可以重新预览。[事务规则](P5.3-PROFILE-MIGRATION.md)

截图收录目录需由用户在 P5.3 的 Riftlet 设置重新选择。辅助功能、麦克风、语音识别、屏幕捕获、控制浏览器等依赖 macOS 实际授予相应主体的权限。窗口管理和外部附件写入都需按各自流程重新授权。旧书签、旧草稿绑定、旧窗口的 PID/CGWindowID 以及钥匙串访问权均不能充当新授权。没有为交付验收读取个人资料、调用钥匙串或申请新的系统权限。[升级与回退验收](P5.3-UPGRADE-ROLLBACK-ACCEPTANCE.md)

## 回退

| 需要恢复的对象 | 操作 |
|---|---|
| 上次切换前的整份资料 | 在 P5.3「设置 → 模块 → 从此前 Nearpane 版本导入」中选择「恢复上一份资料…」，核对后按「确认回退并停止模块」。退出并重新打开 P5.3。切换前刚使用的那份资料也保留备份。 |
| P5.2 应用及它自己的原资料 | 退出 P5.3，然后双击 [Nearpane P5.2 Alpha.app](</Users/hhf/Applications/Nearpane P5.2/Nearpane P5.2 Alpha.app>)。P5.2 继续读取 `Nearpane Alpha P5.2`。之后在 P5.3 增加的资料留在 P5.3。旧程序不会打开新格式的唯一副本。 |

## 成品与后续升级

安装包使用稳定的 Bundle ID `com.holdsnow.nearpane.alpha`。资料格式 1 通过活动代际标识选择数据库，每个版本在打开资料前必须核对格式和写锁。后续兼容版本可以沿用此身份与目录，保留用户资料。改变数据库格式的版本需先在独立代际完成校验，并为旧版保留可读副本。P5.3 为本机 arm64 开发签名包，实读为 `Signature=adhoc`，无 Team ID。保持 Bundle ID 有助于版本延续，不能单独保证后续签名获得原 TCC 授权或钥匙串访问。Developer ID 和公证仍待单独发行流程。[打包入口](../../scripts/build-candidate.sh) · [资料契约](../../Sources/NearpaneCore/ProfileGeneration.swift)
