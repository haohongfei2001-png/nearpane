## 一次环境交接

请设备所有者一次性提供**以专用标准账户独立登录、能让 Codex 从该账户执行、含两个独立测试显示器及指定普通测试 Space A/B 的无人使用桌面**。窗口登记、快捷键校准、三轮验收和收尾由工程端执行。现场需要设置账户密码或进行客户端认证时，由所有者直接在系统界面输入。

1. 本机未发现可复用的专用本地账户。如果选择此路线，在“系统设置 → 用户与群组”创建标准账户，例如 `nearpane-test`。在“通用 → 共享 → 屏幕共享”中仅允许该账户。优先用系统自带 Screen Sharing；无需购买 ARD、设通用 VNC 密码或同时开启远程管理。若已有受管理的 ARD 环境，可沿用其单账户虚拟显示连接。[Apple 屏幕共享设置](https://support.apple.com/guide/mac-help/mh11848/mac) · [Apple Remote Desktop 选择其他用户的虚拟桌面](https://support.apple.com/guide/remote-desktop/apd4f46319e/mac)
2. 从可用的 Mac 客户端，以测试账户凭据选择独立登录或独立虚拟显示。若界面只提供共享当前桌面，就结束连接。Apple 的高性能模式可选择一或两块虚拟显示器；用物理控制台的同一账户登录可能使硬件屏幕变黑。仅考虑测试账户、双虚拟显示且能保留原控制台工作的方式。单机同账户回连、SSH、后台 launchd 和另开浏览器 profile 均没有本机验收证据。[Apple 连接说明](https://support.apple.com/guide/mac-help/share-the-screen-of-another-mac-mh14066/mac) · [显示类型与物理屏幕影响](https://support.apple.com/guide/mac-help/mchl1883115d/mac)
3. 在独立桌面内启动 Codex 执行端，并将该测试桌面交接给工程端，指明供测试的 A/B。保留日常账户登录。工程端从新会话运行下述检查并在自建窗口上验证实际控制能力。目标用户的“隐私与安全性 → 辅助功能”仅按系统实际识别的责任主体授权：见证 App 读取 AX、发送正常快捷键，Reader 读取测试窗 AX；如系统将权限归于启动它们的桌面宿主，则核对该目标账户内的宿主身份。探针无需授权以执行会话比较。新签名不能从旧控制器的结果推断权限，也无需向新账户开放原仓库或完整磁盘访问。

若只能获得共享日常桌面的连接，**备用方案待新的明确授权**：一次指定机器完全无人使用的起止时段、允许联动的两块显示器和专用 A/B，并允许在该时段从当前图形会话进行三轮往返、恢复和清理。现有冻结包会拒绝物理会话。备用执行需为该授权建立单独的现场绑定，不能修改受保护基线文件来放行。两种交接方式本轮均没有执行系统切换。

## 工程端入口、证据与停止条件

当前机器的冻结目录为 `/Users/Shared/Nearpane-P431.EQsCKfWq`。包含一个无可见界面的会话探针、一份本次引导的受保护基线和一个带只读 Reader 的签名测试 App。重新引导后，工程端在原日常控制台重新冻结。开发者从唯一 checkout 运行 [freeze-isolated-gui-kit.sh](../../scripts/acceptance/freeze-isolated-gui-kit.sh) 即可生成新目录。

在目标登录的执行端，从冻结目录依次运行：

```sh
shasum -a 256 -c SHA256SUMS
codesign --verify --deep --strict NearpaneSpaceWitness.app
./SessionProbe check protected.json
./NearpaneSpaceWitness.app/Contents/MacOS/NearpaneSpaceWitness --check
```

探针核对本次系统启动、物理控制台仍由原账户占用、调用者自己的 GUI 登录与图形访问、不同 UID 和 Security Session、两块活动非镜像显示器且与受保护显示器 UUID 集合完全分离。只读通过仅给出 `ISOLATED_GUI_CANDIDATE`。远程标志、同一服务器 PID 或屏幕共享已开启都不足以判定可控制。[探针源码](../window-lab/isolated-gui/SessionProbe.swift)

**三轮入口**为 `./NearpaneSpaceWitness.app/Contents/MacOS/NearpaneSpaceWitness --three-rounds`。只在已交接的合成桌面中调用。P4.3 原本提供的是只读来源检查与现场矩阵。本轮复用 Reader 和窗口身份，增加会话校验、驻留的 AX 元素、实际 GUI 点击见证和至多六次输入的实验入口。独立编译的 Reader 只接受非控制台用户自己的登录、父进程一个标记窗口或空白名单；正式 Reader 沿用原控制台准入。[验收入口](../window-lab/Sources/NearpaneSpaceWitness/main.swift) · [Reader 边界](../../Sources/NearpaneDesktopReader/Reader.swift)

下列是隔离会话**工程控制端**的协议，不是交给用户执行的手动测试：

- 程序输出 `RUN <私有目录>` 和 `WAIT <检查点>`。工程端先通过独立 GUI 核对预先指定的相邻 A/B、原位和回程，确认两屏均只属于测试会话。控制端在 A 上实际点击已标记的 A 窗口，再创建 `enroll-A.ready`。B 窗口登记后同样点击并交付 `observe-B.ready`。窗口进程处理实际鼠标按下事件，单独写文件不能替代这项验证。
- 对 `enroll-B` 与 `return-A` 两个请求，仅在独立 GUI 中用已确认目标和正常系统 Control+方向键完成该方向的校准后，原子写入相应的 `.ready` JSON。字段为 `run`（当前 UUID）、`checkpoint`（准确请求名）、`demonstratedControlArrow`（现场实际使用的 `left` 或 `right`）。两次校准均须有目标窗口和两屏读回；不能凭内部记录顺序填写方向。只支持经校准的相邻桌面，其他布局停在准入。校准不计入三轮。[Apple 的 Spaces 切换操作](https://support.apple.com/guide/mac-help/work-in-multiple-spaces-mh14112/mac)
- 回到已证实的 A 后，程序自动运行三次 A → B → A。每程在新鲜双采样后写入操作 UUID 与目标，再检查会话、指针、键盘修饰键、系统输入权限及精确到自建 key window 的 AX 焦点。每程只向当前登录会话发送一次已校准的系统快捷键。双读回核对窗口代际、owner/AX/CG、唯一 membership、scope/current、另一窗口已离开活动空间和整个显示拓扑。两次校准和每程的待转、已发送及确认文件保存在该次运行目录。
- 拒绝、目标歧义或超时会结束后续输入，关闭仅由该进程创建的窗口。正常完成必须在 A 核对两屏 current、确认两枚 CG 编号无该所有者残留，并读回初始焦点，才写入 `completed.json`。若中途停止在 B，按最后一次意图和新读回重新辨识实际落点；只有仍然证实在 B、隔离有效且原返回路径成立时，隔离会话的工程端才能受控返回 A。无法证明时保留现场，禁止猜测反向键或重放未确认输入。关闭夹具不构成已返回 A 的回执。
